# 任务门禁验收标准（Gates）

> 本文档是 Pir 开发计划 v0.1 所有任务共用的门禁验收文档。
> 每个任务完成后，必须按本文档逐条验收并填写验收记录，方可标记为 `已完成`。
> 任务特有验收标准在各任务文件的「门禁验收」一节，与本文档叠加生效。

---

## 1. 验收流程

```
实现完成 → 自测清单全过（任务文件 §自测） → 逐条核对本门禁 →
填写验收记录（任务文件 §验收记录） → 状态置为「已完成」
```

- 门禁任一条不通过：状态保持 `待验收` 或退回 `进行中`，记录未过项原因。
- 验收人：由非实现者复核为佳；单人开发时按清单逐项自证，命令输出粘贴进验收记录。

## 2. 通用门禁（G1–G7）

### G1 构建与静态检查

```bash
cargo build --workspace
cargo clippy --workspace --all-targets -- -D warnings
cargo fmt --all -- --check
```

全部通过，无警告（含测试目标）。

### G2 测试

```bash
cargo test --workspace
```

- 全部通过；live 测试在未设 `PIR_LIVE_TEST=1` 时默认跳过且不得失败。
- 任务新增的行为逻辑有对应测试；移植上游的测试意图用例命名与上游对应（编码规范 §12.2）。
- 非 live 测试不得访问真实网络（faux provider）。

### G3 对拍门禁（行为类任务强制）

- 涉及行为契约的任务（事件序、线格式、session JSONL、compaction、RPC、TUI 渲染）必须跑归一化 diff 对拍：
  - fixtures 与归一化脚本来自 `pir-test-support` / `fixtures/`（T02 交付物）；
  - 对拍结果（命令 + 输出摘要）附在任务验收记录中。
- 纯基建 / 内部重构类任务若不触碰行为契约，需在验收记录中说明「G3 不适用」的理由。

### G4 红线检查

逐条确认（编码规范 §1.3）：

- [ ] `external/pi/` 无任何改动（`cd external/pi && git status --porcelain` 为空，且 HEAD 仍为 `2efa728d2ee90ef597626e96b1e28ef2b279f07c`）
- [ ] 未引入 JS/TS 执行能力（无 Deno/Node/QuickJS/sidecar）
- [ ] 未读写 `~/.pi` / `.pi`
- [ ] Session 存储仅 JSONL，未引入 SQLite 等其他后端
- [ ] token 估算算法与常量未偏离钉死版 Pi
- [ ] 非测试代码无 `unwrap()` / `expect()`（有不变式注释的除外）
- [ ] 日志 / 错误消息中无 API key、token 等凭据

### G5 线格式与序列化

- [ ] 新增/变更的线格式类型（JSONL、RPC、settings、models.json、manifest）字段为 camelCase，serde 形状与上游逐个核对
- [ ] 对应 fixtures 对拍通过（与 G3 合并执行）

### G6 文档同步

- [ ] 移植代码有溯源注释（上游文件路径 + 版本，编码规范 §14.3）
- [ ] 实现偏离已**回写**到原始文档（`01-requirements.md` / `02-design.md` / ADR / `coding-standards.md`）
- [ ] 若任务交付物改变了既有文档中的描述（目录结构、模块划分、命令、配置项），对应文档已更新

### G7 偏离闭环

- [ ] 本任务关联的所有偏离均已登记到 `deviations/`（一事一记，登记表已更新）
- [ ] 每条偏离状态为 `已回写` 或 `已关闭`；行为级偏离有对应 ADR 编号
- [ ] 任务文件「偏离记录」一节已列出关联偏离 ID

## 3. 验收记录（任务文件中填写，模板）

```markdown
## 验收记录

- 验收日期：YYYY-MM-DD
- 验收人：
- G1 构建/静态检查：通过（命令输出摘要 / CI 链接）
- G2 测试：通过（N passed, 0 failed; live skipped）
- G3 对拍：通过（场景清单 + diff 结果）/ 不适用（理由）
- G4 红线：通过
- G5 线格式：通过 / 不适用（理由）
- G6 文档同步：通过（回写位置列表）
- G7 偏离闭环：通过（D-xxx 清单）/ 无偏离
- 结论：通过 / 不通过（未过项 + 原因）
```

## 4. 进度标识维护

- 验收通过后：任务文件状态置 `已完成`，同步更新 [`index.md`](./index.md) §3 索引表的状态与验收日期。
- 索引表是进度的唯一入口，评审时以索引表为准。
