# v0.1.4-rc.6 (2026-09-11)

**Pre-release (pre-release channel)**: round six of the `0.1.4` stable candidates. This round = **the v0.1.4 additive lines entering the RC channel in full for the first time** (M6: the plugin-rebase atomic pin switch + the interactive custom-UI ABI + the new plugin rpiv-ask-user-question + `ctx.sessionEntries`) + the M7 closeout items (five independent tracking items around tests/harness hardening). The baseline content matches `changes/v0.1.4.md`; at stable-release time each rc file's entries fold into `v0.1.4.md`. Install/upgrade: existing rpi users run `rpi update --rc` (or `rpi update --all --rc` to sync extensions to `0.1.4-rc.6`); force-install via the official script with `RPI_GITHUB_API_URL=https://api.github.com/repos/revpidev/rpi/releases/tags/v0.1.4-rc.6`.

## Increments relative to rc.5 (all from the M6 additive lines + M7 closeout)

### Plugin rebases (atomic pin switch, ADR-0025)

- **Dual-plugin baseline upgrade**: `pi-subagents` v0.48.0 (`56f97234`) → **v0.66.0** (`0fc0eebb`, 568 commits), `pi-mcp-adapter` v2.24.0 (`3d953f90`) → **v2.32.1** (`10a45367`, 90 commits); `smart-fetch`/`pi` untouched. subagents: event streams with fallback/replay guards, discovery robustness (diagnostic exits/pruning/symlinks), worktree integrity and terminal classification, write-failure retries and notification v2, launch contracts and tool-surface intersection gates, model fallback, steer gates and stable Fleet ordering, new settings keys (`subagents.maxThinking`/`defaultProvider`/`agentScanDirs`, …). mcp: command wiring (`/mcp`, `/mcp-auth`), approval scoping and persistence, backoff visibility, ttlMs caching, OAuth 401 re-registration, lifecycle/diagnostics/rendering, performance hardening.
- **BREAKING: mcp direct tool naming** (R7.2.4): server-level prefix resolution with cross-server collision suppression, include/exclude sharing one source with approvals; users with configured direct tools should review their `mcp.json` (guide: `toolPrefix:"none"`); detailed entries in the plugin-rebase section of `changes/v0.1.4.md`.
- **Semantic change: subagent context** (ADR-0026): `defaultContext: fork` **degrades to fresh + a warning** when unavailable (no more fail-fast); subagents **do not inherit global context by default** (host-side `RPI_NO_GLOBAL_CONTEXT` switch); migration guidance in `changes/v0.1.4.md`.

### Interactive custom-UI ABI (ADR-0024/0027, native + wasm dual carriers)

- Seven additive `ui.*` host-calls for extension-mounted interactive components (mount/poll/render/hide/wake/dispose/external editor), capability `ui`, no `rpiAbi` bump; overlay mounting, line-frame composition with cursors, `tick`/`wake`, hidden state, the cleanup matrix (tool abort/session close/reload/extension unload/lifetime caps/guest trap), wasm fuel budgets and fail-visible limits; the `ui.editExternal` external-editor chain (reusing the `Ctrl+G` flow).
- **`ctx.sessionEntries` additive host-call** (ADR-0027): read-only view of active-branch custom entries; the mcp approval restore already migrated to consume it (ABI-first + JSONL fallback for old hosts).

### New plugin: rpiv-ask-user-question (TE28–TE32)

- When requirements are unclear the model issues a 1–4 question questionnaire (2–4 options/multi-select/markdown previews/notes); interactive terminals render a bottom tabbed overlay via the UI ABI (keybindings/envelope byte-compared with upstream; visuals are rpi's own design, TE-D40); RPC/ACP hosts degrade to the host-native select/input walker; non-interactive runs remove the tool automatically. Config at `~/.config/rpiv-ask-user-question/config.json` (inherited from upstream, TE-D39), all 9 locales. **Ships lockstep with the host as `.rpix`** (version = host version).

### M7 closeout items (tests/harness)

- **Windows build fix**: `model_exclusions.rs`'s auth-store mtime read switched to the cross-platform `modified().duration_since(UNIX_EPOCH)` (it previously used `std::os::unix::fs::MetadataExt::mtime` unconditionally, exposed when the baseline branch first passed Windows CI; only second-granularity values participate in the auth-store-changed comparison, semantics unchanged).
- smart-fetch parity replay temp-directory hygiene (fixing tests leaking files into the default temp dir, accumulating until the gate went red); conformance evidence-chain normalization with stable sorting (eliminating re-run churn); model_runtime login determinism (root-curing an occasional load-dependent failure); a shared lock for offline-environment test races (13 sensitive tests pinned, three review rounds closed the loop to zero open items); fanout install-config errors surface **before** consuming the spawn budget (no longer masking the root cause as budget exhaustion).
