# v0.1.9-rc.2 (2026-11-27)

**Pre-release (pre-release channel)**: the second candidate for the `0.1.9` stable release, carrying the fix found on the first runs of `0.1.9-rc.1`. The rc.1 feature set (upstream parity to Pi v1.5.2, the streaming-performance and Linux-memory main line, the statusline `estimate` calculation mode, the provider/MCP/coding-agent increments and the `rpi-subagents` / `rpi-smart-fetch` rebase) is unchanged — see `changes/v0.1.9-rc.1.md` and `changes/v0.1.9.md`; at stable-release time this file's entries fold into `changes/v0.1.9.md`. Install: existing rpi users run `rpi update --rc` (or `rpi update --all --rc` to also move the seven lockstep extensions to `0.1.9-rc.2`); install.sh does not serve RCs (`releases/latest` stays stable at `0.1.8`). This RC does not change any registry, schema, model-catalog or version endpoint beyond the RC endpoint and the profile index of this RC (ADR-0042: assets before endpoints).

## Fixed in this RC

- **The fullscreen transcript driver no longer panics when the session thread restructures the chat between a frame's measurement and a row read** (`rpi-tui`): the V19-06 height index lives in the `Container` behind the `Arc<Mutex<..>>` that the interactive mode shares with the `rpi-tui-driver` thread, and the row readers resolved a row to a direct child through the slot vector of the last `sync` before indexing `children`. A `/clear`, a theme rebuild (`rebuildChatFromMessages` — on startup the auto-theme resolution runs on the session task right after the driver thread starts), a tree navigation or a completed compaction could land between the driver's `sync` and its `rows` (the layout's viewport window, the residual image crop) or between frames (selection copy, prompt jump), so the reader indexed the new — possibly empty — `children` with a stale position and the driver thread died with `index out of bounds: the len is 0 but the index is N`, leaving the TUI without renders; the first start after upgrading to rc.1 was the reported trigger. The row readers (`rows`, `line`, `render_range`, `materialize`) now re-measure a restructured document first — the next frame's `sync` moved ahead of the read, so trusted blocks keep their heights through the identity carry-over and only changed blocks render — and the index readers (`revision_at`, `height_at`, `visible_range`, `prompt_rows`, `block_row`) answer "unmeasured" until the next sync instead of reporting a displaced block. Regressions: `document_readers_follow_a_restructure_between_sync_and_read` and `scroll_content_reads_follow_a_restructure_between_frames` (both panic at the reported site with the fix reverted).

## Verification requests (the point of this RC)

- Fullscreen mode (alt-screen) over a restored session: start rpi with a session that has several messages, switch themes from `/theme` (and once with the auto theme setting), run `/clear`, navigate with `/tree` and let an auto-compaction finish while frames render — the TUI must keep rendering (no `rpi-tui-driver` panic `index out of bounds`) and the first frames after a rebuild must show the new content, not a blank or stale transcript. Regular mode is unaffected by the change and only needs a smoke start.
- The rc.1 verification requests remain open: the Windows settings/auth/keybindings lock fix on a real Windows machine (startup without the `Invalid settings file … another process has locked a portion of the file` failure, `rpi config set`, `rpi install` / `rpi remove`, a `/statusline` save, `rpi auth login` and a restart after the self-update), the BREAKING surfaces on real providers, the performance main line on real hardware and the plugin line.

Known boundary: the RC endpoint (`https://revpi.dev/api/latest-rc-version.json`) and the `0.1.9-rc.2` profile index go live only after the Release assets are in place; the stable endpoint (`latest-version`), the schema/model-catalog files and the extension registry entries for stable stay at their current values. The rc.2 source (the fix plus the version bump) passed the local gates before tagging — `cargo fmt --check`, `cargo clippy --workspace --all-targets -- -D warnings`, `cargo check --workspace --all-targets --locked` on Rust 1.95.0, `cargo test --workspace` run twice (9412 passed, 0 failed, 8 ignored each run), the profile-packaging tests and the `install.sh` suite (275 checks); the PowerShell installer suites run in the Release workflow's installer job — but neither this fix nor the rc.1 post-review commits it builds on has had a fresh-context independent review; whether to add one before the stable fold remains open.
