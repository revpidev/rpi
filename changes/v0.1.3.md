# v0.1.3 (2026-09-03)

Main line of this release: **performance and concurrency governance** — seven audit-driven tasks (V13-01…07) plus two lead-in PR closings (`fix/stream-idle-timeout-write-perf` / `feat/statusline-live-token-count`). Guiding principles: ported regressions realign with upstream shapes; port-introduced concurrency defects pay down the Rust concurrency debt; homegrown throttling layers are added only at FFI-boundary cost points with terminal-state/last-frame semantics unchanged. Zero new ABI (the only host dependency, `ctx.sessionFile`, had already landed with ADR-0022); zero new ADRs.

## First-party plugins (new / enhanced)

- **statusline live token counting** (V13-10, lead-in PR): the `statusLine.liveTokens` key enables ~1Hz script re-runs during streaming; stdin gains a pure-measurement `rpi.live_output` block (character accumulation/increment window/elapsed/exact output tokens), leaving conversion to user scripts. Two host-side riders: eight-event payload forwarding parity completed, and the `ctx.sessionFile` additive host-call (ADR-0022) — fixing dual-instance same-cwd data mix-ups at the root.
- **rpi-ext-subagents authoritative parent-session location** (V13-02): `parent_session` prefers the authoritative `ctx.sessionFile` (the authoritative value is always the new session), with the directory heuristic demoted to a hardened fallback (mtime floor + `<ISO ts>_<uuidv7>` stem-shape filtering, excluding `fork*` self-pollution); four consumers switched to the authoritative session id (closing TE-D16).

## Fixes

- **statusline / smart-fetch same family: events dead or host channel dangling after `/resume`** (v0.1.3 follow-up, same root cause): the audit found two more OnceLock-style plugins breaking on the second host reload — statusline's install early-returned `{"ok": true}`: on the new host there were **zero event subscriptions** (the early return precedes `on` registration) → all statusline events stopped triggering refresh after /resume, the footer froze, and the refresh_loop's poll timer burned the old cookie every tick on a dangling channel (UAF after the old host dropped it), with the old loop already exited by session_shutdown and nothing restarting it; smart-fetch re-registered its tools (before the gate) but `STATE.host` froze forever on host 1 — every web_fetch's `ctx.cwd`/settings resolution and streaming toolUpdate pushes went through the old cookie (dangling or stale, cwd falling back to the process directory). Fixed with the same discipline as mcp-adapter: statusline event subscriptions became unconditional (registered on first install + rebind) + `CHANNEL: OnceLock<Arc<RwLock<AsyncHostCalls>>>` rebindable + refresh_loop restarted on rebind (TRIGGERS wrapped in a Mutex swapped along with it, engine state shared, session_start on the new session resets); smart-fetch's `host` became `RwLock<Option<HostChannel>>` with a rebind to the new channel when `STATE.set` fails, and the three consumers (resolve_runtime/two UpdateSinks) read the current channel at call time. Regression tests: `rpi-ext-statusline/tests/rebind_second_host.rs` (host B gets the full subscription back, event-driven footer recovers on B, zero pushes to A) and `rpi-ext-smart-fetch/tests/rebind_second_host.rs` (B re-registers both tools, toolExecute's ctx.cwd goes through B, zero host calls to A); both verified to turn red with the fix reverted.
- **The "🔌 MCP" status line vanishing after `/resume` (and the MCP extension going missing entirely)** (v0.1.3 follow-up): session replacement (`/resume`/`/new`/`/fork`/`/clone`/`/import`) rebuilds the `NativeExtensionHost` and reloads the cdylib via the same path — dlopen memoizes per path, the plugin's process-wide `STATE: OnceLock` survives across hosts, and the second `install` hit `STATE.set` returning `init: plugin already initialized`, so the extension failed to load on the new host: the old host's session_shutdown had already cleared the "mcp" status line with nothing left to re-push it (the user-visible symptom), and mcp proxy/direct tools, the `mcp-config` flag, and event handlers silently went missing in the new session. Fix: `PluginState`'s host channel (trampoline fn pointer + cookie) became a rebindable `RwLock<HostChannel>` — the rebind keeps the process-wide tokio runtime + dispatcher, re-registers flags/events on the new host, resets the direct-tool surface (a fresh host's registry is empty; the old "already registered" marker would suppress re-registration), rediscovers config from the new session cwd, re-pushes the tool surface and status line, and re-arms the bridge-retry loop (the new host's UI bridge attaches only after `switch_session` returns; direct pushes land on a null bridge and get dropped); all host call sites read the current channel at call time, and the old host receives zero pushes after the rebind. Regression tests at both ends: `rpi-ext-mcp-adapter/tests/rebind_second_host.rs` (the full /resume lifecycle: status line cleared → second-host install succeeds → re-registration → session_start re-initialization → status line pushed back after the UI attaches, zero pushes to the old host) and `rpi-ext-host/tests/native_same_path_reload.rs` (same-path second-host reload must succeed and re-register flags/events/tools on the new host).
- **edit tool falsely reporting `Could not find edits[N]` while the edit actually succeeded** (V13-11, v0.1.3 follow-up, rpi#18): a preview race (when the UI drains slower than the agent writes, the preview must fail to find `oldText` in the already-edited file) stacked with a port regression — upstream's `renderResult` backfills `details.diff` and rebuilds the call component in place (edit.ts:416-424), while rpi's `update_display` built the call component before the result backfill, too late within the same frame with no rebuild after, so the red error froze onto the scrollback permanently. Fix: `ToolExecutionComponent::update_display`'s two shell paths now build the result component first (backfilled state lands) and the call component second (reads the backfilled preview), `add_child` order unchanged; the race damage drops to upstream's "flash and gone" (the race itself is inherent upstream and stays).
- **`rpi update --extensions` upgrading only one plugin** (untracked-install discovery, v0.1.3 follow-up): update/list only iterated the settings `packages` entries, while the extension loader loads **every** manifest directory under the extensions install roots — untracked installs from early versions or manual copies were silently skipped, which in multi-plugin setups surfaced as "only one gets upgraded". update now aligns with loader discovery (loader parity): full updates fold untracked installs into the batch after identity dedup (re-resolved via the `.rpi-install-source` marker or the manifest name, never written back to settings; `.tmp-*`/`.old-*` residue directories skipped), `rpi update <name>` can also hit untracked installs by identity, and `rpi list` marks them `(untracked)`. Two robustness riders: a registry batch no longer short-circuits the rest when one source fails (the first error returns at the end of the batch in source order, per-item errors streamed to stderr via the progress callback), and an untracked install absent from the registry (404) downgrades to a skip note — local dev directories don't drag down update; tracked sources still hard-fail on 404.
- **Streaming request total timeout killing active streams** (V13-08, lead-in): `httpIdleTimeoutMs` had been wrongly mapped onto a reqwest total deadline, cutting off long inferences at 4m59s — replaced with a three-stage timeout (connect / headers / inter-chunk body idle, reset per chunk); all 9 SSE adapters covered, with codex's absolute deadline and openrouter_images' one-shot request as two intentional exceptions.
- **write large-file streaming rendering O(n²)** (V13-09, lead-in): whole-block syntect re-highlighting and full rebuilds degraded quadratically with line count — stable-prefix window skip of recomputation + visible-content fingerprint skip of rebuilds + lazy repair_json + agent_loop deep copies 3→2 (erratum: the first release wrongly said 3→1 — the state copy is gone, but the context-tail update is required by upstream parity and event payloads need exclusive ownership, one each remains); measured 400-line streaming 2250ms → 245ms (9.2×), post-completion re-render 46.8ms → 6µs.
- **Extension UI swap tearing** (V13-05, concurrency correctness): widget swaps split into two critical sections, flashing missing frames during the render window; selector swaps hid then showed, flashing a bare editor + focus misplacement — mount_widget atomized under a single lock (cross-container add-then-remove) + selector `swap_editor_region` single-lock clear+add+set_focus.
- **Streaming render hot path copies/rebuilds** (V13-06): `MessageUpdate` queue consecutive-segment folding keeping the tail (a single drain of K deltas → exactly 1 `update_content`) + `update_content` taking a reference to eliminate caller-side deep copies; final frames line-identical, rebuild counts capped by render frame rate.

## Performance (audit-driven)

- **subagents subprocess event persistence governance** (V13-01): events.jsonl / transcript get one persistent handle per child (per-line open/close → 1 open per run), a 50MiB silent-drop ceiling, empty-line skipping, best-effort write failures; status.json writes gated by 100ms coalescing (upstream FileCoalescer semantics), with terminal/`state` changes/final sync flushes.
- **Subprocess update frame throttling** (V13-03): event-path frame-signature gating (skip push on identical activity + 1s heartbeat fallback + first-frame/terminal always pushed) — 50 identical events measured 3 toolUpdate frames (50 with the old code); `subagent_wait` polling with dirty checks (steady state ≤4 pushes per 1100ms, 5 per round with the old code).
- **smart-fetch progress throttling** (V13-04): body_progress 100ms/64KiB dual-threshold gating (single requests and batches share the download path automatically) + batch snapshot 1%-rounded signature short-circuit; terminal frames and frame shapes unchanged (TE08 parity scope reduced to intermediate frames per the plan's risk table).
- **Streaming hot path** (V13-06, see above) + **low-tier miscellany** (V13-07): mcp-adapter `!command` secret parsing moved to spawn_blocking off the tokio workers; status-bar pushes skipped during UI-bridge retries when no UI; `getAllTools` lazy queries (zero host calls on normal mcp dispatch); statusline change-tick reuses fetch_ctx (12 → 6 host calls); TUI per-frame terminal size reads 4 ioctls → 1.
