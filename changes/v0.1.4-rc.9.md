# v0.1.4-rc.9 (2026-09-12)

**Pre-release (pre-release channel)**: round nine of the `0.1.4` stable candidates. This round = **the residual pi-identifier de-branding pass (de-pi pass, ADR-0028)**: after a repo-wide scan, a one-shot cleanup of `pi` identifiers still appearing in rpi's own name (model-visible copy / CLI / outbound HTTP identity / filesystem traces / extension-ecosystem data-plane naming), plus one real doc-vs-code inconsistency fixed. The baseline content matches `changes/v0.1.4.md`; at stable-release time each rc file's entries fold into `v0.1.4.md`. Install/upgrade: existing rpi users run `rpi update --rc` (or `rpi update --all --rc` to sync extensions to `0.1.4-rc.9`); force-install via the official script with `RPI_GITHUB_API_URL=https://api.github.com/repos/revpidev/rpi/releases/tags/v0.1.4-rc.9`.

## Increments relative to rc.8

- **Real-defect fix**: the orchestration skill doc shipped with the subagents plugin said `PI_SUBAGENT_WAIT_TOOL_ENABLED`, while the code has read `RPI_SUBAGENT_WAIT_TOOL_ENABLED` since ADR-0001 — following the doc did nothing. Unified to the `RPI_` spelling.
- **Model-visible copy**: the default system prompt's `operating inside pi` → `operating inside rpi` (until now every session's model introduced itself as pi); the conditionally inserted "Pi documentation" section rewritten as "Rpi documentation"; pi/Pi in the built-in scout agent, smart-fetch / mcp-adapter tool descriptions, subagents model resolution and diagnostic error copy, and the extension host's stale-ctx prompts all became rpi.
- **Orchestration skill rename**: `pi-subagents` → `rpi-subagents` (asset directory, the `SUBAGENT_ORCHESTRATION_SKILL` constant, the install directory `<agentDir>/skills/rpi-subagents/`, skill layout bumped to v3). On upgrade, old `skills/pi-subagents` directories that are verifiably ours (carrying the `.rpi-layout-version` marker or byte-identical to the upstream v1 body) migrate automatically and are removed; user-customized copies are kept untouched. The refinement overlay marker `<pi-subagents-refinement>` → `<rpi-subagents-refinement>` (readers accept the old spelling).
- **CLI / TUI**: `rpi update` help changed from "Update pi" to "Update rpi" throughout; the positional alias `update pi` → `update rpi` (`pi` no longer accepted); "Authentication is configured outside pi." → "…outside rpi."
- **Outbound HTTP identity**: Provider User-Agent `pi (<os> <release>; <arch>)` → `rpi (…)`; the Codex Responses header `originator: pi` → `originator: rpi`.
- **Filesystem traces**: temp prefixes `pi-editor-` / `pi-output` / `pi-bash-` / `pi-clipboard-` → `rpi-*`.
- **Extension-ecosystem data plane (read-compatible)**: the `package.json` resource manifest key `#pi` → `#rpi` (old key still accepted; `#rpi` wins when both exist); the npm-compatibility placeholder package name `pi-extensions` → `rpi-extensions`; mcp-adapter event names `pi-mcp-adapter/status/v1`, `pi-mcp-adapter:tool-approval-request` → `rpi-mcp-adapter/…`; the model catalog api kind `"pi-messages"` → `"rpi-messages"` (old models.json / catalog entries auto-normalize via `normalize_api_kind`; the value never goes on the wire); the share-page `pi-url-params` / `pi-share-base-url` meta names and the `pi-share:v1:` localStorage prefix → `rpi-*`.
- **Deliberately kept (ADR-0028 §5, non-branding surfaces)**: the `https://radius.pi.dev` gateway and the OAuth `client_id: pi-gateway` (external-service dependencies — renaming breaks auth); the third-party extension name `pi-intercom`; upstream-provenance comments, the `external/pi` pinned baseline, and the "derived from Pi" acknowledgment in UPSTREAM.md and the README.

## Behavior changes (upgrade notes)

- `rpi update pi` is no longer accepted — use `rpi update rpi` or `rpi update self`.
- Provider-side UA / originator values change (affects server-side statistics only).
- The share page's localStorage sidebar-width key changes (local preferences reset once).
- Old `pi-subagents` skill installs migrate to `rpi-subagents` on upgrade (user-customized copies untouched).
