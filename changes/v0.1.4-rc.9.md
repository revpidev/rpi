# v0.1.4-rc.9(2026-09-12)

**预发布(pre-release channel)**:`0.1.4` 正式版候选第九轮。本轮 = **残余 pi 标识去品牌化(de-pi pass,ADR-0028)**:全仓扫描后一次性清除仍以 rpi 自身名义出现的 `pi` 标识(模型可见文案 / CLI / 对外 HTTP 标识 / 文件系统痕迹 / 扩展生态数据面命名),并修复一处文档与代码不一致的真缺陷。基线内容与 `changes/v0.1.4.md` 一致;正式版发布时各 rc 文件条目并入 `v0.1.4.md`。安装/升级:已装 rpi 用户 `rpi update --rc`(或 `rpi update --all --rc` 同步扩展到 `0.1.4-rc.9`);官方脚本强装 `RPI_GITHUB_API_URL=https://api.github.com/repos/revpidev/rpi/releases/tags/v0.1.4-rc.9`。

## 相对 rc.8 的增量

- **真缺陷修复**:随 subagents 插件分发的编排 skill 文档写 `PI_SUBAGENT_WAIT_TOOL_ENABLED`,而代码自 ADR-0001 起读取 `RPI_SUBAGENT_WAIT_TOOL_ENABLED`——按文档操作失效。现统一为 `RPI_` 拼写。
- **模型可见文案**:默认系统提示词 `operating inside pi` → `operating inside rpi`(此前每个会话模型都被以 pi 名义自我介绍);条件插入的 "Pi documentation" 段整体改写为 "Rpi documentation";内置 scout agent、smart-fetch / mcp-adapter 工具描述、subagents 模型解析与诊断错误文案、扩展宿主 stale-ctx 提示中的 pi/Pi 全部改为 rpi。
- **编排 skill 更名**:`pi-subagents` → `rpi-subagents`(资产目录、`SUBAGENT_ORCHESTRATION_SKILL` 常量、安装目录 `<agentDir>/skills/rpi-subagents/`,skill layout 升 v3)。升级时对"确属我们写入"的旧 `skills/pi-subagents` 目录(带 `.rpi-layout-version` 标记或上游 v1 逐字节体)自动迁移删除;用户自定义副本保留不动。refinement 覆盖层标记 `<pi-subagents-refinement>` → `<rpi-subagents-refinement>`(读取端兼容旧拼写)。
- **CLI / TUI**:`rpi update` 帮助通篇 "Update pi" → "Update rpi";位置参数别名 `update pi` → `update rpi`(不再接受 `pi`);"Authentication is configured outside pi." → "…outside rpi."
- **对外 HTTP 标识**:Provider User-Agent `pi (<os> <release>; <arch>)` → `rpi (…)`;Codex Responses 请求头 `originator: pi` → `originator: rpi`。
- **文件系统痕迹**:临时前缀 `pi-editor-` / `pi-output` / `pi-bash-` / `pi-clipboard-` → `rpi-*`。
- **扩展生态数据面(读兼容)**:`package.json` 资源 manifest 键 `#pi` → `#rpi`(旧键仍接受,并存时 `#rpi` 优先);npm 兼容占位包名 `pi-extensions` → `rpi-extensions`;mcp-adapter 事件名 `pi-mcp-adapter/status/v1`、`pi-mcp-adapter:tool-approval-request` → `rpi-mcp-adapter/…`;模型 catalog api kind `"pi-messages"` → `"rpi-messages"`(旧 models.json / catalog 条目经 `normalize_api_kind` 自动归一,该值从不上 wire);会话分享页 `pi-url-params` / `pi-share-base-url` meta 名与 `pi-share:v1:` localStorage 前缀 → `rpi-*`。
- **有意保留(ADR-0028 §5,非品牌面)**:`https://radius.pi.dev` 网关与 OAuth `client_id: pi-gateway`(外部服务依赖,改名即断认证);第三方扩展名 `pi-intercom`;上游溯源注释、`external/pi` 钉死基线、UPSTREAM.md 与 README 的"源自 Pi"致谢。

## 行为变化(升级注意)

- `rpi update pi` 不再被接受——用 `rpi update rpi` 或 `rpi update self`。
- Provider 侧 UA / originator 值变化(仅影响服务端统计口径)。
- 分享页 localStorage 侧栏宽度键更换(本地偏好重置一次)。
- 旧 `pi-subagents` skill 安装在升级时迁移为 `rpi-subagents`(用户自定义副本不动)。

## 验证请求(rc.9 重点)

- **skill 迁移**:从 rc.8 升级后确认 `~/.rpi/agent/skills/` 下出现 `rpi-subagents`(旧 `pi-subagents` 目录应消失);若曾自定义该目录,确认副本仍在且不与新 skill 冲突。
- **更新通道**:`rpi update --rc` 正常识别 rc.9;`rpi update rpi` / `rpi update self` 均可自更新。
- **subagent 会话**:让子代理自我描述或读编排 skill,确认其以 rpi 自称且 `RPI_SUBAGENT_WAIT_TOOL_ENABLED` 按文档生效。
- **模型 catalog**:带 `"api": "pi-messages"` 旧条目的自定义 models.json 升级后模型仍可用(`rpi auth` / `/model` 检查 radius 条目)。
- 其余验证面同 rc.8(对话框高度稳定)与 rc.7(ask-user-question 插件)。
