# v0.1.8-rc.3 (2026-11-04)

**Pre-release (pre-release channel)**: the third candidate for the `0.1.8` stable release, carrying the statusline token-accounting work and the fixes found after `0.1.8-rc.2`. The rc.1/rc.2 feature set (upstream parity to Pi v1.4.0, the issue line #72/#73/#76, the durable runtime/storage increments, the extension/session/settings family, and the TE51–TE53 plugin rebase) is unchanged; at stable-release time this file's entries fold into `changes/v0.1.8.md`. Install: existing rpi users run `rpi update --rc` (or `rpi update --all --rc` to also move the seven lockstep extensions to `0.1.8-rc.3`); install.sh does not serve RCs. No registry, schema, model-catalog or version-endpoint change is part of this RC.

## Fixed in this RC

- **Ctrl+C exit no longer stalls after background subagents** (`rpi-subagents`): `session_shutdown` ran the SIGTERM→SIGKILL ladder once per async run in the process registry, and the ladder slept the full 3s even when the run had no live child. Finished runs stay registered for `status`/`wait` (up to 64), so a session that had used background subagents could pay 3×N seconds at every interactive exit, while a freshly resumed session (empty in-memory registry) exited immediately. The harvest now runs one shared ladder for all live children: it returns at once when nothing is live, polls for actual exit after SIGTERM, and sends SIGKILL only to the survivors at the shared deadline. `kill_all_children_for_shutdown` and the `subagent({action:"stop"})` signalling path use the same early-exit ladder, and finished runs no longer cost the grace at all. Regressions: `stop_with_no_live_child_returns_immediately`, `stop_returns_when_the_termed_child_exits`, `kill_all_returns_when_the_termed_children_exit` and `harvest_terminal_runs_does_not_pay_the_stop_grace` (three terminal runs harvest under 500ms; the pre-fix harvest of one terminal run took 3.02s).
- **Status line final rate after a short reply** (`rpi-statusline` items mode): a settled message still applied the streaming 0.5s decode guard, so a short reply produced no rate and the live-row hold kept the previous message's value. The guard now applies only while streaming, the final rate is computed from any positive frozen window, and the settled frame resets the hold cache. Regressions: `settled_messages_refresh_their_own_final_rate`, `settled_frame_resets_the_hold_cache` and the items integration's short-reply frame.

## Changed in this RC

- **Session total tokens, conversation turns and execution steps in statusline items** (`rpi-statusline`): the strict items registry grows from 26 to 29 fields with `total-tokens`, `turn-count` and `step-count`. `total-tokens` is the sum of all four persisted token components (`input + output + cacheRead + cacheWrite`), distinct from `used-tokens` (which excludes cacheRead); `turn-count` is the persisted user-message count, and `step-count` is the persisted assistant-message count (one model output per step). All three come from the same absolute `ctx.sessionStats` snapshot as the existing session totals: the host snapshot now also returns `userMessages` and `assistantMessages` under the same `SessionManager` lock, so resume/fork restores the counts instead of starting at zero, and late replies are still discarded by the request/session generations. Selecting any of the new fields enables the same `turn_end`/`agent_settled`/`session_compact` refresh path; the `/statusline` editor lists them like every other field, and no new host-call, subscription or transcript read is introduced.
- **Bundled official tokenizers for statusline live token accounting** (`rpi-statusline`): the user-local `~/.rpi/agent/tokenizer` registry is replaced by compact zstd tables for DeepSeek, Kimi, GLM, Qwen, Hunyuan (`hy3`/`hy4`) and MiniMax embedded in the cdylib. The tables are generated from pinned upstream revisions by `scripts/gen-statusline-tokenizers.py` (HF BPE and tiktoken engines, pretokenizer regexes, NFC, added tokens) and validated against the official tokenizers/tiktoken plus checked-in vectors; unknown families keep the reference Han/1.2 + other/3.5 estimate marked with `~`. The crate-level `NOTICE.md` is generated with the sources and licenses and is now shipped in `.rpix` packages (`build.yml` copies it and `SHA256SUMS` covers it). Live token counts for the six families are now exact without a user-local tokenizer install; `/statusline` settings and the `live-output-tokens`/`live-output-rate` items are unchanged.

## Verification requests (the point of this RC)

- Exit: use a background subagent in a new session (`async:true`, `workflow:"parallel"`, or a background workflow), let it reach a terminal state, then press Ctrl+C twice. The process must exit immediately, exactly like a freshly resumed session; `subagent({action:"stop"})` must also return without the fixed 3s grace when no child is live. This fix is in the `rpi-subagents` extension, so reinstall the extension (`rpi update --extensions --rc`, or the normal `.rpix` install) before testing.
- Status line: short replies show their own final rate (no stale previous-message value), idle gaps still hold the last measured value in the field's own tone, the six tokenizer families report exact counts while other families keep the `~` estimate, and the new `total-tokens`/`turn-count`/`step-count` items match the session footer on resume. Enable them with `/statusline` and confirm `total-tokens = input + output + cacheRead + cacheWrite`, while `step-count` advances once per model output.
- Packaging: the `rpi-statusline` `.rpix` ships `NOTICE.md` and `SHA256SUMS` covers it; the seven lockstep extension packages install at `0.1.8-rc.3`.

Known boundary: the RC endpoint (`https://revpi.dev/api/latest-rc-version.json`) goes live only after the manually started Release build has uploaded the assets; the stable endpoint (`latest-version`), the schema/model-catalog files and the extension registry stay at their current stable values for this RC. The remaining rc.1/rc.2 verification items (real-account usage-provider smoke, Windows/pwsh paths, the durable crate's experimental boundaries) are unchanged.
