# v0.1.4-rc.11 (2026-09-12)

**Pre-release (pre-release channel)**: round eleven of the `0.1.4` stable candidates. This round = **the pre-release comprehensive review closing in full** (P0×1 / P1×7 / P2×13 + documentation/release consistency + a CI quality gate; one P2-1 item registered as a deferred deviation). The baseline content matches `changes/v0.1.4.md`; at stable-release time each rc file's entries fold into `v0.1.4.md`. Install/upgrade: existing rpi users run `rpi update --rc` (or `rpi update --all --rc` to sync extensions to `0.1.4-rc.11`); force-install via the official script with `RPI_GITHUB_API_URL=https://api.github.com/repos/revpidev/rpi/releases/tags/v0.1.4-rc.11`.

## Increments relative to rc.10

- **P0 panic-hook wiring**: interactive mode and the first-run setup window had never installed a panic hook — any panic left the terminal in raw mode/alt screen, requiring manual `stty sane && reset` (violating the hard requirement in coding-standards §8.5). A handle-oriented recovery hook is now installed after `TuiHandle` construction, covering both the main screen and the fullscreen alt-screen variants (non-blocking try_stop + a fixed recovery-sequence fallback); the terminal always recovers after a panic.
- **P1 fix family**: ① the `read` tool's negative/extreme `limit` triggered a slice panic (a model-controllable parameter) — restored JS slice semantics (empty selection); ② bash-tool timeout/cancel was entirely dead on Windows (kill was a no-op and wait never converged) — landed System32 `taskkill /F /T /PID` + a 5s post-kill grace window; ③ subagents `syntheticPaths` did no normalization validation and could delete directories outside the worktree — upstream's four validation classes added; ④ parallel tool batches losing `tool_execution_end` on panic (start/end pairing broken, `pending_tool_calls` residue) — JoinError slots now emit it; ⑤ the observable window between mcp adapter's `Ready` publication and `on_ready` (including approval restore) — eliminated with a hooks_complete gate (root-causing the full-gate flakiness); ⑥ eight SSE adapters not responding to cancellation during body reads (had to wait for the next chunk or a 5-minute idle timeout) — now raced against the cancel signal; ⑦ the first-run setup flow's early-exit paths leaked raw mode and polluted `was_raw` — error paths stop the UI first.
- **P2 hardening family**: wasm guest memory 128MiB cap (fuel limits CPU only, not memory); SSE single-line 1MiB / Bedrock frame 16MiB fail-fast caps; SSE empty-`data` event tolerance; atomic `auth.json` writes; session `parentId` cycle guards; smart-fetch response-body 32MiB cap (registered deviation); compaction `session_id` upstream semantics; `--rc` with no pre-release index degrading to "already up to date"; extension-name component validation; unique `parity_runner` naming; batch temp-directory hygiene, etc. (the markdown-transform render-lock item is registered as a deferred deviation; the full list is in the review section of `changes/v0.1.4.md`).
- **Documentation/release consistency**: README 38→40 providers; CHANGELOG.md synced with the three additive lines and the review-fix section (that file compiles into the binary driving `/changelog`); mcp-adapter manifest description v2.32.1; the official-site changelog synced; RELEASING.md gained the changelog-sync step.
- **CI quality gate**: a fmt/clippy/test workflow added (main pushes and PRs; previously only tags built, with gates relying on manual runs).

## Verification requests (rc.11 focus)

- **Terminal recovery after panics** (P0): if any panic occurs in normal use (or is constructed deliberately), the terminal should immediately return to a usable state — no more `stty sane && reset`.
- **Windows users in particular**: the bash tool's `timeout` parameter and Esc cancellation should now work (previously they hung the whole tool call).
- **Cancelling long streaming responses**: cancelling mid-stream should stop immediately (no more waiting out the up-to-5-minute idle timeout).
- **`rpi update --all --rc`**: during the rc graduation window, an all-stable extension index no longer hard-errors (downgrades to an "already up to date" notice).
- Remaining verification surface as in rc.10 (dialog height) and rc.8 (dialog height, first round).
