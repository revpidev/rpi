# v0.1.4-rc.12 (2026-09-14)

**Pre-release (pre-release channel)**: round twelve of the `0.1.4` stable candidates. This round = **the final pre-release five-domain parallel comprehensive review closing in full** (P1×2 / P2×10 / test-gap elimination + corrections of inaccurate release-surface claims). Review method: full local gate re-runs + parallel deep code review across five domains (agent / ai / tui / the main crate / extension plugins, line-checked against the upstream submodules) + release-surface consistency checks, with every P1 finding verified twice in code. The baseline content matches `changes/v0.1.4.md`; at stable-release time each rc file's entries fold into `v0.1.4.md`. ## Increments relative to rc.11

- **P1-A malformed-SSE fail-fast completion**: the three `SseDecoder::finish().unwrap()` sites in anthropic / openai-completions / mistral now propagate errors. Constructible trigger: an unwritten tail of exactly ≤1 MiB + an incomplete UTF-8 sequence + EOF → finish appends U+FFFD, crosses the cap, and returns Err → the old code panicked inside the spawned adapter task, while the event-stream sender lives in the shared `Arc<Inner>`, so the channel never closes with the task gone — that turn **hung forever with no terminal event** (violating rc.11 P2-4's "malformed streams fail fast" claim). Added decoder-boundary tests + an anthropic full-chain regression (a custom fetch injecting a malicious body).
- **P1-B codex SSE body-read cancellation** (rc.11 P1-5 residue): the codex SSE loop switched to `next_chunk_or_cancelled` (keeping the header-deadline race). Previously only a pre-read cancellation check existed, so during a silent body Esc/abort could hang up to `httpTimeoutMs` (5 minutes by default; with the SDK's idle timeout disabled ≈24.8 days); the WS transport was already correct, and SSE happens to be the main path for ChatGPT logins. The mock backend gained a "cancel mid-silent-body" regression test.
- **P2×10**: sequential tool-batch panic guards (matching the parallel path's JoinError fill, so SDK Sequential mode no longer permanently rejects later prompts); the SSE line cap bounding only the unterminated tail (multiple complete lines in one chunk no longer false-killed); the pi-messages reader gained the same 1 MiB tail cap; `streamSimple toolChoice` forwarded by eight adapters (#8607, with three wire-level contract tests); session newline-repair failures propagate per upstream; the `--rc` downgrade predicate tightened (range mismatches no longer silently downgrade); the Editor stale-render click branch returns consumed+focus; the mcp `session_tree` approval restore across the gate window (`try_runtime_after_hooks`); subagents syntheticPaths fail-closed at collection + a tracked-path pre-check; openrouter-images body-read cancellation. Full list in the rc.12 section of `changes/v0.1.4.md`.
- **Test-gap elimination**: parent_id cycle-guard double-guard tests, a compaction `session_id` retention positive assertion, the sequential-batch panic regression, `--rc` downgrade/range double tests, SSE boundary two-state, codex cancellation, the mcp gate window, subagents collection three cases — every zero-coverage area named by the rc.11 review is now pinned.
- **Documentation/release surface**: V14-04's `immediate_retry`→`auto_retry_start/end`, the `x-api-source` wording corrected, V14-07's `imageGenerationModels`/mlx wording corrected, V14-16's verified-copy readback gap registered (a v0.1.5 candidate), and the CI entry rewritten to honestly describe the local-gate end state.
- **Nits**: read ±Infinity error copy, the external-editor brand string Pi→rpi, search-whitespace detection switched to ECMA `\s` (U+FEFF), and Container mouse-cache length mismatches treated as misses.

## Verification requests (rc.12 focus)

- **Cancelling long streaming responses (Anthropic/OpenAI completions/Mistral/Codex SSE)**: Esc should take effect immediately; malformed gateway/proxy output no longer hangs the session (terminal Error event).
- **`rpi update --extensions --rc` during the rc graduation window** (a stable-only extension index): should report "already up to date (no pre-release)" rather than error; a source with a range that genuinely mismatches should still error.
- **SDK / `Sequential` tool mode**: a panicking tool no longer freezes the session.
- **MCP approvals after tree navigation**: an old branch's allow_for_session grant should not linger after switching branches (the millisecond-window race is closed).
