# v0.1.5 (unreleased)

In progress — the main line of this release: **upstream parity** (behavioral gold standard `9841914` → `19451accd` / v0.86.1+1, ADR-0029 + ADR-0031), **plugin expansion** (rpiv-todo as the sixth first-party plugin), and **rpi-native fixes** (issues #52/#53/#54).

## Sessions and UI

- **Verified clipboard writes and headless/WSL fallbacks** (#9618/#9688, V15-11): both clipboard doors (`/copy` / `app.message.copy` and the fullscreen selection copy) now run the full write chain — platform commands first (`pbcopy` on macOS, `clip` on Windows, `termux-clipboard-set`/`wl-copy`/`xclip`/`xsel` on Linux, each bounded by a 5s timeout), then WSL interop (OSC 52 preferred inside Windows Terminal; otherwise the Windows clipboard via a UTF-8 temp file + `wslpath -w` + `powershell.exe Set-Clipboard`, which has no OSC 52 size cap), then OSC 52 with #9618/#9688 gating: remote sessions (SSH/mosh) and display-less Linux (containers, WSL without WSLg) emit OSC 52 because the terminal is the only clipboard route, while desktop sessions with a display report the failure with platform-specific guidance ("install `xclip` or `xsel` …") instead of an unverified success — oversized payloads report the 100 KB encoded limit. The fullscreen flash shows the chain's error message for 5s (success still flashes "Copied!"). Upstream's bundled native clipboard helper binaries (#9163) are not ported (deviation D-104): rpi keeps the platform-commands + OSC 52 chain, which the #9618 port completes (rpi previously wrote OSC 52 unconditionally).

- **TUI fix family** (V15-11): LaTeX legacy font switches (`{\rm …}` etc.) no longer fall back to raw source, `cases` layouts center around the surrounding equation (values padded so conditions align, middle-brace layout for even row counts), and unsupported/nested display scripts stack vertically (#8827/#9564/#7929); WezTerm fullscreen Kitty images survive later line clears (#9169 — rows are cleared before drawing when a WezTerm frame places images), and replaced tool-output images no longer render stale Kitty conversions (#8743 — cached PNG conversions carry their source bytes and are only honored while they match); file/attachment completion treats CJK punctuation (，。：等 plus full-width forms) as token boundaries without breaking CJK paths, quotes completions containing CJK punctuation, and sorts `skill:` slash commands by bare name (#9746/#9120); Alt-modified wheel scrolling is accelerated 5× (#9166); a custom footer rendering zero lines no longer reserves a blank row in fullscreen mode (#8919).

- **Per-model compaction budgets, tail-tool-result compaction, and border spinners** (#8133/#9740/`c1d4c8011`, V15-07): `compaction.modelOverrides` keys exact `"provider/modelId"` strings to per-model `reserveTokens`/`keepRecentTokens` budgets, each field resolving independently through model override → ordinary `compaction.*` setting → built-in default (16384/20000); `enabled` stays global, and global/project files deep-merge per field before lookup. Switching models re-resolves on every trigger check (constructor + each manual/auto compaction sync), and extension-visible `preparation.settings` carries the resolved values. Mid-threshold compaction no longer silently gives up when trailing tool results alone exceed `keepRecentTokens` (#9740): the cut falls back to the latest valid boundary — the assistant tool call preceding the oversized result — so the tool-call/result pair stays together and older history still summarizes. The compaction, branch-summarization, and retry spinners now embed in the editor's top border (same opt-in as the v0.1.4 working indicator): all kinds route through the editor embed first and only fall back to the standalone status row when the editor has not opted in; a thinking-level border change re-renders any active spinner.

- **Prompt cache warming** (#9668, V15-05): long tool executions and idle periods no longer silently lose expensive prompt-cache prefixes. The last session request is replayed with a one-token output cap shortly before the cache entry would expire (90% of the model's cache lifetime, ≥10s margin) whenever the expected avoided cache-miss cost exceeds the refresh cost by at least $0.05. The new `cacheWarming` setting picks `"off"` / `"streaming"` (default: warm while the agent run is active) / `"idle"` (also between runs, using a 15% continuation estimate, capped 30 min after the last real request; active runs cap at 60 min) — global-only, because each refresh costs money; `/settings` exposes it next to the HTTP idle timeout. Warming needs a known cache lifetime: built-in direct-Anthropic models carry one (`promptCache` in the catalog, V15-03), and custom models / provider overrides can declare theirs in `models.json`. Claude models with budget-based (non-adaptive) thinking are skipped while thinking is on, because the replay cannot reproduce their keyed budget. `/session` gains a Cache Warming section (mode, next decision, continuation probability, expected savings vs. the $0.05 threshold, miss penalty and refresh cost); each successful refresh shows in the transcript behind `showCacheMissNotices` with its cost. Refresh usage is persisted as a new `usage` session entry (`kind: "cache_warm"`) that counts toward session totals but never enters model context, and never appears in the conversation tree; older binaries keep reading such sessions via the unknown-entry passthrough. Extensions can veto or force each refresh through the new additive `cache_warming_decision` event (last override wins; handler failures fall back to pi's own decision).

- **Progressive session discovery** (V15-04, upstream `dfbf793b7`/`dd01f5b24`/`9b791a4cc`/`e687434a6` @ v0.86.1): the `--resume` session picker now loads progressively — the most recent sessions render as soon as their headers/messages are read (first session immediately, then batches of 10 for the current folder / 100 across all folders) instead of after a full directory scan, and selecting or cancelling a session aborts the remaining transcript reads. `--continue` stats all candidates first and reads session headers newest-first, stopping at the first cwd match (no more header-scanning the whole directory); exact `--session <id>` lookups resolve from session headers alone without loading transcript bodies. Tree navigation (`/tree`) is now rejected while a response is streaming or a compaction/branch-summary is in flight ("Wait for the current compaction or tree navigation to finish…"), so it can no longer swap the leaf out from under the compaction progress UI. Selected sessions are byte-identical to the previous implementation — only load order and timing changed.

## Tools and extensions

- **Built-in tools prefer strict JSON-schema sampling** (`fcff255b0`, V15-08): `read`, `bash`, `edit`, and `write` now declare `constrainedSampling: { type: "json_schema", strict: "prefer" }` unconditionally — providers that support strict tool schemas convert the parameter schemas on their side (unsupported constructs still fall back to the unstrict form, since the preference is `prefer` not `require`), and the execution schemas themselves are unchanged. Upstream's list also includes `powershell`, which rpi does not ship. Extensions re-registering a same-named tool with `constrainedSampling: false` (or their own config) override the built-in default — the definition value now reaches the executable tool instead of being dropped at the host boundary.

- **Bash tool durations above one minute render readably** (#9628, `fe219d7f8`, V15-08): the Elapsed/Took line keeps `X.Ys` under a minute and switches to `Xm Ys` (and `Xh Ym Zs` past an hour), e.g. `1h 3m 4s` for a 2-hour-3-minute build. Sub-minute precision is unchanged, including the `59.9s → "60.0s"` rounding quirk at 59_999 ms.

- **Signal-terminated shell commands fail with their partial output** (#9577, `a8b3dd199`, V15-08): a bash child killed by a signal (OOM-killer, external `kill`, …) maps to the conventional `128 + signal` exit code and reports `Command exited with code 137`-style errors with the output collected so far, instead of silently succeeding with no exit code. Custom `BashOperations` backends resolving to no exit code at all now fail the command with `Command terminated without an exit code` (also with partial output preserved).

- **Extension tools without a parameter schema are rejected at registration** (#9300, `acaa253cc`, V15-08): `registerTool` with missing, non-object, array, or scalar `parameters` fails the registration with `Tool "<name>" registered by extension "<path>" must define an object parameter schema.` instead of breaking provider request serialization later. The wasm channel no longer silently defaults a missing schema to `{"type":"object"}`; affected guests fail to load with the same message.

- **`pi.on()` returns an unsubscribe handle** (#8967, landed as `46c9de402`, V15-09): native extensions get a callable `OnUnsubscribe` from `ExtensionApi::on` — removing exactly that registration, idempotent on repeat calls, with the last removal of an event dropping its handler entry. Handlers added or removed during a dispatch apply to later dispatches only (each dispatch snapshots the handler list; a nested dispatch takes a fresh one). Over the JSON guest ABI the same surface reads: `on` now answers `{subscriptionId}` (previously `null`; old guests ignore it) and the new additive `off` host-call (free capability, same as `on`) removes one registration — the wasm SDK wraps it as `SubscriptionId` + `subscribe`/`unsubscribe`, tearing the host forwarder down when the last guest handler of an event goes away.

- **`ctx.modelRegistry.stream()` / `streamSimple()` for extension model calls** (#8964, `1f78cea7a`, V15-09): extensions call models through the configured providers with resolved authentication (including providers registered via `pi.registerProvider()`) instead of reimplementing transport — native callers receive the live `AssistantMessageEventStream`; over the JSON guest ABI the synchronous boundary collects it into `{events, result}` (every stream event plus the final message; setup failures surface as an error event + error result, an unbound session answers the standard `unbound` envelope). Options carry the portable subset (`temperature` / `maxTokens` / `reasoning`, plus `toolChoice` on `streamSimple` where `reasoning` excludes `"off"`); the callback-bearing fields of the upstream options cannot cross JSON — the same contract `ctx.modelRegistry.complete` established.

- **Hook event/result types exported at the package entries** (#9642, `4c2d91339`, V15-09): the 60 hook event/result types and their string enums are re-exported from the `rpi_ext_host` crate root (native package entry; everything was already reachable via `types::` — surface alignment only), and the wasm SDK gains `rpi_ext_sdk::events` — typed guest-side views of the same surface for deserializing event payloads, with heavy payloads carried as `Value` per the JSON-boundary rule.

- **RPC `steer` / `follow_up` run extension `input` handlers** (#8718, `faa9863cb`, V15-09): direct RPC steering and follow-up messages now pass through the extension `input` handlers like interactive prompts, preserving their `rpc` input source and streaming behavior — a `handled` result drops the message, a `transform` result queues the transformed text (previously both commands bypassed the handlers entirely).

- **[BREAKING] `user_bash` fails closed** (#9068, `509ee2bd0`, V15-08): an extension `user_bash` handler that throws, or returns a defined-but-invalid result (anything other than exactly one valid `{ operations }` / `{ result }` object), now **aborts the `!`/`!!` command** — later handlers are not invoked and the command never falls back to the local shell. Return `undefined`/`null` to keep propagating; a full-replacement result must carry string `output`, `exitCode` (number or null), boolean `cancelled`/`truncated`, optional `fullOutputPath`. Because custom execution backends (`operations.exec` closures) cannot cross rpi's JSON extension boundary (ADR-0007 gap 1), an `operations`-shaped result is always invalid over that boundary and now aborts the command — the previous drop-with-warning fallback to local execution is gone (breaking for extensions that relied on it). The error is reported through the standard extension error surface.

## Protocol and providers

- **Meta provider with Muse subscription OAuth** (#9096, V15-15): the Meta Model API joins the built-in provider family (`/login meta` → *Sign in with Meta*, or `META_API_KEY`) — device authorization against `auth.meta.com` mints a Model API key via the Muse Code key-mint endpoint (models default to `muse-spark-1.3`, OpenAI-Responses wire, catalog shipped with V15-03). The identity token is stored as the refresh credential and the minted key as the access credential, so the standard OAuth scheduler re-mints the key about once a day; the identity itself is not renewable, so a mint 401/403 clears the path to `/login meta` (sign in again) instead of silently retrying.

- **Built-in model catalog regenerated at the v0.86.1 pin** (`19451accd`, V15-03): 39 → 41 provider catalogs / 1397 → 1443 models (models.dev + OpenRouter/NVIDIA/Vercel snapshot 2026-09-20), retiring the v0.1.4-rc.13 catalog-only refresh (D-101 closed — catalog and behavior pin re-aligned). New faces: the **Radius public catalog** ships built-in (27 models incl. the `balanced`/`cheap`/`precise` routers — Radius models are now selectable immediately after login, with the account's gateway catalog overlaying the static baseline once fetched; custom gateways declared in `models.json` keep their own catalog and do not inherit the public one), the **Meta provider catalog** (5 Muse entries, provider + subscription OAuth land separately), per-tier **prompt-cache lifetimes** on Anthropic models (`promptCache`, consumed by the upcoming cache warming), and Cerebras models marked `supportsStrictMode: false` (mixed strict/unstrict tool usage 400s there). Retired: GPT-5.4 Codex models, the standalone `deferredToolsMode`/`supportsToolReferences` catalog keys (replaced by the mid-conversation compat faces), and stale zai-coding-cn/moonshotai entries per the current models.dev snapshot.
- **SSE idle timeout now defaults to unlimited** (rpi#54, V15-12, deviation D-103 from pi/undici's 5-minute default): `DEFAULT_HTTP_IDLE_TIMEOUT_MS` flips from `300_000` to `0` (disabled), so rpi itself never kills a streaming request over a silent gap by default — reasoning-model thinking pauses, first-token latency after a large prefill, and buffering gateways frequently sit silent for more than five minutes, and the old default aborted those perfectly healthy streams mid-thought (`stream idle timeout: no data for Xms`). The three idle budgets (connect / headers wait / inter-chunk body gap, V13-08 semantics) and explicit configuration are unchanged; the `/settings` selector renders the default as `unlimited`. **Restoring the old behavior**: set `httpIdleTimeoutMs: 300000` in `~/.rpi/agent/settings.json` (any finite value re-enables the idle kill at that budget); genuinely dead peers are still surfaced by OS/TCP-level errors, and Esc-abort remains immediate regardless of the timeout.
