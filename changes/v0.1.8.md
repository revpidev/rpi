# v0.1.8 (TBD)

This file records the V18-00 through V18-05 work and the completed V18-06 implementation. It is not the complete v0.1.8 release note; the remaining version tasks, second independent review and final release review are still pending.

## Breaking Changes

- **Durable tool tasks and session failures** (V18-06): `pi.tool` is version 2. `ToolTaskInput` and `ToolTaskResult` are tagged unions (`kind: "model" | "nested"`), and a stored version 1 input migrates to a model-issued task. `ToolExecutionResult.content` is now `output`, with `structuredOutput` beside it; a code-level consumer must rename the field. The durable `StorageRejected` matching surface is gone: storage reads that reject an invalid request carry `StorageRequestError`, and every other storage error fails the Session. Later calls and pending waits reject with `SessionFailed`, `Session.closed` settles `{reason:"closed"}` or `{reason:"failed",error}`, and a failed Session ends its watches with `WatchEnd::SessionFailed`.
- **Durable SQLite schema version 2** (V18-05): opening a version 1 durable SQLite database rebuilds its task table to allow the `sleeping` status and records version 2. A migrated database cannot be opened by rpi 0.1.7 or earlier, so keep a copy before opening a valuable database with this build. The rebuild runs inside one transaction; a failed or interrupted migration rolls back to a usable version 1 database with its rows and indexes intact. Migration tests operate only on temporary database copies. JSONL needs no migration: format 1 directories are read unchanged.
- **Kimi Code uses OpenAI Chat Completions and requires an explicit `/v1` base URL** (V18-01): the built-in endpoint is now `https://api.kimi.com/coding/v1`; the former Anthropic Messages transport is not an implicit fallback. A custom `baseUrl` under `providers.kimi-coding` in `models.json`, including a provider-wide or per-model override supplied through an extension, must contain `/v1` as a complete path segment. Update a legacy `https://api.kimi.com/coding` override to `https://api.kimi.com/coding/v1`, or use your proxy's explicit `/v1` URL. rpi rejects a missing segment during provider composition and before any request with the provider, model, configuration key and a migration example; it never appends the suffix or rewrites the configured URL. Invalid configurations cannot bypass the check through the native-provider fallback, and request errors do not echo URL credentials. Existing `/v1` paths, including later path segments and repeated segments, are preserved.

## Changed

- **Durable sleeping, timers and restart limits** (V18-06): `TaskRuntime.sleep()` is replaced by `sleepUntil(until, checkpoint, context)`: the task commits the `sleeping` state, holds no invocation, and resumes at its checkpoint once the Harness clock is due. Generation retry/backoff and compaction retry sleep this way and sleep again on an early wake. `HarnessOptions.setTimer` arms pacing timers (a declined foreground timer falls back to the runtime timer); `Harness.wake()` reports active work or the earliest sleep and `onWake` hands it to a host alarm. Surviving `running` tasks count a restart when a Harness opens; at `restartLimit` (default 5, `Infinity` never parks) they are parked until `retryTask()`, a committed state clears the count, a normal close writes stopped tasks back as pending without counting, and an abort handler cut off at the limit faults.
- **Durable submissions and document retention** (V18-06): an input may carry an `InputEntry` (kind + data) placed instead of `pi.user`, with kinds outside `pi.*`; queued inputs keep it in `pi.inbox`. A display-only write (only kind and data) is appended and settled done at once even while busy, unless a reset is queued. `afterFailedRun` keeps, continues, or withdraws inputs queued behind a failed run. `documentRetentionMs` bounds the Session document cache: an unobserved document is reloaded after its last use, while a watch or state keeps it.
- **Durable code mode and images** (V18-06): a `codemode` tool runs a host deterministic sandbox with durable start data, a start reply and a clocked nested-call journal; a repeated key or replay after a restart returns the stored result without executing the call again, and divergence/ordering/corruption fail explicitly. Scripts get `store`/`load`, `searchTools`/`describeTool`/`describeNamespace`/`ALL_TOOLS`, `models.*` catalog and classifier/image calls, the budgeted `codemode` prompt section and bounded output. `read` returns supported PNG/JPEG/GIF/WebP images within 2000x2000 pixels and about 3.4 MB instead of an `unsupported_image` error. Per-model compaction overrides apply at the threshold check, overflow recovery and range selection.
- **Durable nested tool calls and structured output** (V18-06): a tool can run another tool through `executeTool()`. The nested call is its own `pi.tool` task owned by the caller, keyed for replay-safe reattachment, visible in `pi.live.nestedTools` with the arguments it runs with and a bounded summary, and its result is stored in the caller's `NestedCallDoc` until the caller settles; nested calls left running are aborted first. A tool declares who may call it (`callers`), can stay hidden from the model until `modelTools` loads it (`deferred`), and declares `structuredOutputSchema` for programs. A result without that schema gives programs its bounded output (one text as a string, one image as itself, `""` for none, else the list). The durable `tool_search` extension (BM25) loads matching deferred tools through `control.addTools`, which writes the conversation's `modelTools.add`.
- **Durable shell results** (V18-06): `bash` and `powershell` return a nonzero exit as an error result with an `exit_code` diagnostic and structured output (`output`, `truncated`, optional `fullOutputPath`, `exitCode`) instead of throwing; timeouts and spawn failures still throw.
- **Mouse-wheel scrolling, hardware cursor and terminal restore** (V18-04): a focused fullscreen overlay only consumes the wheel events it handles, so the transcript still scrolls; PageUp/Home/End keep deferring to the overlay. `showHardwareCursor` now draws only the terminal cursor: the focused component's fake cursor is removed instead of adding reverse video on top, while unfocused components keep their reverse-video cursor. The panic/abnormal-exit fallback restore also disables mouse tracking and focus reporting and re-enables autowrap, so a crash cannot leave the shell flooded with mouse sequences.
- **Clipboard and delayed terminal replies** (V18-04): POSIX clipboard helpers run in their own process group, so Ctrl+Z no longer suspends a daemonized `wl-copy`/`xclip`/`xsel` owner and later paste works. `RPI_CLIPBOARD_OSC52=1` also sends copies through OSC 52 for remote clients that leave no SSH markers. Delayed terminal replies (OSC 10/11/4 colors, OSC 7501 program status, XTVersion, Kitty graphics) stay buffered until their terminator, so a fragmented color reply no longer leaks hex into the prompt or turns its BEL into Ctrl+G. Shifted symbols such as `+` and `ctrl++` match under the Kitty keyboard protocol and modifyOtherKeys again.
- **Terminal support and CJK rendering** (V18-04): Rex is detected with OSC 8 hyperlinks, truecolor and Kitty images; Herdr now reports Kitty image support. Bold and italic next to CJK punctuation render instead of showing literal `**`/`*`, an unclosed `$$` display-math opener no longer swallows the following table, and a closed display-math block whose line starts with a list marker (`+ b`) stays math.
- **Windows shell resolution** (V18-04): the legacy WSL `bash.exe` launcher is recognized from any absolute `%SystemRoot%`, Git Bash is searched in `%ProgramFiles%` and `%ProgramFiles(x86)%`, and a `where` result is accepted with an access check so Microsoft Store aliases remain runnable. The PowerShell tool stays intentionally absent on rpi.
- **Read line ranges and configuration schemas** (V18-04): the expanded read row, the session tree and the exported HTML viewer share one line-range contract that accepts numbers, numeric strings and `null` and omits malformed ranges. The four configuration schemas are served at `https://revpi.dev/schemas/` with an explicit JSON content type and site-side tests, and the README/docs link them.
- **CLI and template parity** (V18-04): print mode (`-p`) writes the partial response to stdout, warns on stderr and exits 1 when the final response hits the output-token limit; `@` file completion escapes regex metacharacters in the query; prompt templates keep empty quoted arguments (`""`/`''`) in place; `~` expands in `!pattern`/`+path`/`-path` settings entries; a managed-install manifest with a UTF-8 BOM is accepted; the native `grep` tool keeps `rg --no-config` semantics (it never reads `RIPGREP_CONFIG_PATH`).
- **Configuration schemas, share destination and coordinated settings writes** (V18-02): the settings, models, keybindings and theme schemas generated from the pinned Pi v1.4.0 models are vendored by `scripts/sync-config-schemas.py`, branded to `https://revpi.dev/schemas/...` and published under `schemas/` (and the site's `schemas/` directory); built-in themes now point their `$schema` at `https://revpi.dev/schemas/theme.schema.json`. `/share` reads `sessionShareDestination`: `auto`/`gist` use the GitHub gist backend, while `radius` fails explicitly before any upload (rpi has no Radius backend) instead of silently using another service. All first-party settings writes now take the fixed host `fs2` lock then the `<settings>.write-lock` lease, re-read under both locks, preserve untouched top-level keys, the original trailing-newline state and Unix mode, and replace the file atomically; the subagents writer participates in the same A→B order. Windows closes the legacy handle before the same-directory replacement while keeping the authoritative lease.
- **Codemode declarations, worker capacity and timing** (V18-03): tool declarations now show the JSON Schema constraints a TypeScript type cannot express as property comment tags (`@integer`, numeric/exclusive bounds, `multipleOf`, string/array length, `pattern`, `format`, `uniqueItems`, `default`, `deprecated`), read through nullable `anyOf`/`oneOf` branches and draft-04 boolean exclusive bounds; a type over the size budget is rendered again without tags before becoming `unknown`. MCP output schemas render as their own object types instead of `CallToolResult<T>` (the shared MCP type preamble and `mcpStructuredContentSchema` are removed), so an MCP tool without an output schema serializes `structuredContent` as `unknown`. A `// @options:` line that is not the first line is rejected instead of silently ignored. At most two codemode workers may be alive per process (shared by every session and in-process subagent) until the worker thread actually exits; `RPI_CODEMODE_MAX_WORKERS` raises the limit and is read on every admission (positive integers only; invalid values keep the default). At capacity, scripts wait in arrival order up to 60 seconds or their own `timeout_ms`, the wait is cancellable, and the failure says the script did not start. Codemode rows show `Elapsed` while a script runs and `Took` once it finishes, and adjacent text output is joined in linear time.
- **mcp-adapter uninstall guidance removed** (V18-02): the retired `rpi-mcp-adapter` no longer produces a startup removal recommendation or an `rpi update` skip note. An already-installed copy keeps loading, is never deleted automatically, and the plugin crate/registry is not restored; the generic deprecated-extension mechanism remains for a future host-built-in replacement.
- **Extension startup and concurrent dialogs** (V18-02): `before_agent_start` is a `messageType:"user"|"custom"` union and now also fires for idle `sendMessage(..., { triggerTurn: true })` runs, carrying the starting custom message. The session counts as busy from the start of run setup, so messages sent while handlers run join that run instead of starting a second one, an abort requested during setup stops the run at its first request, and the handler-patched system prompt stays stable for the whole run. Concurrent `select`/`confirm`/`input`/`editor`/custom dialogs now form a stack: closing the top restores the previous dialog, a late `done()`/timeout closes only its own frame, and every promise settles. The additive `ui.hasOverlay` query returns `{visible,capturing}` for the current session (hidden and inline-only components excluded; `capturing` implies `visible`), with `{false,false}` on RPC/NullUi and `unsupported-output`-style fallbacks unchanged for old hosts.
- **Extension status rows wrap instead of truncating** (V18-02): `ctx.ui.setStatus` values stay sorted by extension key and whitespace-folded, are joined with a single space, and now wrap to the terminal width with ANSI SGR styles preserved across breaks. The footer grows by the wrapped rows instead of dropping the tail behind a dim ellipsis. This is a host-side rendering change (`rpi-statusline`/`rpi-usage` keep their own content and refresh cadence).
- **New additive extension APIs: `ctx.sessionStats()` and `ui.emitText`** (V18-02, `rpiAbi` stays `1`): `ctx.sessionStats()` returns one host-authoritative absolute snapshot from a single session lock (`sessionId`, optional `sessionFile`, RFC3339 `startedAt`, `entryCount`, the four token components and `cost`); the raw provider `totalTokens` is neither read nor returned, and in-memory sessions omit `sessionFile`. `ui.emitText {text, validateOnly?}` outputs command text through the current mode: TUI notification, RPC/`--mode json` `extension_ui_request` notify frame, or controlled stdout in print mode. `validateOnly` checks the channel without writing; NullUi/subagents answer `unsupported-output`. Print/json bridges are output-capable while `hasUI` stays `false`, so command output is never gated on interactive UI availability.
- **Provider catalog refreshed from the Pi v1.4.0 generator** (V18-01): the 2026-10-27T01:36:18.091Z snapshot contains 42 provider catalogs and 1718 entries (1602 chat, 63 image, 53 classifier), versus 1731 in v0.1.7. GitHub Copilot's default moves from `gpt-5.4` to `gpt-6.1-sol`; NVIDIA's default moves to `nvidia/nemotron-3.5-super-vl-120b-a12b`; Xiaomi remains on `mimo-v2.6-pro`. MiniMax M3.1 Flash and Kimi K3.1 Pro variants arrive, Grok 4.3/4.5 expose `xhigh`, and OpenAI Codex removes models ChatGPT rejects and gives `gpt-6.1-sol` its 500K context window. Generated provider metadata, compatibility flags, prices, context/output limits and the public `revpi.dev` model catalog come from the same generator snapshot.
- **OpenCode and OpenRouter transport updates** (V18-01): OpenCode Zen and Go now use their `/inference` and `/inference/go` endpoint families with the model's protocol selection; their usage origin remains a separate fixed configuration and is not derived from a custom inference URL. OpenRouter can personalize its model catalog for the configured key through `/models/user`, including key-specific prices and context/output limits, regional base URLs, a credential-fingerprinted cache namespace, offline same-key reuse, and built-in fallback when no key or cache is available. Negative placeholder prices are normalized to zero and `router/auto` behavior is preserved.
- **Consistent model compatibility, identity and authentication** (V18-01): provider defaults, model overrides, extension/virtual models and classifiers share compatibility inheritance, including image-input and opt-in-header behavior. Client identity and attribution now propagate through ordinary chat, image/classifier calls, extension stream/complete calls and the durable harness seam; `before_provider_headers` runs before provider-specific identity headers, while `null` header overrides still remove headers. Model changes discard the previous model's thinking blocks without clearing same-model thinking-level changes. Bare model ids offered by several providers prefer an unambiguous configured credential, preserve duplicate provider entries in model scopes, and report actionable ambiguity instead of silently picking catalog order.
- **Authentication origin boundaries** (V18-01): provider and future usage consumers share a process-local resolved-auth view with credential kind, effective origin and a salted credential generation; it does not serialize secrets or account ids. OAuth rotation and legitimate Copilot enterprise origins retain distinct identities. Conflicting Codex account ids fail closed, and a custom/proxy model URL cannot inherit an official subscription identity; configure an API key for that endpoint or restore the provider's official base URL.
- **CJK-friendly Markdown in HTML export** (V18-00): the Pi v1.4.0 viewer assets now include the CJK-friendly Markdown parser; `scripts/sync-export-html-assets.py` deterministically vendors the six embedded assets and `export_html.rs` loads the CJK parser between the base Markdown and highlight scripts. The export smoke test scans for known and generic placeholders.

## Fixed

- **MCP structured content, resources and OAuth lifetime** (V18-03): `structuredContent` may be any JSON value (object, array, `null`, primitive), and a present `null` is no longer conflated with a missing field; MCP tools without an output schema type it as `unknown`. Connections no longer list resources when connecting (which could keep a slow server's tools out of the first prompt); `/mcp` and `rpi mcp list --json` report `resources: true` instead of counts and the resource tools list on demand. `mcp.json` files starting with a UTF-8 BOM are read and edited normally. An authorization response's `iss` is rejected when no authorization server metadata was discovered (no issuer to compare with) instead of skipping the check, and a request cancelled, timed out, or closed while a shared authorization refresh was in progress is not dispatched or retried afterwards.
- **Radius/rpi-messages final tool arguments** (V18-01 review): the server-authoritative `toolcall_end` frame now copies `argumentsError` and `namespace` (and an omitted thought signature still preserves the local one), so a malformed final call is rejected by validation instead of executing the empty `{}` fallback. The `done`/`error` frames also carry `providerThinkingLevel` into the assistant message.
- **Settings lease liveness and reads** (V18-02 review): every lease directory now holds an OS-locked `lease.lock`; the OS releases it on process death, so a crashed owner (including on Windows) and an ownerless/truncated `owner.json` can be reclaimed. Pure reads take only the legacy A lock, so a stale write lease no longer turns settings into an empty in-memory load. The host and subagents writers share the hostname source, the Unix start-time comparison, deterministic key order, and the no-trailing-newline new-file state; a failed subagents first write removes the empty file it created.
- **Concurrent prompts** (V18-02 review): the run-start transition is an atomic compare-exchange taken before auth/setup awaits. Two concurrent prompts can no longer both observe an idle session and start a second run; the loser is queued (with `streamingBehavior`) or rejected before the preflight success response, so its message is never silently dropped and it cannot clear the winner's busy state; a setup future dropped before the handoff releases its claim.
- **Durable telemetry** (V18-06): `HarnessOptions.telemetry` installs a content-free context on every invocation. Phases record task id/name/phase/kind, tools record tool name and call id, and a nested call answered from its stored result adds `pi.durable.replay`; no prompt, token or tool output is recorded.
- **Durable storage failures end the Session** (V18-06): any Storage method error fails the Session except a read that is a `StorageRequestError` (or whose caller was cancelled), which fails only that call. `commit()` and `mintId()` fail it for every storage error, as do the scheduler's own commits. Host `subscribeCommits`/`subscribeClose` listener panics are reported and contained; a component commit listener's panic fails the Session. Nothing retries, and a reopened Session recovers from what was committed.
- **Tool reachability declarations and namespace aliases** (V18-02): extension tool definitions accept `reachesTools(input)` (native callback; wasm guests can declare the static `"all"` or a word array) and `ToolNamespace.aliases`. MCP waiting now uses the shared reachability query, so a codemode script or `tool_search` waits only for the servers it may reach; built-in codemode returns `"all"` for discovery helpers and its identifier words otherwise, `tool_search` and resource tools reach every server, and codemode `describeNamespace()`/`searchTools({namespace})` accept aliases.
- **Resumed sessions restore the recorded tool loadout** (V18-02): with the default tool selection, resume and `/tree` restore the branch's active tools, apply `--tools +name`/`-name` modifiers, activate extension tools registered after the branch recorded (unless `defaultActive:false`), keep explicitly removed tools inactive across later registrations, and keep recorded-but-not-yet-registered tools pending. Explicit `--tools` names, `--no-tools` and `--no-builtin-tools` still replace the recorded loadout. Output-limit recovery also omits the truncated tool call and its tool results together (pre-prompt and post-run), so a provider never rejects an orphaned result on the next request.
- **Compaction summaries use the model's output budget** (V18-02): conversation, branch and split-turn-prefix summary requests no longer cap output at `0.8 * reserveTokens`, `0.5 * reserveTokens` or a hardcoded 4096. They leave output sizing to the provider from the actual request, so reasoning-heavy models no longer fail with "generation hit the token cap" before the summary completes; `compaction.reserveTokens` only controls when compaction starts. Compaction, branch summaries and bug reports also omit thinking blocks from `serializeConversation` (replayed thinking is often not in the live context), and `/compact <instructions>` now reaches the split-turn prefix summary even when the split turn is the only new content since the last compaction.
- **Classifier image and compatibility paths** (V18-01): `models.classify()` carries image-capability metadata and identity through TypeSafe Jev, Cloudflare Clef and OpenRouter classifiers instead of treating those entries as chat models or dropping provider compatibility overrides. Unsupported input is rejected before dispatch.
- **Final tool arguments cannot execute a valid prefix of malformed input** (V18-01): Anthropic Messages, Bedrock Converse, Mistral Conversations, OpenAI Chat Completions and OpenAI Responses retain string repair for recoverable input, but malformed, truncated or non-object final arguments become `{}` plus an `argumentsError` containing the reason and original text. Tool validation fails rather than executing a partially parsed call.
- **Provider response and retry fixes** (V18-01): ChatGPT Business workspace/quota errors are not classified as transient HTTP retries; Copilot oversized requests enter context-overflow recovery; gateway/transport retry classification no longer treats digits in request ids or byte counts as an HTTP status. Anthropic strict tools fall back only for the designated schema-support errors, error tool-result images follow all tool results where required, whitespace-only output is treated as empty, Mistral applies its request timeout to response-header waits without cutting off active bodies, and Gemini/OpenAI-compatible thinking and content ordering cases are preserved.

## Internal

- V18-06 ports the nested tool, structured-output, storage-failure, sleeping/timer/wake, crash-loop, submission, ownership, `listFiles`, document-retention, read-image, telemetry/report and durable code mode surfaces of Pi v1.4.0. The code mode VM stays a host-provided deterministic sandbox; the durable start/journal/store/replay and discovery/catalog surface live in `rpi-durable`. Full gates: 392 durable tests and 8223 workspace tests passed; the PowerShell installer suite (45 checks) ran against a standalone pwsh 7.6.9 with invariant globalization. The durable `tool_search` tool and its BM25 ranker live in `rpi-durable` rather than the host so the crate stays independent.
- V18-01 uses Pi v1.4.0 `4a080252f06caf63a525d7873c5d94d3c23887e0` as its behavior reference. The catalog is vendored by `scripts/refresh-model-catalog.sh`; `rpiAbi` remains `1`. No registry, RC/stable endpoint or deployment action is part of this task. Private providers and paid subscriptions were exercised only with local fixtures and loopback stubs, not real accounts.
- The synthetic tool-load call-id prefix emitted on the OpenAI Responses wire changed from `pi_tool_load_` to `rpi_tool_load_`; no consumer parses the prefix.
- Durable SQLite now takes an optional table/index prefix (`SqliteStorageOptions`, `NodeSqliteStorageOptions`, and `open_node_sqlite_storage`), validating an empty, malformed or reserved `sqlite_` prefix before the database file is created. The portable driver interfaces, generic migration runner and prefix validator moved to `chord/sqlite` (upstream v1.3+ layout); `rpi_durable::storage::sqlite::*` and the crate-root names remain as re-exports. `CURRENT_SQLITE_SCHEMA_VERSION` is 2 and the public `create_sqlite_migrations(&SqliteSchema)` (signature now takes the rendered schema, matching upstream) renders the immutable v1 and v2 history; V18-06 can pass its own schema without touching the migration text.
- Project-owned `pi_*`/`Pi*`/`PI_*` identifiers were renamed to rpi spelling (for example `api/rpi_messages.rs`, `RpiMessages*`, `rpi_messages_*` diagnostics, `rpi_defaults`, `to_rpi_model`, `RpiManifest`); upstream source paths, the legacy `"pi-messages"` API kind, and external service identifiers remain as compatibility/provenance values. See ADR-0028's 2026-10-28 amendment and the naming standard in `AGENTS.md`/`coding-standards.md`.
