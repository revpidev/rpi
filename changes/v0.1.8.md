# v0.1.8 (TBD)

This file currently records the V18-01 provider/catalog work only. It is not the complete v0.1.8 release note; the remaining version tasks and final release review are still pending.

## Breaking Changes

- **Kimi Code uses OpenAI Chat Completions and requires an explicit `/v1` base URL** (V18-01): the built-in endpoint is now `https://api.kimi.com/coding/v1`; the former Anthropic Messages transport is not an implicit fallback. A custom `baseUrl` under `providers.kimi-coding` in `models.json`, including a provider-wide or per-model override supplied through an extension, must contain `/v1` as a complete path segment. Update a legacy `https://api.kimi.com/coding` override to `https://api.kimi.com/coding/v1`, or use your proxy's explicit `/v1` URL. rpi rejects a missing segment before provider registration with the provider, model, configuration key and a migration example; it never appends the suffix or rewrites the configured URL. Existing `/v1` paths, including later path segments and repeated segments, are preserved.

## Changed

- **Provider catalog refreshed from the Pi v1.4.0 generator** (V18-01): the 2026-10-27T01:36:18.091Z snapshot contains 42 provider catalogs and 1718 entries (1602 chat, 63 image, 53 classifier), versus 1731 in v0.1.7. GitHub Copilot's default moves from `gpt-5.4` to `gpt-6.1-sol`; NVIDIA's default moves to `nvidia/nemotron-3.5-super-vl-120b-a12b`; Xiaomi remains on `mimo-v2.6-pro`. MiniMax M3.1 Flash and Kimi K3.1 Pro variants arrive, Grok 4.3/4.5 expose `xhigh`, and OpenAI Codex removes models ChatGPT rejects and gives `gpt-6.1-sol` its 500K context window. Generated provider metadata, compatibility flags, prices, context/output limits and the public `revpi.dev` model catalog come from the same generator snapshot.
- **OpenCode and OpenRouter transport updates** (V18-01): OpenCode Zen and Go now use their `/inference` and `/inference/go` endpoint families with the model's protocol selection; their usage origin remains a separate fixed configuration and is not derived from a custom inference URL. OpenRouter can personalize its model catalog for the configured key through `/models/user`, including key-specific prices and context/output limits, regional base URLs, a credential-fingerprinted cache namespace, offline same-key reuse, and built-in fallback when no key or cache is available. Negative placeholder prices are normalized to zero and `router/auto` behavior is preserved.
- **Consistent model compatibility, identity and authentication** (V18-01): provider defaults, model overrides, extension/virtual models and classifiers share compatibility inheritance, including image-input and opt-in-header behavior. Client identity and attribution now propagate through ordinary chat, image/classifier calls, extension stream/complete calls and the durable harness seam; `before_provider_headers` runs before provider-specific identity headers, while `null` header overrides still remove headers. Model changes discard the previous model's thinking blocks without clearing same-model thinking-level changes. Bare model ids offered by several providers prefer an unambiguous configured credential, preserve duplicate provider entries in model scopes, and report actionable ambiguity instead of silently picking catalog order.
- **Authentication origin boundaries** (V18-01): provider and future usage consumers share a process-local resolved-auth view with credential kind, effective origin and a salted credential generation; it does not serialize secrets or account ids. OAuth rotation and legitimate Copilot enterprise origins retain distinct identities. Conflicting Codex account ids fail closed, and a custom/proxy model URL cannot inherit an official subscription identity; configure an API key for that endpoint or restore the provider's official base URL.

## Fixed

- **Classifier image and compatibility paths** (V18-01): `models.classify()` carries image-capability metadata and identity through TypeSafe Jev, Cloudflare Clef and OpenRouter classifiers instead of treating those entries as chat models or dropping provider compatibility overrides. Unsupported input is rejected before dispatch.
- **Final tool arguments cannot execute a valid prefix of malformed input** (V18-01): Anthropic Messages, Bedrock Converse, Mistral Conversations, OpenAI Chat Completions and OpenAI Responses retain string repair for recoverable input, but malformed, truncated or non-object final arguments become `{}` plus an `argumentsError` containing the reason and original text. Tool validation fails rather than executing a partially parsed call.
- **Provider response and retry fixes** (V18-01): ChatGPT Business workspace/quota errors are not classified as transient HTTP retries; Copilot oversized requests enter context-overflow recovery; gateway/transport retry classification no longer treats digits in request ids or byte counts as an HTTP status. Anthropic strict tools fall back only for the designated schema-support errors, error tool-result images follow all tool results where required, whitespace-only output is treated as empty, Mistral applies its request timeout to response-header waits without cutting off active bodies, and Gemini/OpenAI-compatible thinking and content ordering cases are preserved.

## Internal
