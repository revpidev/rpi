# v0.1.7

## Breaking Changes

- **Azure provider renamed to `azure`** ([#9714](https://github.com/earendil-works/pi/pull/9714), V17-01): the provider id changed from `azure-openai-responses` to `azure`, since the provider now serves Azure Foundry Chat Completions deployments in addition to the Responses API. `auth.json` and `models.json` entries keyed on the old id no longer match, and existing sessions see the provider as gone on their next turn (the saved model no longer exists, so the session falls back to another available model with the usual "Could not restore model …" notice). Update the keys to `azure` or run `/login` again. The `azure-openai-responses` **api id** and the `AZURE_OPENAI_*` environment variables are unchanged. rpi reports the old keys explicitly — a diagnostic naming the file and key position (settings.json `defaultProvider` / `enabledModels` / `modelThinkingLevels`, models.json `providers`, auth.json credential keys) with this migration guidance — but never rewrites the files and never aliases the old id ([VARIANT]: upstream fails silently; ADR-0036 decision ④).

- **`--tools` keeps MCP tools** ([#10325](https://github.com/earendil-works/pi/issues/10325), V17-04): `--tools` no longer removes MCP tools unless one of its entries starts with `mcp__`, so `rpi --tools codemode` still reaches every MCP server from codemode scripts. MCP tools the list does not name are never declared to the model directly; only `tool_search` can load them. The exact rules: a non-empty `--tools` list without `mcp__` entries keeps the whole MCP tool set; once an entry starts with `mcp__` (including patterns such as `mcp__radius__*`), the list filters MCP tools too; an empty `--tools` list or `--no-tools` removes everything. `--exclude-tools` applies to MCP tools as before. Use `--exclude-tools 'mcp__*'` or the new `--no-mcp` to remove MCP tools. The list also accepts `*` patterns and `+name`/`-name` entries that adjust the default selection instead of replacing it.

- **Home/End belong to the editor; the transcript uses Ctrl+Home/Ctrl+End** ([#10314](https://github.com/earendil-works/pi/issues/10314), V17-05): in fullscreen mode `Home`/`End` now reach the focused component like in the regular TUI — they move the editor cursor to the line start/end instead of scrolling the transcript. The transcript top/bottom moved to `Ctrl+Home`/`Ctrl+End`. Custom keybindings are untouched; a configuration that explicitly pinned the old editor defaults (`["home","ctrl+home","ctrl+a"]` / `["end","ctrl+end","ctrl+e"]`) is migrated to the new defaults so `Ctrl+Home`/`Ctrl+End` do not double-bind.

- **`rpi-mcp-adapter` is removed** (ADR-0037, TE49): the deprecated first-party MCP adapter extension is retired, closing the explicit-install escape hatch documented for v0.1.6 — `rpi install rpi-mcp-adapter` now fails with a registry 404, and its update chain is gone. The supported replacement has been built in since v0.1.6: the `builtin:mcp` extension reads `~/.rpi/agent/mcp.json` and `<cwd>/.rpi/mcp.json` and serves `mcp__*` tools plus `/mcp`; the `mcp.json` layout is unchanged. Already-installed copies keep loading, but `rpi update` never touches them and the startup pipeline keeps recommending removal. Uninstall with `rpi remove rpi-mcp-adapter` (append `-l` for a project-scoped install); everything the adapter did that is still supported has a built-in equivalent.

## Changed

- **Program status via OSC 7501** ([#10607](https://github.com/earendil-works/pi/issues/10607), V17-05): terminals that answer the program status query see `working`, `blocked` (extension dialogs and logins), `done`, `error`, and `idle` reported for the interactive mode; the status clears while the terminal is stopped. `RPI_PROGRAM_STATUS=1|0` overrides the probe (ADR-0001 rename of `PI_PROGRAM_STATUS`); terminals without OSC 7501 support see no change.
- **`outputPad` applies to every transcript block** ([#10557](https://github.com/earendil-works/pi/issues/10557), [#9946](https://github.com/earendil-works/pi/issues/9946), V17-05): the setting now pads tool executions, `!` command output, and the branch/compaction/skill summaries as well as messages, and changing it repads the visible transcript in place instead of rebuilding it.
- **Context estimates reserve more room for new text** ([#10497](https://github.com/earendil-works/pi/issues/10497), V17-04): request context is estimated at 3.5 characters per token instead of 4 when calculating output limits, so large new inputs are not overestimated. Long-context pricing and compaction estimates are unaffected.
- **OpenAI Decisions classifier** (V17-04): `openai/gpt-6-luna` classifies through OpenAI's Decisions API with structured `choice`, `score`, and `bool` questions, optional images, usage/cost accounting, and a specific error when the gateway's 5-second limit rejects very large inputs. `models.classify()` in codemode accepts images for models whose catalog entry allows them; Sign in with ChatGPT credentials hide the classifier because the Decisions API only accepts API keys.
- **Login strings carry rpi's name** (V17-04): the Sign in with ChatGPT consent screen shows `rpi` as the agent name and the Codex browser login sends `originator=rpi`; the new SDK `LoginOptions.agentName` lets apps override both (upstream defaults to its own brand name).
- **Bash output strips escapes that arrive split across chunks** ([#10504](https://github.com/earendil-works/pi/issues/10504), V17-04): an ANSI/OSC sequence cut at a chunk boundary is held back until the next chunk completes it, so colors no longer leak into recorded `!` output. The Termux clipboard is read on Android/Termux (which reports platform `android`) and a failed Termux copy names the Termux:API packages ([#10391](https://github.com/earendil-works/pi/issues/10391)).
- **Project `mcp.json` can override global servers** ([#10277](https://github.com/earendil-works/pi/issues/10277), V17-03): an entry without `command`, `url`, or `type` in `<cwd>/.rpi/mcp.json` changes only `enabled`, `exposure`, and `toolExposure` of the global server with the same name, so a project can turn a global server off (or change its exposure) without copying its command or credentials. `/mcp` offers "Enable/Disable in this project" and writes a project override instead of the user's `mcp.json`; `rpi mcp list` shows the override file.
- **MCP OAuth can identify with a Client ID Metadata Document** ([#10302](https://github.com/earendil-works/pi/issues/10302), V17-03): `oauth.clientRegistration: "cimd"` skips dynamic client registration and identifies with rpi's Client ID Metadata Document for authorization servers that allow it for public clients. Without the `iss` parameter (RFC 9207), the document and callback path are specific to the MCP server.
- **The `/mcp` manager stays usable while servers connect** ([#10562](https://github.com/earendil-works/pi/issues/10562), V17-03): opening `/mcp` does not wait for the connection set, and enable/disable/reconnect run in the background, with the result shown in the server's entry.
- **Codemode `image()` saves its output** ([#10310](https://github.com/earendil-works/pi/issues/10310), V17-02): each image is also written to a user-only temp file and the result names the path right before the image, so later turns can copy or move generated images. Output files (the full text of truncated tool output, binary MCP resources, and codemode images) are now readable only by the user.
- **Codemode output items are separated** (V17-02): with several `text()` items each starts with a `==> text N/M <==` line, and `console.*` lines follow the other output in one `<console_output>` block instead of running into it.
- **Extension surfaces stay additive** (V17-06): `pi.registerToolRenderer()` lets an extension choose how calls to a tool are drawn — including tools that are not registered, such as a resumed session's MCP tool calls; tool render contexts gain `durationMs` (the recorded execution time of a final result) and `outputPad`; `tool_execution_end` extension events and tool-result messages carry `durationMs` (absent when the tool did not run); `agent_settled` carries `aborted` on the session, extension, and JSON/RPC faces, so integrations can tell a cancelled run from a finished one; and `prepareLoadout` hooks read a tool's `promptGuidelines` through `ToolLoadout.getPromptGuidelines()`. `rpiAbi` stays `1`, the event list is unchanged, and extensions that do not read the new fields are unaffected ([#10285](https://github.com/earendil-works/pi/issues/10285), [#10549](https://github.com/earendil-works/pi/issues/10549), [#10557](https://github.com/earendil-works/pi/issues/10557), [#10607](https://github.com/earendil-works/pi/issues/10607), [#10343](https://github.com/earendil-works/pi/issues/10343)).
- **llama.cpp decision models are classifiers** ([#10382](https://github.com/earendil-works/pi/issues/10382), V17-16): models llama.cpp reports as native decision models (`architecture.outputModalities` with `decisions`) are now registered as `typesafe-system-one` classifier entries whose base URL is the server's inference URL, so `models.classify()` reaches them through `/v1/systemone`; the refreshed catalog persists and restores them alongside the chat models. Chat lists are unchanged, and the label-probability fallback for chat models remains unavailable in rpi.

- **Durable tool chain and local environment** (V17-15, experimental): the durable crate now carries the upstream tool set (`read`/`write`/`edit`/`bash`, plus `powershell`), the full `ExecutionEnv` surface (result-shaped file system and shell with argv exec, output spill and retained windows, streaming UTF-8 decoders, line scanner, snapshot watcher) and the local `NodeExecutionEnv`, the tool task's bounded output buffer and throttled progress pump, and the ported execution-environment conformance suite. The crate stays out of the default CLI path (`crates/rpi` does not depend on `rpi-durable`; no command is registered and no host session code is touched), and its new runtime dependencies are `notify` (native file-change events) plus the already-vendored `sha2`/`unicode-normalization`. Experimental: the API changes without notice between releases.
- **Extension session commands work in the interactive TUI** (#70, V17-11): an extension command's `ctx.newSession()`, `ctx.fork()`, `ctx.switchSession()`, `ctx.reload()`, and `ctx.navigateTree()` are now queued to the interactive run loop and applied — previously they silently did nothing outside RPC mode. The fork path refills the editor with the forked branch's text, session replacement rebinds the UI and extension host, and tree navigation issues the same non-retry compaction-queue flush as `/tree`.
- **Declarative extension channels round-trip** (#70, V17-11): `ctx.ui.custom()` mounts the declarative tree with keyboard focus and resolves an interaction result — top-level children with a `done` prop are selectable (Up/Down + Enter resolves that value, Escape resolves `undefined`) — instead of displaying the tree and resolving immediately. `ctx.ui.setEditorComponent()` mounts the descriptor tree in the editor region until un-set (a declarative tree still cannot handle typing; use the interactive UI ABI for a live editor), `ctx.ui.addAutocompleteProvider()` accepts a declarative `{trigger, items}` source whose items complete after the trigger, and a `user_bash` handler can return declarative `operations.rules` (`allow`/`deny`/`rewrite`, `*`/`?` patterns) instead of a closure bundle — matching rules execute locally, rewrites run the replacement command, unmatched commands are denied, and a malformed policy still fails the command closed.
- **Loaded-resources diagnostics are split into four categories** (#71, V17-11): the panel now renders `[Skill conflicts]`, `[Prompt conflicts]`, `[Extension issues]`, and `[Theme conflicts]` (collisions grouped by name with winner/loser marks) instead of one merged `[Resource issues]` block, and the Skills/Prompts/Extensions sections expand into the upstream scope groups (project → user → path, with package sources listed under their source).
- **rpi-subagents rebased to pi-subagents v0.76.1** (TE48, ADR-0036): three release windows of upstream hardening land in the Rust port — child boundary instructions now follow Pi's base prompt so providers that recognize it by its opening sentence keep doing so (#2693), a child that times out or errors returns the text it was still streaming, labeled `Partial output before timeout:` / `Partial output before child error:` and marked `outputPartial` (#2653), built-in agent overrides are saved atomically and serialized across sessions through the shared settings lease (#2627/#2680), and multiline agent descriptions are written as a YAML literal block so every line survives rediscovery (#2681). The parity harness rotates to v0.76.1 (target) / v0.74.0 (regression), both MATCH.
- **rpi-ask-user-question and rpi-todo rebased to rpiv-mono v2.13.8** (TE48, ADR-0036 annex): the questionnaire opens inline in the editor slot with a 70%/12-row budget instead of an overlay (#253), RPC hosts can return a typed reply instead of an option and partial submits name the questions left blank with an `unanswered:` segment (#299/#142/#194/#291/#244), a multi-select answer keeps the checked options and the custom text together (#188), a saved note stays visible after its editor closes with its own edit affordance (#197), and `todo` snapshots changed through codemode are persisted as custom entries so they survive resume, reload, tree navigation and compaction (#290). The parity harness pin follows to v2.13.8 with a full MATCH.

## Fixed

- Fixed messages queued during compaction being flushed into an aborted run: the flush signal now carries the `compaction_end` event's `willRetry`, and a retry re-queues every message into the retry turn (extension commands through the extension path, steer/follow-up by mode) (#61, V17-11). Session-tree navigation also flushes the queue through the two explicit non-retry call sites.
- Fixed session-picker status messages never disappearing: the header status auto-hides after 2 seconds for info, 3 seconds for errors, and 4 seconds for load failures, and a new message cancels the previous timer (#71, V17-11).
- Fixed a theme hot reload leaving the transcript and footer in the previous palette: the history is rebuilt with the new theme (mid-stream, the streaming component and the current turn's tool components are preserved) and the footer repaints immediately (#71, V17-11).
- **Non-PNG images render on Kitty terminals** ([#10292](https://github.com/earendil-works/pi/issues/10292), V17-05): JPEG/GIF/WebP images are transcoded to PNG (with EXIF orientation) before the Kitty graphics protocol sees them, including images rendered by extensions through the `Image` component; without a transcoder they show the text fallback.
- **WezTerm keeps images while scrolling** ([#10319](https://github.com/earendil-works/pi/issues/10319), V17-05): a write to a row covered by a Kitty image redraws the placement after the text, so scrollbar and transcript updates no longer erase it.
- **Fullscreen selection does not survive transcript rebuilds** ([#9311](https://github.com/earendil-works/pi/issues/9311), [#10567](https://github.com/earendil-works/pi/issues/10567), V17-05): switching sessions clears the selection and multi-click state before re-rendering, so stale coordinates cannot highlight unrelated text.
- **Herdr is detected as OSC 8 capable** ([#10573](https://github.com/earendil-works/pi/issues/10573), V17-05): `TERM_PROGRAM=herdr` enables hyperlinks without enabling images, even when a leaked `KITTY_WINDOW_ID` suggests otherwise.
- Fixed the `!!` command header losing its dim color after the first update ([#10557](https://github.com/earendil-works/pi/issues/10557), V17-05), and reloaded bash results restoring their recorded `Took` duration ([#10549](https://github.com/earendil-works/pi/issues/10549), V17-05).
- **MCP OAuth dynamic registration sends an `application_type`** ([#10493](https://github.com/earendil-works/pi/issues/10493), V17-03): native for loopback redirect URIs and custom schemes, web otherwise (derived from `redirect_uris` unless set). OpenID Connect authorization servers no longer reject the loopback redirect with `invalid_redirect_uri`.
- **Closing an MCP server waits for a connect still in progress** ([#10249](https://github.com/earendil-works/pi/issues/10249), V17-03): shutdown aborts the in-flight connect (including the wait between HTTP retries), closes its client, and returns once the attempt settled.
- **MCP sign-ins can be cancelled and cannot hang shutdown** ([#10565](https://github.com/earendil-works/pi/issues/10565), V17-03): Esc cancels the sign-in, a session shutdown aborts a running sign-in and waits for its cleanup, requests to the authorization server time out after 15 seconds, an aborted refresh never falls back to a new authorization, and closing a streamable HTTP session reuses the last request's token instead of triggering a refresh. `rpi mcp login --timeout` now limits the whole sign-in, not only the redirect prompt. Credentials written by earlier versions without the stored authorization-server discovery state should sign in again: a refresh for them re-discovers the authorization server from the MCP server before sending the stored tokens ([GHSA-6qxp-vccf-f47h](https://github.com/advisories/GHSA-6qxp-vccf-f47h); the issuer binding itself is tracked for v0.1.8).
- **Codemode survives scripts that patch built-ins** ([#10444](https://github.com/earendil-works/pi/issues/10444), V17-02): built-ins are frozen and built-in globals made read-only before the script runs, so patches such as `Array.prototype.toJSON = ...` have no effect, while instances can still override `constructor`, `name`, `message`, `toString`, `toLocaleString`, `valueOf`, `toJSON`, and `Object.prototype` members.
- **Codemode scripts cannot exhaust host memory with output** ([#10283](https://github.com/earendil-works/pi/issues/10283), V17-02): `text()`, `image()`, and `console.*` fail the script with a `RangeError` past 16M characters or 100000 items.
- **Codemode `tools.read()` resolves image files to image blocks** ([#10251](https://github.com/earendil-works/pi/issues/10251), V17-02), so scripts can show them with `image(block)`.
- **Codemode lookup helpers are documented as async** ([#10555](https://github.com/earendil-works/pi/issues/10555), V17-02): `searchTools()`, `describeTool()`, and `describeNamespace()` are shown as `await …`, so models no longer serialize an unawaited promise as `{}`.
- **Hidden tools stay out of the system prompt rules and the skills hint** ([#10343](https://github.com/earendil-works/pi/issues/10343), V17-02): tools hidden by `prepareLoadout` are left out of the tool list and rules, the skills hint names no tool when the file reader is hidden, and `codemode` shows each tool's prompt guidelines with its declaration.
- Fixed provider errors such as "Selected model is at capacity", `server_busy`, and "servers are currently busy" ending the turn instead of being retried ([#10278](https://github.com/earendil-works/pi/issues/10278), [#10543](https://github.com/earendil-works/pi/issues/10543), V17-04), and retried HTTP/2 "pending stream has been canceled" failures that arrive after a stalled connection ([#10379](https://github.com/earendil-works/pi/issues/10379)).
- Fixed Mistral reporting a transient failure as `finish_reason: "error"` without a retryable message ([#10487](https://github.com/earendil-works/pi/issues/10487), V17-04).
- Fixed Sign in with ChatGPT falling back to a paste prompt when the callback port is held by another login: the browser callback would reach the other listener and be rejected with a state mismatch, so login now fails before opening the browser with a clear error ([#10265](https://github.com/earendil-works/pi/issues/10265), V17-04). The Anthropic browser login instead falls back to a free loopback port ([#10571](https://github.com/earendil-works/pi/issues/10571)).
- Fixed a cancelled or superseded OAuth refresh discarding the rotated credential: the refresh now completes and persists once started, bounded by its timeout ([`bde882c74`](https://github.com/earendil-works/pi/commit/bde882c74), V17-04).
- Fixed Bedrock Claude replays failing after the system prompt or tools changed: Opus 4.7+, Sonnet 5+, and Fable 5 send `thinking.block_binding` with the `drop_block` behavior and its beta ([#10324](https://github.com/earendil-works/pi/issues/10324), V17-04), and the configured thinking level now reaches OpenAI models on Bedrock as `reasoning.effort`/`reasoning_effort` ([#9331](https://github.com/earendil-works/pi/issues/9331), [#10142](https://github.com/earendil-works/pi/issues/10142)). Bedrock OpenAI models keep their models.dev pricing tiers, so long-context requests bill the long-context rate ([#10326](https://github.com/earendil-works/pi/issues/10326)).
- Fixed Cloudflare AI Gateway Claude model ids using dotted versions the `/anthropic` passthrough rejects; the catalog now ships dashed ids ([`c10bfb0d7`](https://github.com/earendil-works/pi/commit/c10bfb0d7), V17-04).
- Fixed Radius listing models an organization owner disabled: the gateway catalog replaces the shipped baseline once known ([`43d376399`](https://github.com/earendil-works/pi/commit/43d376399), V17-04).
- Fixed the Codex provider forcing its own `originator` and `User-Agent` over caller headers ([#10429](https://github.com/earendil-works/pi/issues/10429), V17-04).
- Fixed a trailing comma in `--models` adding an empty pattern that matched every model by substring and added an extra model to the model cycle ([#10334](https://github.com/earendil-works/pi/issues/10334), V17-04).
