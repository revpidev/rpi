## Breaking Changes

- **Azure provider renamed to `azure`** ([#9714](https://github.com/earendil-works/pi/pull/9714), V17-01): the provider id changed from `azure-openai-responses` to `azure`, since the provider now serves Azure Foundry Chat Completions deployments in addition to the Responses API. `auth.json` and `models.json` entries keyed on the old id no longer match, and existing sessions see the provider as gone on their next turn (the saved model no longer exists, so the session falls back to another available model with the usual "Could not restore model …" notice). Update the keys to `azure` or run `/login` again. The `azure-openai-responses` **api id** and the `AZURE_OPENAI_*` environment variables are unchanged. rpi reports the old keys explicitly — a diagnostic naming the file and key position (settings.json `defaultProvider` / `enabledModels` / `modelThinkingLevels`, models.json `providers`, auth.json credential keys) with this migration guidance — but never rewrites the files and never aliases the old id ([VARIANT]: upstream fails silently; ADR-0036 decision ④).

## Changed

- **Project `mcp.json` can override global servers** ([#10277](https://github.com/earendil-works/pi/issues/10277), V17-03): an entry without `command`, `url`, or `type` in `<cwd>/.rpi/mcp.json` changes only `enabled`, `exposure`, and `toolExposure` of the global server with the same name, so a project can turn a global server off (or change its exposure) without copying its command or credentials. `/mcp` offers "Enable/Disable in this project" and writes a project override instead of the user's `mcp.json`; `rpi mcp list` shows the override file.
- **MCP OAuth can identify with a Client ID Metadata Document** ([#10302](https://github.com/earendil-works/pi/issues/10302), V17-03): `oauth.clientRegistration: "cimd"` skips dynamic client registration and identifies with rpi's Client ID Metadata Document for authorization servers that allow it for public clients. Without the `iss` parameter (RFC 9207), the document and callback path are specific to the MCP server.
- **The `/mcp` manager stays usable while servers connect** ([#10562](https://github.com/earendil-works/pi/issues/10562), V17-03): opening `/mcp` does not wait for the connection set, and enable/disable/reconnect run in the background, with the result shown in the server's entry.
- **Codemode `image()` saves its output** ([#10310](https://github.com/earendil-works/pi/issues/10310), V17-02): each image is also written to a user-only temp file and the result names the path right before the image, so later turns can copy or move generated images. Output files (the full text of truncated tool output, binary MCP resources, and codemode images) are now readable only by the user.
- **Codemode output items are separated** (V17-02): with several `text()` items each starts with a `==> text N/M <==` line, and `console.*` lines follow the other output in one `<console_output>` block instead of running into it.

## Fixed

- **MCP OAuth dynamic registration sends an `application_type`** ([#10493](https://github.com/earendil-works/pi/issues/10493), V17-03): native for loopback redirect URIs and custom schemes, web otherwise (derived from `redirect_uris` unless set). OpenID Connect authorization servers no longer reject the loopback redirect with `invalid_redirect_uri`.
- **Closing an MCP server waits for a connect still in progress** ([#10249](https://github.com/earendil-works/pi/issues/10249), V17-03): shutdown aborts the in-flight connect (including the wait between HTTP retries), closes its client, and returns once the attempt settled.
- **MCP sign-ins can be cancelled and cannot hang shutdown** ([#10565](https://github.com/earendil-works/pi/issues/10565), V17-03): Esc cancels the sign-in, a session shutdown aborts a running sign-in and waits for its cleanup, requests to the authorization server time out after 15 seconds, an aborted refresh never falls back to a new authorization, and closing a streamable HTTP session reuses the last request's token instead of triggering a refresh. `rpi mcp login --timeout` now limits the whole sign-in, not only the redirect prompt. Credentials written by earlier versions without the stored authorization-server discovery state should sign in again: a refresh for them re-discovers the authorization server from the MCP server before sending the stored tokens ([GHSA-6qxp-vccf-f47h](https://github.com/advisories/GHSA-6qxp-vccf-f47h); the issuer binding itself is tracked for v0.1.8).
- **Codemode survives scripts that patch built-ins** ([#10444](https://github.com/earendil-works/pi/issues/10444), V17-02): built-ins are frozen and built-in globals made read-only before the script runs, so patches such as `Array.prototype.toJSON = ...` have no effect, while instances can still override `constructor`, `name`, `message`, `toString`, `toLocaleString`, `valueOf`, `toJSON`, and `Object.prototype` members.
- **Codemode scripts cannot exhaust host memory with output** ([#10283](https://github.com/earendil-works/pi/issues/10283), V17-02): `text()`, `image()`, and `console.*` fail the script with a `RangeError` past 16M characters or 100000 items.
- **Codemode `tools.read()` resolves image files to image blocks** ([#10251](https://github.com/earendil-works/pi/issues/10251), V17-02), so scripts can show them with `image(block)`.
- **Codemode lookup helpers are documented as async** ([#10555](https://github.com/earendil-works/pi/issues/10555), V17-02): `searchTools()`, `describeTool()`, and `describeNamespace()` are shown as `await …`, so models no longer serialize an unawaited promise as `{}`.
- **Hidden tools stay out of the system prompt rules and the skills hint** ([#10343](https://github.com/earendil-works/pi/issues/10343), V17-02): tools hidden by `prepareLoadout` are left out of the tool list and rules, the skills hint names no tool when the file reader is hidden, and `codemode` shows each tool's prompt guidelines with its declaration.
