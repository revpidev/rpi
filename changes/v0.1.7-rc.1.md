# v0.1.7-rc.1 (2026-10-17)

**Pre-release (pre-release channel)**: candidate for the `0.1.7` stable release, published ahead of it for verification. Content matches `changes/v0.1.7.md` (the upstream-parity v1.1.0 main line, the issue line #57–#71, the rpi-mcp-adapter removal, and the durable stack); at stable-release time this file's entries fold into `v0.1.7.md`. Install: existing rpi users run `rpi update --rc` (or `rpi update --all --rc` to also update the seven lockstep extensions to `0.1.7-rc.1`); install.sh does not serve RCs (`releases/latest` stays stable). The retired `rpi-mcp-adapter` is not part of the lockstep set (no `0.1.7-rc.1` artifacts and no update chain); its registry entry is deleted after this RC ships and before the stable release, so `rpi install rpi-mcp-adapter` starts failing with a 404 at that point — the announcement lands first, by design. Already-installed copies keep loading, and `rpi update` recommends removal.

## Breaking changes in this RC

- **Azure provider renamed to `azure`**: the provider id changed from `azure-openai-responses` (the provider now serves Azure Foundry Chat Completions deployments in addition to the Responses API). rpi reports the old keys with a migration diagnostic naming the file and key position — it never rewrites or aliases them — and an old session falls back to another model with the usual restore notice. The `azure-openai-responses` api id and the `AZURE_OPENAI_*` environment variables are unchanged. Update the keys or run `/login` again.
- **`--tools` keeps MCP tools** ([#10325](https://github.com/earendil-works/pi/issues/10325)): a list without `mcp__` entries keeps the whole MCP tool set (`rpi --tools codemode` still reaches every MCP server from codemode scripts); once an entry starts with `mcp__`, the list filters MCP tools; an empty list or `--no-tools` removes everything. Use `--exclude-tools 'mcp__*'` or `--no-mcp` to drop MCP tools. `*` patterns and `+name`/`-name` entries adjust the default selection.
- **Home/End belong to the editor; the transcript uses Ctrl+Home/Ctrl+End** ([#10314](https://github.com/earendil-works/pi/issues/10314)): in fullscreen mode `Home`/`End` move the editor cursor to the line start/end; the transcript top/bottom moved to `Ctrl+Home`/`Ctrl+End`. A configuration that explicitly pinned the old editor defaults is migrated so the new bindings do not double-bind.
- **`rpi-mcp-adapter` is removed** (ADR-0037): it is no longer packaged or updated, and the registry entry is deleted after this RC ships but before the stable release (from then on, `rpi install rpi-mcp-adapter` fails with a 404). Already-installed copies keep loading, the startup pipeline keeps recommending removal, and everything still supported has a built-in equivalent (`builtin:mcp` reads the unchanged `mcp.json` layout).

## Verification requests (the point of the RC)

- Self-update on all six targets (`rpi update --rc`: download + sha256 verification + atomic replacement; Windows gets manual-replacement instructions).
- `rpi update --extensions --rc`: the seven lockstep extensions going to `0.1.7-rc.1`; an existing `rpi-mcp-adapter` install must still load while `rpi update` recommends `rpi remove rpi-mcp-adapter` (its registry entry is deleted after this RC, so the install-404 path is verified post-RC).
- The four BREAKING surfaces above: the Azure migration diagnostic (old `azure-openai-responses` keys in settings/models/auth; the new `azure` id must work and the api id must stay `azure-openai-responses`), the `--tools` MCP three-state behavior, the Home/End remap (custom keybindings untouched), and the mcp-adapter 404 + uninstall path.
- The durable stack: `cargo test -p rpi-durable` conformance (Memory/JSONL/SQLite) and the persist/resume anchors; the default CLI path must be unchanged (`crates/rpi` does not depend on `rpi-durable`).

Known boundary: the RC endpoint (`https://revpi.dev/api/latest-rc-version.json`) goes live once the Release assets are in place; self-hosted mirrors must provide the file in the same directory. The registry entry for `rpi-mcp-adapter` is deleted after this RC ships but before the stable release (the announcement lands first, by design).
