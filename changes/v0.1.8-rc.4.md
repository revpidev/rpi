# v0.1.8-rc.4 (2026-11-08)

**Pre-release (pre-release channel)**: the fourth candidate for the `0.1.8` stable release. It carries the V18-13 delivery fixes found by the independent review: installer transactionality, PowerShell semver/network/prompt parity, strict profile-index parsing, a real Alpine runtime gate, and release-notes/index hardening. The rc.1-rc.3 feature set is unchanged; at stable-release time this file's entries fold into `changes/v0.1.8.md`.

Install: existing rpi users run `rpi update --rc` (or `rpi update --all --rc`); `install.sh`/`install.ps1` do not serve RCs. This RC does not move the stable endpoint, registry or schema files.

## Fixed in this RC

- **PowerShell semver validation** (`install.ps1`): both sides of `minHostVersion` are now fully parsed and validated before any ordering decision. A numeric prerelease identifier with a leading zero (`0.1.0-01`), an empty prerelease/build identifier, an invalid character, or a 20-digit core component is `invalid` instead of being treated as lower/higher. Core and prerelease numeric components compare by length/ordinal order, so they no longer overflow `int64`. The value must cover the whole string (`\z` plus an explicit length check), so a trailing LF can no longer compare `eq`. Regression matrix covers invalid values on both sides against stable and prerelease peers, including trailing LF/CR/TAB/space.
- **Transactional binary/manifest replacement** (`install.sh`, `install.ps1`): the two renames are one commit. The old pair is backed up in the destination directory; if the manifest rename fails, the old binary is restored (first install removes the new binary). A failed restore keeps the backups and prints their paths. Non-file destinations are rejected before the binary is staged, and every failure path removes the staging binary/manifest instead of leaving `.rpi.stage-<pid>` residue. Tests cover upgrade rollback, first-install rollback, success, no stage/backup residue, and a directory occupying the manifest path.
- **Profile index digest/sidecar consistency** (`rpi-pages/scripts/generate-site.py`): `--publish-profiles` always reads every `.sha256` sidecar, even when the Release API returns a valid `digest`, and requires the two values to be equal. A stale, malformed or unreadable sidecar now fails before any index is written. Tests cover digest+sidecar agreement, mismatch, unreadable/malformed sidecars, and the unchanged digest fast path for extension indexes.
- **206 resume validators** (`install.sh`, `install.ps1`): a `206` is appended only when the current response carries a validator and it equals the validator the partial was requested with. A missing or changed validator discards the partial and restarts from zero. PowerShell decides before opening the append stream and no longer persists a mixed partial's validators after a broken transfer. Tests cover `206` without a validator and the clean `200` retry.
- **PowerShell settings seeding** (`install.ps1`): a directory/permission/lock failure while seeding `settings.json` is a warning and returns `false`; the successful binary + plugin install still exits 0. The cleanup in `finally` is itself non-throwing (`Test-Path -ErrorAction SilentlyContinue` under `$ErrorActionPreference='Stop'`), so an inaccessible agent directory cannot turn the warning into a fatal error. The summary distinguishes seeded/existing/failed, so a fresh install that failed to seed no longer claims "existing settings were not rewritten". Tests cover a non-file agent path, a denied stage parent, and the failed-seed summary.
- **PowerShell download parity** (`install.ps1`): `HttpWebRequest.Timeout` again bounds DNS/connect/response headers (default 10s, `RPI_INSTALL_CONNECT_TIMEOUT`); the body uses the stall timeout with no total timeout. `429`/`503` carry `Retry-After` (delta-seconds or HTTP-date, capped at 60s), backoff has ±20% jitter, and `RPI_INSTALL_ATTEMPTS`/`RPI_INSTALL_STALL_TIMEOUT`/`RPI_INSTALL_CONNECT_TIMEOUT` are wired and validated. An explicitly detected truncation (early EOF without an exception) resumes with the same 1/2/4/8s jittered backoff instead of a fixed 1s pause. Shell ordinary retries and the invalid-`Retry-After` fallback now use a portable awk-based ±20% jitter (dash/busybox, no `$RANDOM`), while a valid `Retry-After` is honored exactly. End-to-end tests cover a slow-header connect timeout, `429` + `Retry-After` measured between server-side request timestamps, a truncated download, ordinary 5xx retry jitter, and the invalid-`Retry-After` fallback.
- **Strict profile-index parsing** (`install.sh`, `install.ps1`): a dependency-free JSON parser validates the flat schema and detects duplicate keys at every object level. The shell parser replaces line-counting `grep`/`sed`; the PowerShell parser replaces `ConvertFrom-Json` coercion. `schemaVersion` must be the JSON number `1` (not `"1"`), `version` must match exactly, `assets` must be a flat `name -> 64-hex` map containing the target, optional `sizes` must be a flat non-negative integer map over known assets, and arrays/nested objects/trailing data/unknown keys are rejected. JSON escapes are case-sensitive in both parsers: `\u` is the only accepted form, so `\U0061` and friends are a parse error rather than a decoded key. Metadata reads are bounded by bytes (256 KiB), not characters, and are checked before/while reading.
- **PowerShell prompt timeout** (`install.ps1`): profile and PATH prompts now honor `RPI_INSTALL_PROMPT_TIMEOUT` (default 60s) through a console key poller. A timeout is `__timeout__`, never an empty consent; the profile timeout selects the default profile but refuses native-plugin consent, and PATH times out without modifying the user PATH. A host that cannot poll the console (ISE/remoting) returns `__unavailable__` instead of degrading to an unbounded `Read-Host`, and a `$null`/unavailable PATH answer is treated as "no", never as the default Yes.
- **PowerShell cache GC** (`install.ps1`, `install.sh`): parts older than seven days are removed unless a `.lock` sibling marks an active transfer; `-NoCache` skips GC. An auxiliary `<asset>.meta` probes the lock of its base asset, so an in-flight resume no longer loses its validators. Tests cover a locked part, a locked meta, and an unlocked old part+meta.
- **Installer summary text**: `registered in settings.json` is no longer printed when existing settings were merely left untouched; the summary reports seeded settings, existing settings, or the extension directory the plugins were installed in.
- **Alpine runtime gate** (`.github/workflows/build.yml`, `scripts/alpine-gate.sh`): Alpine 3.21 x86_64 builds the dynamic binary, static fallback and all seven native plugins, then asserts dynamic + 7 plugins `get_commands`, missing `libgcc` dynamic failure, static fallback startup without libs, missing `libstdc++` smart-fetch failure, existing-native-plugin static refusal, and `--static-fallback` ignored while dynamic is usable. aarch64 builds under QEMU and asserts dynamic/static linkage; its full runtime remains the explicit R3.11.16 untested boundary.
- **Test coverage**: `scripts/test-install-ps1-main.ps1` runs the full PowerShell installer against a fake local Release (mini/standard/full, plugin materialization, settings seeding, existing settings, failed seeding, corrupt archive, non-file install target, 206, 429, slow headers, prompt timeout). `429` Retry-After is measured between the fake server's monotonic request timestamps instead of the whole child-process runtime, so a slow start can no longer mask a missing wait. `scripts/test-install-ps1.ps1` adds uppercase-JSON-escape, semver trailing-byte, GC meta-lock, failed-seed, and prompt-sentinel cases. `scripts/test-install-sh.sh` adds strict-index, transaction, 206, GC meta-lock and backoff-jitter cases (unit bounds plus end-to-end 5xx/429-invalid retry logs); `scripts/test_generate_site.py` adds digest/sidecar cases.
- **P3 cleanup**: removed the trailing whitespace in `scripts/test-install-sh.sh`, added the missing `Cross.toml` final newline, and corrected the V18-13 status drift in `RELEASING.md` and the rpi-docs plan/README.

## Breaking changes

- **musl main artifacts are dynamically linked from this release line.** They need `libgcc`; `standard`/`full` additionally need `libstdc++` for `rpi-smart-fetch`. On Alpine: `apk add libgcc libstdc++`.
- **Old static musl installations must install the runtime libraries before `rpi update --self`.** The old static binary downloads the new dynamic asset and cannot preflight the libraries; on a base Alpine system the updated binary will fail to start. Either install `libgcc libstdc++` first, or reinstall through `install.sh`/`install.ps1`, which detects the missing runtime and offers the binary-only `-static` fallback with explicit consent. Static fallback cannot load native plugins, and an existing native plugin blocks the switch.
- **Profile installation is fail-closed.** `standard`/`full` require the `rpi-pages` profile index; a missing/invalid index exits 1 with a `--profile mini` hint. It never auto-falls back to mini and never trusts only the Release sidecar.
