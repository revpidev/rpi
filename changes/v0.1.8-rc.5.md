# v0.1.8-rc.5 (2026-11-11)

**Pre-release (pre-release channel)**: the fifth candidate for the `0.1.8` stable release. It carries the late terminal-color reply fix found after rc.4, versioned statusline default migrations for existing installations, and startup extension update notices. The rc.1-rc.4 feature set is otherwise unchanged; at stable-release time this file's entries fold into `changes/v0.1.8.md`.

Install: existing rpi users run `rpi update --rc` (or `rpi update --all --rc`); `install.sh`/`install.ps1` do not serve RCs. This RC does not move the stable endpoint, registry or schema files.

## Fixed in this RC

- **Terminal color queries retain delayed replies** (rpi#77, ADR-0045): an early DA1 followed by grace-deadline expiry no longer discards the late-reply subscription. A delayed OSC 11 now completes the late delivery immediately and re-applies the generated system theme instead of leaving every panel transparent for the session. The pending entry remains only to finish late delivery and is reaped by a later DA1 or complete color report, without leaking terminal replies into keyboard input or invoking the callback twice. Regressions: `terminal_colors_query_early_da1_timeout_still_delivers_late_colors` and `terminal_colors_query_late_background_then_da1_reaps_without_duplicate_callback`.
- **Statusline defaults migrate once on global extension updates** (rpi#2, ADR-0046): extension manifests may declare per-key integer `defaultSettingsMigration` versions alongside `defaultSettings`. After a successful global update, a missing default is seeded only when its migration version increases; legacy manifests and affected rc.4 installs count as version zero. Later updates at the same version do not re-enable a key the user deleted, existing values (including explicit `null`) are preserved, and project-local updates never write global settings. `rpi-statusline` declares `statusLine` migration version 1, so fresh installs and old-RC upgrades show the default live session-total and output-rate rows without a manual `/statusline` save. Regressions: `test_update_migrates_manifest_default_settings_only_once`, `test_update_migration_preserves_existing_values_and_project_scope`, and the manifest consistency check.
- **Startup extension update notices follow the host channel**: interactive startup asynchronously checks npm, git, registry and `github:` packages, including discovered registry/GitHub installs without a settings entry. Stable hosts compare registry versions against the latest stable release and RC hosts against the latest RC; only strictly newer compatible versions produce a package-update banner, and the RC action is `rpi update --extensions --rc`. Registry/GitHub sources were previously skipped and the interactive package-update notification was not connected. Regressions: `test_check_for_available_updates_registry_uses_running_channel`, `test_check_for_available_updates_github_release`, `package_update_notifications_use_channel_specific_commands`, and `startup_package_check_queues_updates_for_the_running_channel`.

## Packaging and verification

- The V18-13 target manifest remains **20 archives + 20 `.sha256` + 42 `.rpix` + 42 `.rpix.sha256` = 124 files**. After all assets and sidecars are uploaded, run `python3 rpi-pages/scripts/generate-site.py --publish-profiles 0.1.8-rc.5` before refreshing the RC endpoint; the stable endpoint stays unchanged.
- Terminal: verify the `system` theme after a fullscreen Ctrl+C exit with an early DA1 and delayed OSC 11, including over SSH; panel backgrounds must recover when the late reply arrives, and a later DA1 must not appear as keyboard input.
- Statusline: upgrade both a legacy installation and an affected rc.4 installation, confirm the default live rows appear without overwriting existing settings, then delete `statusLine` and update again at the same migration version to confirm it stays deleted.
- Startup notices: confirm stable hosts show only stable extension updates and `rpi update --extensions`, while RC hosts show RC updates and `rpi update --extensions --rc`; include registry/GitHub extensions that have no settings entry.
