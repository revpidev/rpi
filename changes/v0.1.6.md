# v0.1.6 (unreleased)

This file collects the v0.1.6 window's user-visible changes ahead of the
release closeout (TE47). Task-level details and evidence live in
`rpi-docs/plan/v0.1.6/`.

## Breaking changes

### Session format and canonical context (V16-03)

- **Canonical session context**: `SessionManager` is now the single
  authority for provider context. The context is rebuilt from the session
  projection before every provider request, so assigning the agent's
  `state.messages` directly no longer affects what the model sees; sessions
  recover context through the session append APIs plus `refreshContext()`
  (upstream agent-session.ts @ v0.99.2). Old session files without
  `context_edit` entries replay unchanged.
- **New session entry: `context_edit`** (append-only, additive): omits
  (`replacement: null`) or replaces the content of an earlier
  user/assistant/tool-result/custom message for model context only. Raw
  history, usage accounting, and UI history are untouched. A new
  `append_context_edit` API and the retain-none compaction form
  (`append_compaction(summary, null, tokensBefore)`) accompany it.
- **Agent boundary semantics** (internal extension-facing): the
  `shouldStopAfterTurn` hook is replaced by `finishTurn`, which returns an
  explicit `{action: "continue" | "end"}` decision; error/aborted turns
  still invoke it but ignore the decision. `turn_end` and the new
  `agent_before_settle` boundary events are dispatched through a chained
  `{entries, continue, context}` pipeline, may persist structural drafts
  (custom entries/messages, context edits, compactions), and can force one
  more provider request.

### Extension event surface (additive, ABI minor bump lands with V16-06)

- Two new events: `context_with_system` (runs after `context` handlers on
  the restored full transcript, output sent verbatim) and
  `agent_before_settle` (before final settlement).
- `context` handlers no longer see system messages; the prompt and tool
  declarations are restored by the host after each handler (#9789/#9822).
- `turn_end` payloads gain the boundary fields (`entries`, `continue`,
  `context`, `outcome`, `messageEntryId`, `toolResultEntryIds`);
  `ExtensionRunner.emit()` no longer accepts `turn_end` /
  `agent_before_settle` (they are dispatched through `emitBoundary`).

### Session payload increments

- Assistant messages record the requested pi thinking level
  (`thinkingLevel`, R2.7.1).
- Tool-result messages can carry a bounded `nestedCalls` snapshot
  (session record only; never sent to the model). The writer lands with
  V16-06.
