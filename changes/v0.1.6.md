# v0.1.6 (unreleased)

This file collects the v0.1.6 window's user-visible changes ahead of the
release closeout (TE47). Task-level details and evidence live in
`rpi-docs/plan/v0.1.6/`.

## Breaking changes

### Session format and canonical context (V16-03)

- **Canonical session context**: `SessionManager` is now the single
  authority for provider context. The context is rebuilt from the session
  projection before every provider request, so assigning the agent's
  `state.messages` directly no longer affects what the model sees; sessions
  recover context through the session append APIs plus `refreshContext()`
  (upstream agent-session.ts @ v1.0.0). Old session files without
  `context_edit` entries replay unchanged.
- **New session entry: `context_edit`** (append-only, additive): omits
  (`replacement: null`) or replaces the content of an earlier
  user/assistant/tool-result/custom message for model context only. Raw
  history, usage accounting, and UI history are untouched. A new
  `append_context_edit` API and the retain-none compaction form
  (`append_compaction(summary, null, tokensBefore)`) accompany it.
- **Agent boundary semantics** (internal extension-facing): the
  `shouldStopAfterTurn` hook is replaced by `finishTurn`, which returns an
  explicit `{action: "continue" | "end"}` decision; error/aborted turns
  still invoke it but ignore the decision. `turn_end` and the new
  `agent_before_settle` boundary events are dispatched through a chained
  `{entries, continue, context}` pipeline, may persist structural drafts
  (custom entries/messages, context edits, compactions), and can force one
  more provider request.

### Extension event surface (additive, ABI minor bump lands with V16-06)

- Two new events: `context_with_system` (runs after `context` handlers on
  the restored full transcript, output sent verbatim) and
  `agent_before_settle` (before final settlement).
- `context` handlers no longer see system messages; the prompt and tool
  declarations are restored by the host after each handler (#9789/#9822).
- `turn_end` payloads gain the boundary fields (`entries`, `continue`,
  `context`, `outcome`, `messageEntryId`, `toolResultEntryIds`);
  `ExtensionRunner.emit()` no longer accepts `turn_end` /
  `agent_before_settle` (they are dispatched through `emitBoundary`).

### Session payload increments

- Assistant messages record the requested pi thinking level
  (`thinkingLevel`, R2.7.1).
- Tool-result messages can carry a bounded `nestedCalls` snapshot
  (session record only; never sent to the model). The writer lands with
  V16-06.

### Plugin rename: two first-party extensions move to the `rpi-` prefix (TE42, ADR-0033)

- **Two first-party extensions were renamed to `rpi-ask-user-question` and
  `rpi-todo`.** This is a clean switch: no install alias, no automatic
  migration of installed directories, no index redirect. The former names
  and install paths are retired: if you have an older install, remove it
  (`rpi remove <installed-name>`) and reinstall the current extension —
  there is nothing to migrate.
- **All published artifacts carry the new prefix**: every historical
  release asset was renamed in place (all `rc` and stable releases), and
  the registry version matrix serves `rpi-`-named `.rpix` files only.
- **Internal identifiers were normalized the same way**:
  - event channels `rpi:ask-user:prompt` / `rpi:ask-user:blocked`
    (event subscribers must update their channel names);
  - the todo overlay widget key `rpi-todos`;
  - the XDG config paths `~/.config/rpi-ask-user-question/` and
    `~/.config/rpi-todo/` — clean switch: no legacy directory is read
    (move the files to keep custom settings).
- Naming norm (ADR-0033): official extensions use the `rpi-` prefix +
  kebab-case; the prefix is reserved, and the site index rejects third-party
  entries that claim it.
## Tool orchestration (V16-06, additive)

- **Tool exposure and loadout** (extension API, additive): tool definitions
  can declare `exposure` (`direct` default / `model-only` / `codemode` /
  `deferred` / `hidden`; `codemode-deferred` is an alias for `codemode`),
  `namespace`, MCP-style `annotations`, `outputSchema`, `defaultActive`,
  and a `prepareLoadout(loadout)` hook that replaces declared descriptions
  and hides declarations from requests while the tools stay callable.
  `hidden` tools are unreachable even when named; `model-only` tools are
  declared but reject invocation; `codemode`/`deferred` tools are callable
  from other tools without being declared.
- **Nested tool calls**: tools can run other tools through
  `ctx.executeTool(name, args)` (`ctx.execute_tool` for native
  extensions). Nested calls go through the full validation, hook, and
  permission pipeline with ids `<parent>/<n>`; `tool_call`, `tool_result`,
  and `tool_execution_*` events carry `parentToolCallId`. The calling
  tool's result message records a bounded `nestedCalls` snapshot
  (name/arguments/status/duration/error; never the results; arguments
  omitted and byte-counted over 8 KiB per call or 32 KiB total; errors
  truncated at 500 chars; at most 256 calls), and nested usage is folded
  into the message usage. Nested calls never enter the transcript.
- **Structured tool results**: results may carry `structuredContent`
  matching a declared `outputSchema`, and may report failure with
  `isError: true` while keeping `content`/`details`. A `tool_result`
  handler that replaces `content` without restating `structuredContent`
  drops it.
- **Two new events**: `provider_stream_event` (per parsed provider stream
  event, in stream order, notification only — never persisted) and
  `mcp_servers_change` (registered MCP server set changes; the registry
  list wiring follows with the built-in MCP extension). The extension
  event table grows 39 → 41.
- **Session-scoped tool exposure overrides** (extension API, additive,
  V16-14): `setToolExposures({"<toolName>": "<exposure>"})` applies a
  session-scoped exposure override (unknown names ignored; the whole map
  is validated before anything is applied) and returns the applied names;
  `clearToolExposures([names])` drops the overrides so the tools return to
  their registered exposure. Overrides survive registry rebuilds, are read
  back through `getAllTools()`, and are the exposure-setting surface
  rpi-plan-mode consumes for its read-only boundary.
- **ABI**: all of the above is additive; `rpiAbi` stays `1`. The
  `extension-abi.md` method table and change history record the host calls
  (`executeTool`, `setToolExposures`/`clearToolExposures`), definition
  fields, event names, and the additive v1.0.0 surfaces
  (`ctx.modelRegistry.generateImages()`,
  `McpOAuthConfig.authServerMetadataUrl`).

## Built-in MCP extension (V16-08)

- **`mcp.json` servers**: the built-in `mcp` extension reads
  `~/.rpi/agent/mcp.json` and, for trusted projects, `.rpi/mcp.json`
  (streamable HTTP and stdio; legacy SSE entries are rejected). Project
  entries override global ones; `auth` is global-only. Servers can be
  exposed as `codemode` (default), `deferred`, `direct`, or `hidden`, with
  per-tool `toolExposure` overrides. **BREAKING ⑧**: OAuth credentials live
  in `~/.rpi/agent/mcp-auth.json` under `mcp__<name>|<url>` keys; a legacy
  URL-only key is taken over atomically by the first server that uses it.
- **Surface**: `mcp__<server>__<tool>` tools (names sanitized, hash-suffixed
  on collision), the three resource tools, a short `mcp_servers` system
  prompt section, `/mcp` management, and `rpi mcp add|remove|list|login|logout`
  (works without a session).
- **Extension API (additive)**: `pi.registerMcpServer(name, config)` /
  `unregisterMcpServer(name)` / `getMcpServers()`. Registrations are not
  persisted and are announced through `mcp_servers_change`.
- **Compatibility**: the built-in extension stands down when another
  extension registers an `mcp` tool or `/mcp` command; `rpi mcp` always
  uses the built-in implementation.

## codemode scripting and tool search (V16-07)

- **`codemode` built-in tool** (registered inactive; enable it with
  `codemode` in `defaultTools` or `+codemode` via `--tools`): the model
  writes raw JavaScript that runs as an async function body in a QuickJS
  sandbox (wasmtime + a vendored `quickjs.wasm`; no Node, filesystem,
  network, or timers). Scripts call arbitrary tools as
  `tools.<name>(args)` (nested calls run through the same permission and
  hook pipeline), batch/chain/filter their results, and reach classifiers
  and image models through `models.*`. `text()`, `image()`, `console.*`,
  top-level `return`, and `exit()` produce output; `store(key, value)` /
  `load(key)` keep small JSON values across calls as branch-scoped
  `codemode-store` entries. A first-line
  `// @options: {"max_output_tokens": …, "timeout_ms": …}` sets the output
  budget and the script deadline. The model-facing description lists the
  callable tools within `codemode.inlineBudget` (default 3000 estimated
  tokens) and points at `docs/codemode.md` for the full reference.
- **BREAKING — codemode scripts must use `"x" in tools` to probe tools**:
  reading a missing tool member now throws a `TypeError` with close-match
  suggestions, so `typeof tools.x` no longer reports `"undefined"`.
  Rewrite existence checks as `"x" in tools` (upstream v1.0.0 behavior).
- **`tool_search` built-in tool** (registered inactive): BM25 search over
  the tools that are not declared to the model (the `codemode`/`deferred`
  exposure classes); matches are loaded into the active set for the next
  model call. The same ranker powers the script-side `searchTools()`.
- **Structured bash results**: bash declares an `outputSchema` and returns
  `structuredContent` (`{output, truncated, full_output_path?, exit_code,
  wall_time_seconds}`; up to 1 MiB keeping head/tail around an omission
  marker). A non-zero exit code is now an `isError` result carrying that
  structured value instead of a thrown error, so codemode scripts can
  inspect failures; the model-facing text is unchanged apart from the
  status suffix.
- **Classifier and image generation execution**: `models.classify()`
  (TypeSafe System One and Cloudflare Workers AI transports, shared by the
  TypeSafe/OpenRouter/Vercel AI Gateway/OpenCode providers) and
  `models.generateImages()` (OpenRouter) resolve auth at request time
  (stored credentials, OAuth, runtime API keys, `models.json` headers)
  and never reject: failures come back with `stopReason: "error"` /
  `"aborted"` and an `errorMessage`. Provider catalogs now expose every
  schema-v6 model type (chat/image/classifier); the classifier-only
  TypeSafe provider is now registered.

## Miscellaneous fixes (V16-04)

- **`--mode` validation** (#9045): a missing value, an option-shaped value,
  or an unknown value (`rpi --mode yaml`) now reports
  `Invalid mode "yaml". Valid values: text, json, rpc` and exits with
  status 1 instead of silently ignoring the flag. `text` / `json` / `rpc`
  are unchanged.
- **Split-turn compaction summaries are accepted again** (#9908): when a
  turn is split for compaction, the summarization prompt now separates the
  conversation from the instructions and uses continuation-oriented
  wording, so reasoning models (Fable 5.1) no longer refuse the summary.
- **GIF detection requires the complete signature**: only `GIF87a` and
  `GIF89a` headers are treated as GIF images; a text file whose content
  starts with `GIF` is no longer misclassified as an image (all three
  entry points: `read`, `@file`, tool results).
- **Malformed prompt frontmatter is reported**: a prompt template with a
  YAML syntax error in its frontmatter no longer disappears silently. It is
  skipped with a resource warning (path + parser position) while the valid
  sibling templates keep loading, both in `/prompts` listing and warning
  surfaces.
- **Per-model image input limits are enforced**: when a model declares
  `inputLimits.images.resize` (in `models.json` overrides or catalog
  metadata), prompt images, `read` images, and tool-result images are
  resized with that profile (max width/height, byte budget, JPEG quality).
  `@file` attachments are resized after extension hooks pick the request
  model. Models without a profile keep the previous global defaults and
  produce byte-identical output.
- **Cache warming skips late refreshes**: a scheduled cache-warming
  refresh that fires after the point where a full-price cache write is
  likely (half of the original expiry margin consumed by timer delays) is
  skipped and the warmer stops with `cache refresh deadline missed`.
- **Fullscreen jump-to-end label is stable** (#9842): the
  "jump to latest message" indicator stays centered when the auto-hiding
  scrollbar appears or disappears and is clipped before the scrollbar
  column, so it never covers or captures clicks on the scrollbar.

## TUI theme system, colors, and fullscreen default (V16-10)

- **`theme` now defaults to `system`** (upstream `bf8e4b953`): the new
  built-in `system` theme derives all colors from the terminal's reported
  foreground/background/16-color palette, keeps body text at >= 4.5:1
  WCAG contrast, and follows light/dark switches. It is listed first in
  theme pickers and is a reserved name. Explicitly configured themes
  (`dark`, `light`, custom) and `light/dark`-style automatic pairs behave
  as before.
- **Terminal color query rewritten** (upstream 0.99.0 [BREAKING]): the two
  query APIs (`queryTerminalBackgroundColor`, `queryTerminalColorScheme`)
  and the OSC 11 background parser are replaced by a single-pass
  `queryTerminalColors()` that asks for OSC 10 (foreground), OSC 11
  (background), and OSC 4 (palette 0-15) terminated by a DA1 request.
  Startup waits at most 100ms; late replies still apply. The system theme
  renders in grayscale until the terminal answers.
- **New color value surface** (upstream `567469096`, `ddba59618`): `Color`
  (indexed/sRGB/OKLCH), `parseColor()` (`#rgb`, `#rrggbb`, `oklch()`,
  `okhsl()`), `mixColors()`, `colorToHex()`/`colorToRgb()`/
  `colorToOklch()`/`colorToOkhsl()`, `styleText()`, and
  `getTerminalColorMode()`; `TERM=*-direct` is treated as truecolor.
- **Theme file format**: color values accept `#rgb`, `oklch()` and
  `okhsl()` in addition to hex, `var` references and 0-255 indices; an
  optional `appearance` field declares the background a theme is designed
  for (omitted: detected from the theme's own colors). The built-in
  `dark`/`light` themes are rewritten in OKHSL (upstream `bf8e4b953`).
  Exported HTML converts OKHSL values to hex.
- **`tuiMode` now defaults to `fullscreen`** (upstream `88ff80b98`,
  v1.0.0): start with `--tui-mode regular` or set `tuiMode: "regular"` to
  keep the inline mode. The alt-screen renderer, settings
  (`fullscreenExitOutput`, `fullscreenScrollbar`, `fullscreenCopyOnSelect`)
  and the new `fullscreenWheelScrollLines` wheel acceleration
  (upstream `f1927c2d5`: `"auto"` default, up to six lines per event on
  fast spins, Alt still 5x) are unchanged otherwise.
- **Startup banner**: the `[Themes]` section is removed; the header stays
  the brand wordmark plus version. rpi already renders a text wordmark, so
  upstream `ca9c92511`'s Apple-Terminal logo fallback has no equivalent
  surface (registered as [N/A-struct]). `quietStartup: "header"` keeps the
  version and key-hint header but hides the model scope line and
  loaded-resource list (the setting key registers with V16-13).
- **TUI fixes**: `sliceByColumn` preserves ANSI order at slice boundaries
  so selections/search highlights no longer leak color (#10169);
  `TuiAltScreen.getScreenLines()` returns the previous frame (additive);
  user messages keep one copy of each rendered line (identical output).

## Authentication: Sign in with ChatGPT, shared OAuth callbacks, federation (V16-11)

- **Sign in with ChatGPT** (upstream `02eed88fd`): the `openai` provider
  offers a ChatGPT subscription OAuth flow next to the API key. Each
  login registers a public client, uses the fixed loopback callback
  (`http://127.0.0.1:1455/auth/callback`), and stores the issued client
  ID and granted scopes with the credential. A stable per-installation
  UUID (`deviceId`) is generated in the global settings on first use and
  sent as the agent host ID; project settings never supply it.
  Subscription usage-limit errors
  (`subscription_sharing_usage_limit_exceeded`) are not retried and link
  to the ChatGPT usage page, while the related `*_unavailable` codes
  stay retryable. Requests made with a ChatGPT credential omit
  `prompt_cache_retention`, `prompt_cache_options`, `max_output_tokens`
  and `temperature`, which the endpoint rejects.
- **Shared OAuth callback server** (upstream `4df157433`): the Anthropic,
  OpenAI Codex, OpenRouter and Radius browser sign-ins now share one
  loopback implementation. Provider error redirects settle the wait
  immediately (previously the Anthropic and Codex flows could hang), and
  a port collision for Anthropic or Codex falls back to pasting the
  redirect URL; Radius keeps failing the login (device-code remains its
  alternative) and OpenRouter keeps its ephemeral port, matching
  upstream. `/login` provider sign-ins use the real OAuth dialog now.
- **Anthropic workload identity federation** (upstream `a9424cd43`):
  `ANTHROPIC_FEDERATION_RULE_ID`, `ANTHROPIC_ORGANIZATION_ID` and
  `ANTHROPIC_IDENTITY_TOKEN_FILE` (plus the optional
  `ANTHROPIC_SERVICE_ACCOUNT_ID` / `ANTHROPIC_WORKSPACE_ID`) resolve the
  provider through an RFC 7523 jwt-bearer exchange against the API's
  `/v1/oauth/token`, with an in-process two-tier token cache (advisory
  refresh at 120s, blocking at 30s) and a 401-driven re-exchange. Stored
  keys and `ANTHROPIC_AUTH_TOKEN` keep precedence.
- **Anthropic copy-code login** (upstream `7a11fe1c7`, #10194): `/login`
  offers "Copy code login (headless)" for Anthropic, using the
  platform-hosted redirect and the pasted `code#state`.
- **Radius sign-in in `/login`** (upstream `ed8b3bcc1`): the top-level
  `/login` menu lists "Sign in with Radius" last (with the auth status),
  cancelling returns to that menu, and after signing in rpi offers to
  point the global `mcp.json` Radius server at the login
  (`auth.provider: "radius"`) and reload.

## Virtual models (V16-12, experimental)

- **`registerVirtualModel()`** (upstream `540e174c7`, #10035): extensions can
  register a catalog entry that routes each request to a physical model and
  thinking level. The selection (`/model`, `model_change` entries, the agent
  state) keeps naming the virtual model; everything below the routing step —
  providers, assistant messages, cost buckets — only sees the physical model
  that answered. A virtual model belongs to a provider id (existing or new;
  a virtual-only provider needs no credentials) and hides a physical chat
  model with the same id. `unregisterVirtualModel()` removes it. The route
  callback crosses the extension boundary as a host→extension dispatch, so
  wasm and native extensions register the same way; routing from inside the
  routing extension's own in-flight model call is refused instead of
  deadlocking (documented limitation).
- **Per-request routing**: the router receives the request conversation, the
  reason (`user` / `continuation` / `retry` / `direct`), the previous
  successful response, and — for retries — the failed response. Returned
  router state is stored on the session branch (`pi.virtual-model-state`)
  and handed back on later requests; it follows the session tree and
  survives compaction. Router failures, non-physical targets and targets
  without credentials end the request with an error response naming the
  virtual model, without calling the physical provider.
- **Display**: the footer shows the routed model after the selection
  (`auto • high → gpt-5.6-luna • medium`), context limits follow the
  physical model that answered, and `/session` keeps the per-model cost
  breakdown expanded under a virtual selection because the bucket key never
  matches the selection. Compaction, overflow recovery and branch summaries
  route their summary request with reason `direct`; resuming a session
  restores a still-registered virtual selection and falls back to the last
  physical response otherwise.
- **Example**: `examples/extensions/jev-router` plans on a strong model and
  implements on a cheap one (ported from upstream's Jev router example).
- The feature is experimental, matching upstream: the API may change without
  notice. The extension ABI additions (`registerVirtualModel` /
  `unregisterVirtualModel`, `ctx.modelRegistry.findOfType` /
  `ctx.modelRegistry.classify`) are additive; `rpiAbi` stays `1`.

## Permission modes and usage providers (V16-05, rpi-own)

- **Permission mode**: `Shift+Tab` now cycles a session-scoped permission
  mode (`app.mode.cycle`, `default` ↔ `plan`); the thinking-level cycle
  previously on `Shift+Tab` moved to `Alt+T`. A keybindings config that
  explicitly pinned the old `Shift+Tab` default for `app.thinking.cycle` is
  migrated to `Alt+T` on load. Plan mode shows a `⏸ plan` badge in the
  built-in footer, and a statusline extension replacing the footer
  (`ui.setFooter`) hides that built-in footer — and the badge — entirely.
- **Mode API (additive)**: extensions read/write the mode through
  `ctx.getMode()` / `ctx.setMode("default" | "plan")` and receive
  `mode_change` events (`{from, to}`) on every transition. Sessions that
  are not interactive answer `default`; a fresh session (`/new`, `/resume`,
  `/fork`, `/clone`, `/import`) starts in `default` and the outgoing plan
  state is announced as `plan → default`.
- **Scripted usage providers (additive)**: `ctx.usage.register(provider,
  scriptPath)` registers an executable script, `ctx.usage.listProviders()`
  lists the known providers, and `ctx.usage.fetch(provider, force?)`
  returns the last successful usage envelope. A TTL cache answers without
  re-running (60s); a failed run keeps the last success; execution is
  serialized, capped at 64 KiB stdout, and times out after 3000ms by
  default (`usage.timeoutMs`, 500–60000). Providers resolve explicit
  `usage.providers` settings > `~/.rpi/agent/usage-providers/<provider>.py`
  > plugin registration. Scripts receive `{provider, baseUrl?, apiKeyEnv?,
  model?}` on stdin — the credential itself reaches the child only through
  its environment — and print `{schemaVersion: 1, provider, plan?,
  balance?, quota?, used?, resetAt?, displayText}`. Unknown fields are
  ignored and the cache never stores a field beyond that schema.
- `getMode`/`setMode` and `ctx.usage.*` are additive; `rpiAbi` stays `1`.
  The extension event table grows 41 → 42 with the rpi-own `mode_change`
  appended at the tail.

## Plan mode (`rpi-plan-mode`, TE43, rpi-own)

- **New first-party plugin**: `/plan` (or the host `Shift+Tab` cycle)
  switches the session into a read-only planning mode. Entering Plan mode
  hides every non-whitelist tool through the session exposure override
  layer (`setToolExposures`), activates the read-only whitelist
  (`read`/`grep`/`find`/`ls`/`web_fetch`/`batch_web_fetch`) plus
  `write_plan`, and shows a one-line editor hint. Leaving Plan mode
  restores the tool exposures and the pre-entry active set.
- **`write_plan(content)`** writes the complete plan to
  `<cwd>/.rpi/plans/<session-id>-<n>.md` (lazy directory creation,
  incrementing file per Plan entry, revisions overwrite the current
  file). The tool takes no path argument — the path is derived from the
  bound session, so path injection is structurally impossible. Models
  outside Plan mode cannot reach the tool (registered inactive).
- **Review dialog**: a successful `write_plan` asks **Approve and
  execute** / **Continue revising** / **Abandon**. Approve leaves Plan
  mode and injects the plan summary plus an execution instruction as a
  follow-up message; revise routes the collected feedback through the
  tool result; abandon leaves Plan mode with no injection. Esc counts as
  abandon. Where no interactive dialog is available (no UI, or RPC mode),
  the tool reports a text note and the session stays in Plan mode.
- **Prompt injection**: while Plan mode is active, `before_agent_start`
  contributes four plan guidelines (research first; no writes; write the
  plan with `write_plan`; wait for approval) and a `plan_mode` prompt
  section carrying the current plan file path. Leaving Plan mode — or
  setting `promptInjection = false` — removes exactly that contribution.
- **Config**: `~/.config/rpi-plan-mode/config.toml`
  (`allowTools`/`blockTools`/`planDir`/`promptInjection`; malformed files
  fall back to the defaults per key, unknown keys are ignored). The file
  is re-read on every mode trigger, so edits apply at the next mode
  change / session event / prompt turn, in both the hide and release
  directions. `planDir` accepts absolute paths (documented risk).
- **Commands**: `/plan` toggles, `/plan status` reports the mode and plan
  file, `/plan file` prints the path, `/plan edit` opens the current plan
  file in the external editor (`ui.editExternal`, falling back to
  `ui.editor`).
- The plugin is additive (`rpiAbi` stays `1`); it consumes the V16-05
  mode API and the V16-14 exposure overrides. XDG config path is the
  TE-D45 [VARIANT]; the exposure-hidden boundary shape (instead of CC's
  permission prompts, `bash` excluded by default) is the TE-D46
  [VARIANT].

## Usage lookup (`rpi-usage`, TE44, rpi-own)

- **New first-party plugin**: `/usage` (the current model provider),
  `/usage <provider>` (a registry key), and `/usage all` (every reachable
  provider) query balance / plan quota through the V16-05 scripted
  usage-provider framework and report multi-line output; a provider without
  a matching script gets configuration guidance instead of a guess.
- **Footer status line**: a successful lookup is shown as
  `ui.setStatus("rpi-usage", displayText)` alongside other extensions'
  status entries. Refreshes follow `session_start`, `model_select`, and
  `/usage`; `message_end` refreshes under the `usage.refreshMs` throttle
  (default 5 minutes). A failed refresh keeps the last successful line (no
  flicker, no error toast); a model switch to a provider without a script
  removes the entry instead of showing stale data. Sessions without a UI
  stay dormant.
- **Four built-in providers**: DeepSeek (`GET /user/balance`), GLM Coding
  Plan (z.ai / BigModel `api/monitor/usage/quota/limit`, 5-hour / weekly /
  monthly-MCP windows), MiniMax Token Plan (`/v1/token_plan/remains`,
  international and China hosts) and Kimi Code (`/coding/v1/usages` with an
  `sk-kimi-*` key). The contracts were pinned against live endpoints on
  2026-10-05 and covered by recorded fixtures; scripts are python3
  standard-library only, print the `schemaVersion: 1` envelope, and degrade
  with a non-zero exit (the host answers the last success). No HTTP client
  is added to the plugin.
- **Scripts and credentials**: the scripts are compiled into the plugin and
  materialized at install under `<agentDir>/rpi-usage/scripts/` (idempotent,
  atomically replaced), then registered through `ctx.usage.register`.
  Explicit `usage.providers` settings and `<agentDir>/usage-providers/*.py`
  keep precedence, so user overrides win unchanged. A script resolves its
  API key from the injected/exported environment variable first, then from
  the rpi credential store `<agentDir>/auth.json` (read-only `api_key`
  entries; `$VAR` references follow the environment, command references are
  never executed). Keyring-only credentials need the environment variable
  path.
- **Config**: `<agentDir>/settings.json` `usage` section — `enabled`
  (default `true`), `footer` (default `true`), `refreshMs` (clamped
  1s–1h, default 5min); `providers` / `timeoutMs` remain the host
  framework's typed keys. Edits apply on the next trigger.
- The plugin is additive (`rpiAbi` stays `1`; no new host calls).

## Built-in extension governance, settings, and RPC (V16-13)

- **Built-in extensions are now `builtin:<name>` resources** (upstream
  `4259686d9`, #10159): `llama.cpp`, `codemode`, `tool-search`, and `mcp`
  resolve through the package manager like any other extension path. They
  load in the final pass, after project trust resolves and after file/package
  extensions, and show up in `rpi config` under a **Built-in** group (bare
  name; a project-scope entry reads `Built-in (project override)`). Their
  extension path, diagnostics, and RPC `sourceInfo` all use the
  `builtin:<name>` name. `settings.json` `extensions` entries such as
  `-builtin:mcp`, `+builtin:mcp`, or `!builtin:*` enable/disable them
  (project entries override user ones); `--no-extensions` disables built-ins
  too, and `rpi -ne -e builtin:mcp` loads one explicitly. Unknown
  `builtin:<name>` paths fail with `Unknown built-in extension: <path>`.
- **`defaultTools` supports `+name` / `-name`** (upstream `30a1d1849`,
  #10245): a list containing only modifiers is merged onto the inherited
  value (project onto user), a list with plain names replaces it, and the
  resolved list starts from `read,bash,edit,write` and applies `+`/`-` in
  order. Extension tool names such as `codemode` and `tool_search` can be
  selected this way. On `/reload`, tools newly added to `defaultTools` are
  activated; removed ones stay active and tools disabled during the session
  stay disabled unless the setting newly adds them. `--tools` /
  `--no-tools` / `--no-builtin-tools` still override the setting, and
  `--tools` treats `+name` literally (no modifier parsing).
- **New settings keys** (upstream `8562bcf66`, `02eed88fd`): `codemode.mode`
  (`"on"` default / `"only"`) and `codemode.inlineBudget` (estimated tokens,
  default 3000; `0` lists namespaces only) are now validated and read
  through the settings manager; `deviceId` is a stable UUID created on first
  login use and read from the global settings only; `quietStartup` now
  offers `true` / `"header"` / `false` in `/settings`.
- **RPC prompt dispositions** (upstream `e473b5cd8`, #9098/#9803): the
  success response of `prompt` carries
  `data.disposition: "handled" | "queued" | "started"` and `steer` /
  `follow_up` carry `"handled" | "queued"`. `prompt` accepts
  `streamingBehavior: "steer" | "followUp"` while the agent is streaming.
  `"handled"` means no run started for this prompt; do not wait for
  `agent_settled` (see `docs/json-rpc.md`).
- **Tool call arguments and extension registration fixes** (upstream
  `5257d0d5f`, `dc83372f8`, `9d1a65035`): tools without a custom renderer
  show their arguments on the call line (`key=value`, truncated at 100
  chars) and per-line when expanded; an extension command registered with an
  empty name now fails the extension load instead of crashing the editor
  when typing `/`; a replaceable built-in replaced by another extension
  reports a warning naming the registration and pointing at `rpi config`.

## Review hardening (v0.1.6-rc.1 review rounds 1 and 2)

Pre-stable fixes from the two full review rounds on the rc.1 surface; user-visible behavior changes are marked. Fixes carry revert-red regression tests where a deterministic test is possible (the codemode close-wakeup window and similar scheduler races document in place why they cannot be opened reliably; filesystem-durability details are covered by the atomic-write tests).

- **Codemode**: execution output is capped at 16 MiB with an explicit notice when later items are dropped; cancel/Esc settles an execution whose script never settles on its own, and a script that catches the QuickJS interrupt can no longer keep the worker thread alive after a timeout; a successful script without a return value still persists its store writes (upstream `execute.ts:404`); store/return JSON is depth-bounded at 1024 levels and trailing garbage after a JSON document is rejected; the sandbox `close()` races (missed wakeup on a settling execution, stale waiters) are closed.
- **MCP transport**: a server that echoes a numeric request id as a JSON float (`1` &rarr; `1.0`) is matched by value for every server-echoed id that indexes a map (responses, progress tokens, cancellation), so an already-answered response no longer triggers a spurious GET resume or an "unknown request" error event.
- **Built-in MCP OAuth**: a rotated refresh token replaces the stored one instead of forcing a re-login at the next expiry; a corrupted or unreadable credential store is refused rather than overwritten with an empty one; credential writes are atomic 0600 with a synced parent directory (the lock directory is created 0700 like upstream); the refresh lock now distinguishes "another process holds the credential refresh lock" from local setup failures; a sign-in whose credentials could not be persisted reports an error instead of silently asking for another login next session.
- **MCP adapter**: approvals are rebuilt on branch navigation/resume/session replacement, dropping server-wide "allow for this session" grants so a stale dialog cannot authorize a server after the branch changed; the broker is consulted before the server grant (a broker deny wins) and a broker's server-wide value fails closed (the UI keeps that choice); `approveTools` values from unvalidated sources (including `"destructive"`, whose annotation semantics are still deferred) fail closed and require approval for every call; the approval dialog explains what the server-wide choice grants (upstream `serverScope` text); approval timestamps are real ISO-8601 UTC (existing epoch-second values stay readable); approval writes sync the parent directory.
- **Plan mode**: a failed `getMode`/`getAllTools` snapshot no longer releases the hidden boundary (the boundary is kept and the next event retries; a failed `getActiveTools` still asserts the whitelist); a failed exit cleanup notifies the user (once per Plan entry) and retries instead of leaking hidden overrides for the rest of the session, and an exit whose active snapshot was unavailable warns after a clean release; `planDir` expands a leading `~/`; `/plan edit` writes atomically; per-session state is dropped on `session_shutdown`; plan-file revisions use exclusively-created temp files.
- **Subagents**: a misspelled later task/step agent fails the whole call before any child starts, in both foreground and background modes (no spawn budget spent, no run directory, no receipt), and batch errors keep their requested composition mode in `details`; a per-agent `modelScope.agents.<name>` rule with an enforced reserved token fails closed when no parent model exists, and per-agent rules are enforced by their own `enforce` (an inherited parent model now warns/errors like upstream); inherited Git routing variables (`GIT_DIR`/`GIT_WORK_TREE`/`GIT_CONFIG_*`) are stripped from child environments, and children of an untrusted project receive `--no-approve`.
- **Extension host / ABI**: a misspelled tool `exposure` is rejected with `invalidRequest` instead of silently registering as `direct`; native plugin host calls on an unloaded plugin answer a stale-context error instead of touching freed memory; re-entrant `executeTool`/virtual-model dispatches fail closed instead of deadlocking; events emitted while an extension is blocked in a synchronous host call are skipped (rpi's blocking ABI cannot queue them like upstream's JS loop — registered deviation D-105); extension `renderResult` hooks now receive the tool result's `isError` bit, so errored cards (a failed subagent preflight, a failed `write_plan`) render as failures.
- **Usage providers**: the host injects its enforced timeout budget into the provider scripts (the built-in 8s script timeouts used to be unreachable under the 3s host default); `/usage` while disabled clears a stale footer line; `auth.json` `$VAR` and `${VAR}` references both resolve; a Windows launcher (`.cmd` shim) write failure is a hard error instead of registering a `.py` path that cannot start.
- **Themes/CLI**: non-ASCII theme colors no longer panic; unknown theme top-level keys are ignored like upstream (typebox `additionalProperties`) instead of rejecting user themes; `system` themes keep their styling in `/export`; script children are killed on drop and Windows kills use the full process tree from the trusted System32 path.

### Pre-stable fix (v0.1.6-rc.2 verification)

- **Built-in MCP (ABBA deadlock)**: a server still connecting when the first prompt dispatched `before_agent_start` could deadlock the interactive run loop: `pending_servers` (and the other server-list readers) held `servers` while locking each server's `entry`/`connection`/`ready`, while the connection callbacks held `server.connection` across `register_tools`/`on_connection_change` (the `if let` temporary-guard lifetime) — and those take `servers` and make synchronous host calls. Enter did nothing (the user message was never persisted, so no session file appeared) and Ctrl+C could not quit (the run loop never reached the shutdown watch). The readers now snapshot `servers` before per-server locks and the callbacks clone the connection out of its lock first; the same guard-lifetime class is fixed in `reconnect`/`sign_out` (a guaranteed self-deadlock through `drop_client` re-locking `self.client`) and `hide_tools` (a synchronous `registerTool` host call under the `tools` lock).
