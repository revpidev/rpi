# v0.1.6-rc.5 (2026-10-08)

**Pre-release (pre-release channel)**: candidate for the `0.1.6` stable
release. Content = `v0.1.6-rc.4` plus the changes below. Upgrade:
`rpi update --rc` (or `rpi update --all --rc`); `install.sh` does not serve
RCs (`releases/latest` stays stable).

## Changed in this RC

- **`rpi-mcp-adapter` is deprecated** (MCP moved into the host): every `rpi update` path skips it with a removal note instead of upgrading it (`rpi update --extensions --rc` included), startup recommends `rpi remove rpi-mcp-adapter` whenever an install is found in an extension root (the user root always, a project root when trusted — even when the extension is disabled or not loaded), the official registry entry is marked deprecated, and the extension is no longer packaged: this RC and later Releases ship seven lockstep `.rpix` archives instead of eight (`rpi-ext-mcp-adapter` removed from CI packaging; its 0.1.6-rc artifacts stay in the registry version matrix). Existing installs keep working as the optional replacement, and an explicit `rpi install rpi-mcp-adapter` is unaffected. Full detail: `changes/v0.1.6.md` → "MCP adapter extension" → "Deprecation: `rpi-mcp-adapter` is retired as an MCP solution".

## Fixed in this RC

- **Off-TTY TUI tests no longer hang** (found while verifying rc.4): an injected-writer `ProcessTerminal` (the test/harness constructor) called `crossterm::terminal::enable_raw_mode()` unconditionally in `start()`. With stdin not a tty, crossterm resolves the controlling terminal through `/dev/tty`; in a non-TTY session with an accessible controlling tty that call blocks, wedging the rpi-tui recovery panic-hook tests (observed: `cargo test -p rpi-tui` never finished off-pty, while `setsid` runs passed instantly). The injected-writer terminal now never manages the process raw mode (`owns_raw_mode`); `ProcessTerminal::new()` (the production wiring) is unchanged. Per-fix detail: `changes/v0.1.6.md` §Pre-stable fix (v0.1.6-rc.5 verification).
