# v0.1.4-rc.3 (2026-09-08)

**Pre-release (pre-release channel)**: round three of the `0.1.4` stable candidates, fixing the settings-list alignment defect found during rc.2 verification and closing out two investigation items from switching-mode reports. The baseline content matches `changes/v0.1.4.md`; at stable-release time each rc file's entries fold into `v0.1.4.md`. Install/upgrade: existing rpi users run `rpi update --rc` (or `rpi update --all --rc` to sync extensions to `0.1.4-rc.3`); force-install via the official script with `RPI_GITHUB_API_URL=https://api.github.com/repos/revpidev/rpi/releases/tags/v0.1.4-rc.3`.

## Fixes relative to rc.2 (found in rc.2 verification, rpi#24)

- **Settings list value-column alignment** (rpi#24): the "Default thinking level per model" row's value sat 2 columns right of every other row — upstream's `SettingsList` label-column width is `Math.min(36, widest label)` (settings-list.ts:120), but the port had mistyped `min(30)`, and the longest real label is exactly 32 columns, past the 30 cap after which no padding is added; fixed to `min(36)`, verbatim with upstream, with a regression test across the 30–36 column range.

## Investigation closures (not defects, recorded in rpi#24)

- **"Horizontal rule becomes two rows" after switching fullscreen↔normal**: exhaustive A/B testing against the pin `9841914` (a VT emulator with ?1049 double buffering + cursor save/restore semantics, same key sequences against both binaries) — dialog rendering, hot-switch sequences, long transcript/scrollbar/Esc flows are all **line-identical** between rpi and upstream; reproduction experiments confirmed the symptom comes from terminals rendering ambiguous-width characters (`─` U+2500, East-Asian Ambiguous) as 2 columns: in normal mode with autowrap on a full row of border characters wraps, in fullscreen (`?7l`) it doesn't, and **upstream reproduces identically** (a residual risk already recorded in ADR-0020). Remedy: set the terminal's Ambiguous width = Narrow.
- **No side margins in fullscreen mode**: upstream's fullscreen is likewise full-bleed with no horizontal padding (`chat-viewport.ts` / `tui-alt-screen.ts` have no horizontal insets), and rpi is line-identical with it; per the upstream-parity principle no padding is added (a deviation would need its own ADR).
