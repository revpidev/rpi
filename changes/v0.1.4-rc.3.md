# v0.1.4-rc.3(2026-09-08)

**预发布（pre-release channel）**：`0.1.4` 正式版候选第三轮，修复 rc.2 验证发现的 settings 列表对齐缺陷，并闭环两项切换模式报告的排查结论。基线内容与 `changes/v0.1.4.md` 一致；正式版发布时各 rc 文件条目并入 `v0.1.4.md`。安装/升级：已装 rpi 用户 `rpi update --rc`（或 `rpi update --all --rc` 同步扩展到 `0.1.4-rc.3`）；官方脚本强装 `RPI_GITHUB_API_URL=https://api.github.com/repos/revpidev/rpi/releases/tags/v0.1.4-rc.3`。

## 相对 rc.2 的修复（rc.2 验证发现，rpi#24）

- **settings 列表值列对齐**（rpi#24）：「Default thinking level per model」行的值比其他行右移 2 列——上游 `SettingsList` 标签列宽为 `Math.min(36, 最宽标签)`（settings-list.ts:120），移植误写为 `min(30)`，而最长真实标签恰为 32 列、越过 30 上限后不再补空格；修复为 `min(36)` 与上游逐字一致，附 30–36 列区间对齐回归测试。

## 排查闭环（非缺陷，rpi#24 记录）

- **切换全屏↔普通后「横线变两行」**：对 pin `9841914` 穷尽 A/B 实测（?1049 双缓冲 + 光标保存/恢复语义的 VT 模拟器，同键序双二进制）——对话框渲染、热切换序列、长转录/滚动条/Esc 各流程 rpi 与上游**逐行一致**；复现实验确认症状由终端把歧义宽度字符（`─` U+2500，East-Asian Ambiguous）按 2 列渲染所致：普通模式 autowrap on 满行 border 折为两行、全屏（`?7l`）不折行，**上游同样复现**（ADR-0020 已记录的残留风险）。处置：终端设置 Ambiguous width = Narrow。
- **全屏模式左右无边距**：上游 fullscreen 同样通栏无边距（`chat-viewport.ts`/`tui-alt-screen.ts` 无水平内边距），rpi 已与其逐行一致；按上游一致原则不加边距（如需偏离另立 ADR）。

- 如仍见切换模式后 border 折行：确认终端 Ambiguous width 是否为 Narrow 后复测，并将终端类型 + 列宽 + 是否复用 tmux 反馈至 issue
- 其余验证面同 rc.2（见 `changes/v0.1.4-rc.2.md`）
