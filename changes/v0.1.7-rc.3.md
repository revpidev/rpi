# v0.1.7-rc.3 (2026-10-19)

**Pre-release (pre-release channel)**: candidate for the `0.1.7` stable release. Content = `v0.1.7-rc.2` plus the installer/uninstall PATH hardening below; at stable-release time these entries fold into `changes/v0.1.7.md`. Upgrade: `rpi update --rc` (or `rpi update --all --rc` to also move the seven lockstep extensions to `0.1.7-rc.3`); `install.sh` does not serve RCs (`releases/latest` stays stable).

## Fixed in this RC (installer and uninstall hardening)

- **`install.sh` PATH writes preserve the user's profile**: the `# rpi` block is rewritten in place instead of being replaced with `mv`, so symlinked dotfiles stay symlinks and the file mode/owner is kept (a 600 profile no longer becomes group/world-readable). Rewrites are idempotent, no longer accumulate blank lines, and recognize the legacy absolute `export PATH="…:$PATH"` line printed by older installers.
- **The generated PATH entry is idempotent**: POSIX profiles get a one-line `case ":$PATH:" in …` guard (nested shells no longer append duplicates); `fish_add_path` remains the fish spelling. The default `~/.local/bin` is still emitted as `$HOME/.local/bin` for portability, custom paths are escaped for `$`, `"`, backtick and backslash, and a custom path under `$HOME` works with spaces.
- **Interactive prompting is automation-safe**: the prompt requires terminal stdout, a usable `/dev/tty`, and no `CI`/`RPI_NONINTERACTIVE`/`TERM=dumb` marker. Shells with `read -t` treat an unanswered prompt as "no" after `RPI_INSTALL_PROMPT_TIMEOUT` seconds (default 60). CI/pty automation should set `RPI_INSTALL_ADD_PATH=0`; `--add-path` and `--no-add-path` are now mutually exclusive, and the environment value is trimmed/case-normalized (`True`, `ON`, …).
- **Shell detection is explicit**: bash uses `.bashrc`, then `.bash_profile`/`.bash_login`, then `.profile`; zsh honors `ZDOTDIR`; fish honors `XDG_CONFIG_HOME`; sh/dash/ash/ksh use `.profile`. Unsupported shells (csh/tcsh/nushell/pwsh/xonsh, …) only print manual guidance instead of writing invalid syntax into `.profile`.
- **Windows PATH updates keep user-managed spellings**: the installer preserves the existing registry value kind (REG_SZ stays literal, REG_EXPAND_SZ stays expandable), removes duplicates by comparing expanded `%VAR%` spellings while writing the original text back, keeps a drive root as `C:\` (not `C:`), broadcasts `WM_SETTINGCHANGE`, and updates the current process PATH. If a machine-level `rpi` still precedes the new user entry in a fresh terminal, it prints a warning; the manual fallback command also preserves the registry kind and `%VAR%` entries.
- **Windows prompting follows the same non-interactive rules**: CI, `RPI_NONINTERACTIVE`, `TERM=dumb`, redirected input or redirected output all skip the prompt and print the manual command.
- **`rpi self-uninstall` reliably removes the installer block**: matching now uses both the resolved executable path and the manifest's logical `installPath`, so symlinked HOME directories and symlinked install directories are covered. `ZDOTDIR`/`XDG_CONFIG_HOME` are treated as unset when empty and both the default and env-selected profiles are scanned, so changing those variables between install and uninstall no longer leaves a stale block. Matching is path-token aware (no `/home/me/.local/bin-extra` false positive), handles escaped custom paths, preserves CRLF profiles, drops the installer's separator blank line, and warns (instead of silently skipping) on non-UTF-8 profiles. The binary is removed before the PATH block, so a failed binary deletion leaves the user able to retry. Manual PATH lines without the `# rpi` marker are never touched.

## Tests and docs

- `scripts/test-install-sh.sh` is hermetic (clears `ZDOTDIR`/`XDG_CONFIG_HOME`) and grows to **95 checks**: symlinked profile + mode preservation, prefix changes, HOME trailing slash, special-character paths (sourced in sh), legacy absolute lines, mixed-case env, mutual-exclusion flags, unsupported shells, bash `.bash_profile`, the interactive pty prompt (`n`/`y`) and the `read -t` timeout path.
- New `scripts/test-install-ps1.ps1` (44 checks) parses `install.ps1`, loads its PATH helpers, and mocks the registry/prompt seams: scope detection, literal and `%VAR%` dedupe, drive roots, combined-PATH shadow warning, manual/refresh command escaping, skip/add/prompt/non-interactive branches. The release workflow runs the shell suite on Linux (`sh`), and the PowerShell suite on Linux (`pwsh`) and Windows (`Windows PowerShell 5.1`).
- README/README.zh-CN and the site docs describe the interactive/non-interactive policy, `RPI_NONINTERACTIVE`/`RPI_INSTALL_PROMPT_TIMEOUT`, unsupported-shell behavior, and the Windows machine-PATH warning.
