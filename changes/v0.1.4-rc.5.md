# v0.1.4-rc.5(2026-09-08)

**预发布(pre-release channel)**:`0.1.4` 正式版候选第五轮。本轮 = **v0.1.4 全面审查闭环**——8 路并行深审(v0.1.3..rc.4 全量 diff 对拍上游 `9841914`)+ 主审复核 + 修复后独立复审,处置全部 1 Blocker + 6 Major;同时合入积压的子代理修复(rpi#29/#30)与 widget 排序修复(rpi#27)。基线内容与 `changes/v0.1.4.md` 一致;正式版发布时各 rc 文件条目并入 `v0.1.4.md`。安装/升级:已装 rpi 用户 `rpi update --rc`(或 `rpi update --all --rc` 同步扩展到 `0.1.4-rc.5`)。

## 相对 rc.4 的修复

### 审查处置(1 Blocker + 6 Major,每项含红绿回归)

- **Blocker·rpi#33:RPC abort 在手动 compaction/branch summary 在飞期间永久挂起**(V14-02 回归):`isIdle` 收紧为含 `!isCompacting()` 后,唯一 idle 唤醒点仍只挂在 agent run 收尾——compaction 被取消、runner 锁释放后 `wait_for_idle` 睡在 `Notify` 上无人唤醒(实测复现:abort 挂死 >5s 永不返回)。修复:对齐上游 `_resolveIdleWaitIfIdle` 全部 4 个调用点(agent 收尾已有,补手动 compaction 收尾 / 自动 compaction finally / navigateTree finally 三处);回归测试在 `CompactionStart` 回调内并发触发 abort,精确复现 RPC「compact→abort」时序。
- **Major·rpi#34:`rpi update --extensions --rc` 会把已装 stable 扩展降级为旧预发布**(违反 R6.1.3「任何通道不降级」):更新路径跳过条件仅为精确相等、无 semver 比较,毕业索引(0.1.4 + 0.1.4-rc.4 并存)下已装 0.1.4 会被 rc.4 覆盖。修复:registry/github 两路统一 `is_newer_package_version` 判定「不新于已装即 no-op」(与本体 self-update 同一判定);双向不降级回归(rc→stable 方向同修)。
- **Major·rpi#35:`pi.getFlag` 在扩展 factory 期间读不到刚注册的 pending 默认值**(上游 #8423 钉死行为):`get_flag` 只读 runtime 值、无 pending 回退。修复:loading 期回退 pending 缓冲(CLI 已设值仍优先);factory 内 registerFlag 后立即 getFlag 可见(镜像 8423 回归场景)。
- **Major·rpi#36:`/llama` 显式刷新未强制 `allowNetwork:true`,RPI_OFFLINE 下实时目录被 stored 快照覆盖**:`refresh(None)` 缺省取 offline 开关,llama provider 的 stored 恢复段先无条件覆盖 `models` 再提前返回。修复:对齐上游 index.ts:51-56——`allow_network:true` + `providers:[llama]` + 15s signal + `aborted→"Model catalog refresh timed out."`;**复审补丁**:`ModelRuntime::refresh` 补 `providers` 透传(此前被 `..Default::default()` 静默丢弃,llama-only 实际未生效),runtime 边界回归钉死两阶段(false→true)与未选中 provider 整只滤除。
- **Major·rpi#37:`/model` 搜索默认项钉顶语义与上游不同**:rpi 移植的是上游 `1d3503fb9` 时点形态(`" default startup"` + 整词匹配),漏掉 `768184923` 的语义修复(`" default"` + 前缀判定)。修复:搜索后缀与钉顶判定对齐 `9841914`(输入 `d`/`de` 钉顶、`startup` 不再误命中)。
- **Major·rpi#38:`Box::handle_mouse` 缺 x 边界守卫**:点击 Box 左右 padding 列仍会派发子组件(`with_local` 不钳制),全屏工具块 padding 点击误触展开/收起。修复:补上游 box.ts:79 三条件守卫,padding 点击回到屏幕级处理。
- **Major·rpi-pages#4:站点 stable 端点无预发布护栏**(已有一次线上事故先例 4160d1e):RC 窗口裸跑 `generate-site.py` 会把 workspace 预发布写进 `api/latest-version.json`。修复:预发布形态闸 + `--allow-prerelease` 逃生门 + RC-only 刷新(`--rc-version`)自动跳过 stable 端点(与 RELEASING RC 流程兼容)。

### 积压修复随本 rc 合入

- **rpi#29**:tasks[] 并行批次运行期间步骤状态恒挂「queued」——`run_parallel_async` 新增 Started/Finished 事件流,per-child running/complete 实时转换 + `ctx.step_status` 活动镜像接通(父 agent 的 subagent_wait 实时列表不再误导)。
- **rpi#30**:`globalConcurrencyLimit` 从 dead code 接线为 run 级全局子代理并发信号量(上游默认 20,per-run 共享、与每批自身 concurrency 叠加;Started 事件在取得 permit 后触发)。
- **rpi#27**:belowEditor widget 同 key 重挂载沉底——原位替换消除多 widget 顺序闪跳(statusline + subagents fleet 行)。

全量门禁复跑(合入全部修复 + rc.5 bump 后):workspace **5716 用例零失败**(连续两轮一致),`fmt --check` / `clippy --workspace --all-targets -- -D warnings` 干净;每项修复均含「只回退源码、保留测试」的定向破坏验证(对应回归必红)。

- RPC 客户端:会话中触发 `/compact` 后立即发 `abort`——abort 响应应正常返回(不再挂死);`new_session`/`fork`/`resume` 在 compaction 在飞时也应正常收口

- `/model` 搜索:输入 `d` 默认模型钉顶;输入 `startup` 不再命中默认模型
- 全屏点击工具块左右边缘列:不再误触展开/收起
- 其余验证面同 rc.4(见 `changes/v0.1.4-rc.4.md`)
