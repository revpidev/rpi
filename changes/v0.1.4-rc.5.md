## Fixes relative to rc.4

### Review dispositions (1 Blocker + 6 Majors, each with red/green regression)

- **Blocker·rpi#33: RPC abort hanging forever while manual compaction / branch summary is in flight** (a V14-02 regression): after `isIdle` was tightened to include `!isCompacting()`, the only idle wakeup point remained attached to agent-run completion — once the compaction was cancelled and the runner lock released, `wait_for_idle` slept on a `Notify` with nobody to wake it (reproduced: abort hung >5s and never returned). Fix: aligned with upstream's `_resolveIdleWaitIfIdle` at all 4 call sites (agent completion already had it; added manual-compaction completion / auto-compaction finally / navigateTree finally); the regression test triggers abort concurrently inside the `CompactionStart` callback, replaying the exact RPC "compact→abort" interleaving.
- **Major·rpi#34: `rpi update --extensions --rc` downgrading installed stable extensions to older pre-releases** (violating R6.1.3 "no channel ever downgrades"): the update path's skip condition was exact equality with no semver comparison, so under a graduated index (0.1.4 coexisting with 0.1.4-rc.4) an installed 0.1.4 got overwritten by rc.4. Fix: registry/github paths unified under `is_newer_package_version` — "not newer than installed = no-op" (the same predicate as the binary's self-update); bidirectional no-downgrade regression (the rc→stable direction fixed as well).
- **Major·rpi#35: `pi.getFlag` unable to read just-registered pending defaults during the extension factory** (behavior pinned by upstream #8423): `get_flag` only read runtime values with no pending fallback. Fix: during loading, fall back to the pending buffer (CLI-set values still win); getFlag right after registerFlag inside the factory is visible (mirroring the 8423 regression scenario).
- **Major·rpi#36: `/llama` explicit refresh not forcing `allowNetwork:true`, letting stored snapshots overwrite the live catalog under RPI_OFFLINE**: `refresh(None)` defaulted to the offline switch, and the llama provider's stored-restore section unconditionally overwrote `models` before returning early. Fix: aligned with upstream index.ts:51-56 — `allow_network:true` + `providers:[llama]` + a 15s signal + `aborted→"Model catalog refresh timed out."`; **review patch**: `ModelRuntime::refresh` gained `providers` passthrough (previously silently dropped by `..Default::default()`, so llama-only never actually applied), with runtime-boundary regression tests pinning both stages (false→true) and the wholesale filtering-out of unselected providers.
- **Major·rpi#37: `/model` search default-entry pinning semantics differing from upstream**: the rpi port had upstream's `1d3503fb9`-era shape (`" default startup"` + whole-word matching), missing the `768184923` semantic fix (`" default"` + prefix matching). Fix: the search suffix and pinning predicate aligned with `9841914` (typing `d`/`de` pins the default; `startup` no longer matches it).
- **Major·rpi#38: `Box::handle_mouse` missing x-boundary guards**: clicks on a Box's left/right padding columns still dispatched to children (`with_local` doesn't clamp), so clicking a fullscreen tool block's padding accidentally toggled expand/collapse. Fix: upstream's box.ts:79 three-condition guard added; padding clicks return to screen-level handling.
- **Major·rpi-pages#4: the site's stable endpoint had no pre-release guard** (with one prior production incident, 4160d1e): running `generate-site.py` bare during an RC window would write the workspace pre-release into `api/latest-version.json`. Fix: a pre-release shape gate + an `--allow-prerelease` escape hatch + RC-only refreshes (`--rc-version`) automatically skipping the stable endpoint (compatible with the RELEASING RC flow).

## Verification requests (rc.5 focus)

- RPC clients: trigger `/compact` mid-session then immediately send `abort` — the abort response should return normally (no more hanging); `new_session`/`fork`/`resume` should also close out normally while compaction is in flight
- Users with 0.1.4-rc.4 extensions installed: `rpi update --extensions --rc` should upgrade to rc.5; a locally hand-installed 0.1.4 stable extension must not be downgraded by `--rc`
- Extension development: `pi.getFlag` inside a factory should immediately see just-registered defaults
- `/llama` under `RPI_OFFLINE=1`: the live catalog is no longer overwritten by the old snapshot, and no other provider makes network requests
- `/model` search: typing `d` pins the default model; typing `startup` no longer matches it
- Clicking the left/right edge columns of a fullscreen tool block: no more accidental expand/collapse
- Remaining verification surface as in rc.4 (see `changes/v0.1.4-rc.4.md`)
