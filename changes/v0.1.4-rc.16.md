# v0.1.4-rc.16 (2026-09-17)

**Pre-release (pre-release channel)**: round sixteen of the `0.1.4` stable candidates. This round = **statusline `live_output` freezing `decode_ms`** (#50). Install/upgrade: existing rpi users run `rpi update --rc` (or `rpi update --all --rc` to sync extensions to `0.1.4-rc.16`); force-install via the official script with `RPI_GITHUB_API_URL=https://api.github.com/repos/revpidev/rpi/releases/tags/v0.1.4-rc.16`.

## Increments relative to rc.15

- **Decode-duration passthrough for stateless tok/s on the statusline** (#50; `rpi-statusline`, PR #51): rc.15 passed the raw material through (accumulated text, streaming usage, the decode wall-clock anchor, message_id), but the payload still lacked the **decode duration** — `message_end` froze `elapsed_ms` without clearing the anchor, so idle ticks kept drifting on `now − decode_started_at_ms`, and precise tok/s scripts had to persist per-session state across calls (three classes: TTFT `max()` back-derivation, frozen-denominator caching + just-ended detection, and `message_id` boundary detection); `on_session_start` resets LiveMeasure while the script-side state file doesn't follow, so both failure modes — orphaned state after a resume changes the id, and stale frozen rates when the id is reused — really happen. The fix has the host measure and pass through a single number that absorbs all three state classes: `decode_ms` = first delta→now (streaming, live per tick) / first delta→end (frozen after `message_end`; idle ticks recompute the same value from an unchanged payload). **Always present, 0 before the first delta** — aligned with the `delta_ms`/`elapsed_ms` duration discipline (scripts can index unconditionally, and `decode_s < 0.5`-style guards absorb the pre-first-delta window; the issue's original "omitted until first delta" proposal contradicted its own example script that indexes directly, so it was ruled this way — see the issue comment); TTFT becomes the **same-clock, same-instant difference** `elapsed_ms − decode_ms` — durations measured with `Instant` twin anchors (set at the same instant as the SystemTime wall-clock anchor, which is kept as-is to serve `decode_started_at_ms`): decode_ms is computed inside the host so clocks are never compared across processes, monotonicity holds across wall-clock jumps, `snapshot` samples the same `now` as `elapsed_ms`, and the frozen value is captured at the same event instant as `on_message_end`, so the difference is exact TTFT in both streaming and frozen states (also revising the issue snippet's `SystemTime::elapsed()` `Result` compile error and its choice-of-approach). Boundaries: a `message_end` with no deltas (aborted before the first token) → `decode_ms = 0` (`output_tokens_exact` is also `None`; the script returns empty); a lost `message_end` → the next `message_start` self-heals; `peek_fingerprint` needs no inclusion (streaming `elapsed_ms` already drives it, it's stable once frozen, and switches are covered by `message_seq`). Zero changes to the host/ABI/subscription set/JSON-RPC wire protocol; the original 15 fields stay byte-identical; behavior without `liveTokens` configured is exactly as in TE12.
- **Gates**: `cargo test -p rpi-ext-statusline` 54 unit tests + 3 integration binaries all green (new: decode_ms 0 before the first delta / live streaming updates / same-`now`-sampled TTFT window assertions (8..40ms) / idle snapshots after freezing identical / no-delta abort → 0; cross-carrier-seam: present every tick, monotonic across ticks, `elapsed_ms ≥ decode_ms`, message_end-frozen ≥ the last streaming tick, and the second message resetting per message); clippy/fmt clean.

## Verification requests (rc.16 focus)

- With `statusLine.liveTokens` + a custom tok/s script configured: during streaming the rate = `output_tokens / (decode_ms/1000)` (or tokens estimated from raw text), computable from a single snapshot — **no state file needed anymore**; after `message_end`, the rate shown by idle ticks should be constant (frozen denominator), with the exact ✓ rate = `output_tokens_exact / (decode_ms/1000)`; TTFT = `elapsed_ms − decode_ms` consistent between the streaming and frozen states; after a resume (fork/new session id), no stale rate from the previous host lifetime lingers.
- Users without `liveTokens` configured: statusline behavior exactly as in rc.15 (zero-change regression).
