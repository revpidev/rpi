# v0.1.4-rc.16(2026-09-17)

**预发布(pre-release channel)**:`0.1.4` 正式版候选第十六轮。本轮 = **statusline `live_output` 冻结 `decode_ms`**(#50)。安装/升级:已装 rpi 用户 `rpi update --rc`(或 `rpi update --all --rc` 同步扩展到 `0.1.4-rc.16`);官方脚本强装 `RPI_GITHUB_API_URL=https://api.github.com/repos/revpidev/rpi/releases/tags/v0.1.4-rc.16`。

## 相对 rc.15 的增量

- **statusline 无状态 tok/s 的 decode 时长透传**(#50;`rpi-statusline` 插件,PR #51):rc.15 透传了原材料(累积原文、流式 usage、decode 墙钟锚点、message_id),但 payload 仍缺 **decode 时长**——`message_end` 冻结 `elapsed_ms` 却不清除锚点,空闲 tick 的 `now − decode_started_at_ms` 持续漂移,精准 tok/s 脚本被迫跨调用持久化 per-session 状态(TTFT `max()` 回推、冻结分母缓存 + just-ended 检测、`message_id` 边界检测三类);`on_session_start` 重置 LiveMeasure 而脚本侧 state file 不跟随,resume 换 id 孤儿 / 复用 id 读陈旧冻结速率两个失败模式都真实存在。修复为宿主直接测量并透传一个数收编全部三类状态:`decode_ms` = 首 delta→now(流式,随 tick 活更新) / 首 delta→end(`message_end` 后冻结,空闲 tick 从未变 payload 重算同一值)。**始终存在、首 delta 前 0**——对齐 `delta_ms`/`elapsed_ms` 的时长纪律(脚本可无条件索引,`decode_s < 0.5` 类守卫吸收首 delta 前窗口;issue 原提案"omitted until first delta"与示例脚本直接索引自相矛盾,按此裁定,见 issue 评论);TTFT 变为 `elapsed_ms − decode_ms` 的**同钟同时刻差**——时长测量用 `Instant` 双子锚点(与 SystemTime 墙钟锚点同刻设定,后者原样保留服务 `decode_started_at_ms`):decode_ms 为宿主内计算不再跨进程比钟,墙钟跳变下单调性保持,`snapshot` 用与 `elapsed_ms` 同一 `now` 采样、冻结值在 `on_message_end` 同事件时刻捕获,流式/冻结两态差值恒为精确 TTFT(顺带修订 issue 片段 `SystemTime::elapsed()` 的 `Result` 编译错误与选型)。边界:无 delta 的 `message_end`(首 token 前中止)→ `decode_ms = 0`(`output_tokens_exact` 亦 `None`,脚本返回空);丢 `message_end` → 下一 `message_start` 自愈;`peek_fingerprint` 无需纳入(流式 `elapsed_ms` 已驱动、冻结后稳定、切换由 `message_seq` 覆盖)。宿主/ABI/订阅集/JSON-RPC 线协议零改动;原 15 字段逐字节不变;未配置 `liveTokens` 行为与 TE12 完全一致。
- **门禁**:`cargo test -p rpi-ext-statusline` 54 单测 + 3 集成二进制全绿(新增:decode_ms 首 delta 前 0/流式活更新/同 `now` 采样的 TTFT 窗口断言(8..40ms)/冻结后空闲快照恒等/无 delta 中止 → 0;跨 carrier-seam:每 tick 在场、跨 tick 单调、`elapsed_ms ≥ decode_ms`、message_end 冻结 ≥ 最后流式 tick、第二条消息按消息重置);clippy/fmt 干净。

## 验证请求(rc.16 重点)

- 配置 `statusLine.liveTokens` + 自定义 tok/s 脚本:流式期间速率 = `output_tokens / (decode_ms/1000)`(或原文估算 tokens),单快照即可算,**不再需要任何 state file**;`message_end` 后空闲 tick 显示的速率应恒定不变(冻结分母),带 ✓ 的精确速率 = `output_tokens_exact / (decode_ms/1000)`;TTFT = `elapsed_ms − decode_ms` 流式/冻结两态一致;resume(fork/新 session id)后不再残留上一宿主生命周期的陈旧速率。
- 未配置 `liveTokens` 的用户:statusline 行为与 rc.15 完全一致(零变化回归)。
