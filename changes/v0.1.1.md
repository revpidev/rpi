# v0.1.1 (2026-08-16)

Three main lines in this release: alignment with upstream Pi v0.84.1 (T17–T32, parity freeze), the Rust port of three popular Pi plugins landing (TE01–TE11), and the extension distribution/install pipeline going live (registry / official-site index / CI packaging).

## Extension distribution and installation (new)

- **`rpi install <name>[@<range>]`**: the registry channel. A bare name resolves against the revpi.dev index (`/api/extensions/<name>.json`) with semver selection (exact / `^` / `~` supported, latest by default), pre-flight `rpiAbi` and `minHostVersion` compatibility checks before install; downloads prefer a direct GitHub connection with fallback to the official-site edge proxy; sha256 is verified against the official-site index record — on mismatch the install aborts immediately with no source switch.
- **`rpi install github:<owner>/<repo>[@<tag>]`**: a channel pointing straight at GitHub Release artifacts (for unlisted/private plugins); integrity verification degrades to the Release's own `.sha256` sidecar, and the install output states the integrity-level difference explicitly.
- **`.rpix` package format**: a gzip tar with `rpi-extension.json` + carrier + `SHA256SUMS` at the root; installation verifies every file and the name/version consistency, then atomically swaps a temporary directory into `~/.rpi/agent/extensions/<name>/` (or project-level `.rpi/extensions/` with `-l`).
- **Trust prompts**: install/update shows the author and the full capabilities table; L0 native plugins (no sandbox, full OS permissions) get a prominent warning and require confirmation in interactive mode or `--yes`.
- `remove` / `list` / `update` support the new channels end-to-end; `RPI_REGISTRY_URL` can inject a registry mirror/test URL, `off` disables the registry entirely.
- **First-party plugins ship with host releases**: CI packages `rpi-ext-subagents` / `rpi-ext-mcp-adapter` / `rpi-ext-smart-fetch` / `rpi-ext-statusline` each as `<name>-<version>-<target>.rpix` (four targets: Windows x64 / macOS arm64 / Linux x64 and arm64 glibc; musl hosts cannot load native extensions, so no plugin packages for them), published in the same GitHub Release as the host binary with lockstep versions; the official-site index picks them up automatically and marks them "official".
- New on revpi.dev: the `/api/extensions/` index API (statically generated), the `/extensions/download/` proxy (allowlist + edge origin-pull), and the plugin catalog page (extensions.html, showing capabilities and the L0 trust copy).

## First-party plugin ports (TE01–TE12)

- **rpi-ext-mcp-adapter** (porting pi-mcp-adapter v2.24.0): the MCP client adapter — three-source config merge, stdio/SSE/HTTP transports, the full OAuth flow (PKCE fail-closed), proxy and direct tool registration, lazy-connect lifecycle with session restore, status-bar wiring and collapsed tool-result rendering; parity evidence chain in scripts/mcp-parity.
- **rpi-ext-subagents** (porting pi-subagents v0.48.0): structured delegation via the `subagent` tool — six built-in agents with four-level discovery/aliases/agentOverrides, fresh/fork, composition orchestration and background async runners, worktree isolation, acceptance gates and run budgets, the supervisor coordination channel, streaming progress/message rendering with TUI visualization (TE11), three artifact modes with throttled cleanup, and `/run` `/subagents` `/subagents-doctor`; parity harness fully MATCH + dual-track E2E.
- **rpi-ext-smart-fetch** (porting agent-smart-fetch v0.3.17): the full `web_fetch` pipeline — batch concurrency, meta refresh / alternate fallbacks, streamed downloads, progress event streams with spinner, component-tree rendering, settings wiring.
- **rpi-ext-statusline** (rpi-native, TE12): a Claude Code-compatible scriptable custom statusline — a top-level `statusLine` key in the global settings.json configures a shell command; the plugin feeds the session data to it on stdin following the CC JSON contract (model/cost/context_window/effort/session, …) and renders its stdout (multi-line + ANSI) as the footer. Two placements: `replace` (default — replaces the built-in footer entirely) / `status` (appends a status line); event-driven refresh + 300ms debounce + cancellation of in-flight scripts, optional `refreshInterval` timer, `timeoutMs` hard-kill with reaping, last-render retention on failure, and built-in footer restoration when the key is removed. CC community scripts work unmodified (a local `~/.claude/statusline.py` rendered fully with two colored lines in testing); the rpi extension stdin block is `rpi.session_totals`. Zero ABI / zero host changes.
- **Extension ABI gaps closed** (TE01, ADR-0015): `unregisterTool` / `toolUpdate` on both carriers, registerTool capability rejection, own-registry isolation, one wasm Store per extension; fully additive, `RPI_ABI_VERSION` stays 1.

## Upstream alignment with Pi v0.84.1 (T17–T32, pinned 4181f66)

- **rpi-ai**: v0.84 message types and request-option extensions; stream-termination semantics and general streaming fixes; provider adapter fixes and compat extensions; transactional models refresh and OAuth behavior; the auth command family; new providers and model-catalog updates.
- **rpi main paths**: JSON/RPC delta wire format with stdout backpressure; session behavior clusters; resource loading and package-management parity.
- **rpi-agent**: agent-loop micro-behaviors and the compaction contract.
- **rpi-tui**: the renderer trait refactor; a TUI behavior-fix cluster (immediate rendering / grapheme exception table / OSC8 / keybindings / Windows); LaTeX and Mermaid rendering; the layout engine (LayoutNode / Stack solver / ScrollView); the fullscreen renderer (alt screen / mouse / kitty); UI-mode wiring (`--tui-mode` / the `tuiMode` settings key / TuiHandle hot-switch); v0.11 parity freeze.
- **Extension API surface** synced 12 upstream items (ADR-0013 ABI version governance).

## Behavior changes

- **Removed the npm/pnpm/yarn/bun self-update branches** (ADR-0011 revised decision 7, deviation D-055): GitHub Releases binaries are the only distribution channel; the four package-manager branches were unreachable dead code and were removed; `update --self` always performs a true binary self-update. The `npm:` extension-package install channel is unaffected.
- **CI builds now trigger on tags only**: pushes to `main` / `0.*` branches no longer build automatically; `workflow_dispatch` remains for manual runs.

## Fixes

- The main-screen renderer's `panic!` on over-wide rows killed running sessions, and full-width rows drifted into garbled wraps when terminal width disagreed (two incidents: the 2026-08-11 `rpi-crash.log` and the 2026-08-17 "Working..." residue) — over-wide rows now truncate via `slice_by_column` and rendering continues, with the diagnostic snapshot still written to `rpi-crash.log` noting "rendering continued" (a deliberate deviation from upstream's throw, ADR-0020 / D-086); additionally a pessimistic-width conservative truncation — `width_divergence_extra` accounts for risk characters (the ✓ family) that emoji-font fallback renders 2 columns wide, eliminating row drift from "measured full-width but actually wider in the terminal" (T33, no upstream counterpart; eaw=A is a known residue).
- Lone `=` / `-` rows inside `$$` / `\[` formula blocks were parsed as setext headings, cutting formulas apart before they reached math rendering (comrak parses before the renderer's LaTeX recognition; upstream's marked extension runs before the setext rule and never hit this — a difference missed by D-078) — fixed with an equal-length shadow-source rewrite before parsing: lone operator rows inside blocks are replaced with same-length `.` bytes fed to the parser, while render slicing and LaTeX input still use the original source so the lone `=` typesets as part of the formula; after the fix all 5 cases match the upstream tsx run byte-for-byte (follow-up to T29; behavior when `renderLatex` is off is unchanged, registered in D-078).
- LaTeX rendering fell back to raw text for the whole block whenever the upstream symbol table met an unknown command (a single symbol vetoed everything) — `\blacksquare` (the QED proof-end marker, frequent in LLM math output) triggered exactly that. After auditing 270 common macros against the KaTeX list and measuring 78 gaps, they were all filled: 62 symbol mappings (blacksquare/Box/black families/long-arrow tails including mirrors/amssymb negations and strict relations as single macros/miscellaneous ordinaries — mappings follow KaTeX) plus terminal-degraded rendering for parameterized macros and the `subarray` environment (`\xrightarrow[f]{g}` → footnote-style long arrow `⟶_fᵍ`, `\cfrac` as `\dfrac`, `\genfrac` with explicit delimiters, phantom-family monospace-protected space placeholders, `raisebox` drops distance keeps content, rlap/llap drop overlap, `subarray` comma-joins to one line). Upstream does not support these commands either (not a port regression); the 143 upstream ground-truth cases contain none of these forms so parity holds, with new rpi-only assertions (T29 follow-up, D-087).
- Word-level diff's `js_trim` advanced the right trim boundary by byte index `+1`; when a token's final character was multi-byte UTF-8 (Chinese/full-width/accented letters) the slice landed mid-character and rendering any diff containing such content panicked with `not a char boundary`, killing the `rpi-tui-driver` render thread (upstream jsdiff uses JS's native `String.prototype.trim()` and cannot hit this — a port-introduced defect) — now advances by the last character's `len_utf8()`, with multi-byte regression cases, staying byte-identical against the vendored jsdiff 8.0.4 reference vectors.
- Multiple native plugins failed to co-load — root cause was abi_stable memoizing module loads by type; switched to per-path loading.
- SSE line limit aligned to the SDK's ReadBuffer 10MiB — the 8KiB limit introduced during the review wave wrongly swallowed large-line responses (plus a 512KiB cross-chunk regression test).
- Input dead after fullscreen hot-switch, `/settings` hang, `/settings` tui-mode switch hang.
- file_processor test TempDir naming race; bash result-truncation warning line now wraps to terminal width.
