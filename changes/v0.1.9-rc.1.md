# v0.1.9-rc.1 (2026-11-26)

**Pre-release (pre-release channel)**: candidate for the `0.1.9` stable release, published ahead of it for verification. Content matches `changes/v0.1.9.md` (upstream parity to Pi v1.5.2, the streaming-performance and Linux-memory main line, the statusline `estimate` calculation mode, the provider/MCP/coding-agent increments, and the `rpi-subagents` / `rpi-smart-fetch` rebase); at stable-release time this file's entries fold into `v0.1.9.md`. Install: existing rpi users run `rpi update --rc` (or `rpi update --all --rc` to also update the seven lockstep extensions to `0.1.9-rc.1`); install.sh does not serve RCs (`releases/latest` stays stable at `0.1.8`). This RC does not change any registry, schema, model-catalog or version endpoint: those move only in the human-initiated release steps, assets before endpoints (ADR-0042).

## New in this RC (first release of the v0.1.9 window)

- **Upstream parity to Pi v1.5.2** (ADR-0048; behavioral gold standard `b4afdddf`, the v1.5.0–v1.5.2 window folded in): the regenerated models.dev v2 catalog (43 providers, 1815 entries, the new `qwen-token-plan-individual-cn` provider, Azure long-context pricing, GLM allowlists, OpenCode protocol endpoints), Anthropic message threads and per-message effort binding, idle cache warming, provider-reported costs, the OpenAI compatibility controls, strict-tool fallbacks, `rpi auth login|logout`, HTTP(S)-only login URLs, and the bounded MCP/codemode increments. pi-subagents moves to v0.88.1 and agent-smart-fetch to v0.3.23; rpiv-mono stays at v2.15.0. Upstream has since released Pi v1.6.0/v1.6.1 and pi-subagents v0.89.0–v0.90.0; this release stays on the re-confirmed v1.5.2 / v0.88.1 pins, and moving them is a separate ADR for the next version.
- **Streaming performance and Linux memory** (ADR-0049): Markdown/Mermaid/highlight reuse, the incremental tool-argument parser (upstream #9265), the fullscreen transcript height index and viewport window, the cross-frame layout cache and latest-wins render scheduling with adaptive backpressure, the compiled `jsonschema` meta-validator, shared model catalogs, `M_ARENA_MAX=1` and the PNG byte budget. On the release benchmark the main long-history + long-code-answer + fullscreen scenario runs at 38.3% of the v0.1.8 process CPU with pure-compute frame p95 at 44.1% and input-to-visible latency at 5.5%; an empty Linux GNU session uses 60% less resident and 82% less virtual memory, and a long session about half.
- **Statusline**: `statusLine.liveTokens.calculation: auto|estimate` (strict schema, `/statusline` cycle, hot reload), the live session total with `message_end` settlement, the additive O(1) `ctx.sessionStats({countsOnly:true})` watermark probe, incremental token counting for the six bundled tokenizer families and their compact tables (Kimi −71%, GLM −41% resident after load). Under `auto`, the local contribution of a normally completed message now stays in the live total (a display change, not breaking).
- **Coding agent, sessions and TUI**: missing-cwd Continue/Fork/Cancel, bounded `exec`/`read`/`edit`, custom overlay and Markdown transformer surfaces, `capturesViewportInput`, NFC search, and the experimental durable increments (group commit, tagged watch/observer, deferred progress, live v3, bounded transcript windows, read-only modes, `Continue`/`maxTurns`, `afterRun`/`before_provider_request`).
- **Plugin line**: `rpi-subagents` rebased to pi-subagents v0.88.1 (trusted parent-owned recovery, `subagent_launch` approval, retention and cleanup, drain, terminal length/acceptance, owner-scoped list/status/fleet/wait/steer, fork copy layout); `rpi-smart-fetch` rebased to agent-smart-fetch v0.3.23 (compact `fetchSummary`/`batchSummary` details); `rpi-ask-user-question`/`rpi-todo` re-verified against rpiv-mono v2.15.0.
- **Fixed**: long single-word lines wrap in one pass in `rpi-tui` (the `write` preview of a one-line 25–41 KiB file no longer re-wraps ~80,000 scanner calls per streaming delta), plus the durable, catalog-refresh, Bedrock/Gemini, MCP OAuth and provider-retry fixes listed in `changes/v0.1.9.md`.

## Breaking changes in this RC

- **Providers, validation and configuration**: `Model.compat` is `Option<Box<ModelCompat>>` (Rust source break; recompile callers); plain JSON Schema follows the final pi-schema coercion and unresolved-`$ref` behavior (`BigInt`/`Undefined` accepted, `Void` rejected, error paths/messages changed); official Anthropic origins use message threads by default (disable with `compat.supportsMessageThreads: false` or `StreamOptions.disable_continuation`); the default `cacheWarming` mode is `idle`; OpenAI-compatible endpoints omit empty `tools` by default (`compat.requiresToolsWithToolHistory` restores the old behavior; new `promptCacheKeyMode` and `requiresNonNullAssistantContent`).
- **Tools, Markdown and sessions**: `grep` builds its context from ripgrep output and never calls the deprecated `GrepOperations::read_file` default (custom grep implementations change remote results by overriding `AgentTool::execute`); `MarkdownTransformContext` covers `custom`/`summary`/`changelog`, so summary and changelog output can change; missing-cwd sessions require an explicit Continue/Fork/Cancel decision.
- **Durable Rust API migration** (experimental, not source-compatible): ordered-batch `Storage::commit` with `CommitResult`, `Arc` hot reads, tagged watch/observer shapes, `observeCommits`/`DocumentCommitChange`, `FileChange::{Paths,Overflow,Failed}` with stopping watchers, the bounded `ConversationView` window and `ConversationTranscript`, `ConversationHandle::submit` with `WhenIdle::Reject`, `pi.live` v3 / `pi.tool` v3 / `pi.generation` v2 (old readers refuse new records; the next write upgrades v1/v2 data), the single `Report` channel, `Continue` submissions and terminal restart limits. The complete table is in `changes/v0.1.9.md`.
- **Extensions**: background resume/auto-resume requires the parent-owned `recovery.json` and refuses legacy runs; the capability ceiling is keyed by session id; `structured_output` validates the raw value before coercion; smart-fetch persists compact `fetchSummary`/`batchSummary` details; managed-worktree resume refuses removed or out-of-root cwds.

## Verification requests (the point of the RC)

- Self-update on all six targets (`rpi update --rc`: download + sha256 verification + atomic replacement) and `rpi update --extensions --rc` moving the seven lockstep extensions to `0.1.9-rc.1` while a `0.1.8` install keeps working.
- The BREAKING surfaces on real providers: an Anthropic continuation that reuses the thread and one that falls back to a full request; `cacheWarming` staying idle; an OpenAI-compatible proxy that needs `compat.requiresToolsWithToolHistory`; a `Model.compat` caller recompiled against the boxed field; a missing-cwd session's Continue/Fork/Cancel; a custom grep implementation; summary and changelog rendering; the durable crate (`cargo test -p rpi-durable`) and an old rpi refusing a migrated database copy.
- The performance main line on real hardware: long streaming answers in fullscreen over a long history (lower CPU, the adaptive frame rate under load, input staying responsive), `/statusline` switching `auto`/`estimate` mid-stream, and the memory of a long session after `/new` and `/resume` on Linux.
- The plugin line: a legacy background run refused with the relaunch hint, a denied `subagent_launch` approval leaving no side effects, and smart-fetch's compact details in the transcript.

Known boundary: the RC endpoint (`https://revpi.dev/api/latest-rc-version.json`) goes live only after the Release assets are in place; the stable endpoint (`latest-version`), the schema/model-catalog files and the extension registry stay at their current stable values for this RC. Providers, private subscription endpoints and the Windows/pwsh paths were exercised only with offline fixtures/loopback and the CI build environment, not with real accounts or a local Windows machine.
