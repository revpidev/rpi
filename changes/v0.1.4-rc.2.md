# v0.1.4-rc.2 (2026-09-08)

**Pre-release (pre-release channel)**: round two of the `0.1.4` stable candidates, fixing two defects found during rc.1 verification. The baseline content matches `changes/v0.1.4.md`; at stable-release time each rc file's entries fold into `v0.1.4.md`. Install/upgrade: existing rpi users run `rpi update --rc` (or `rpi update --all --rc` to sync extensions to `0.1.4-rc.2`); force-install via the official script with `RPI_GITHUB_API_URL=https://api.github.com/repos/revpidev/rpi/releases/tags/v0.1.4-rc.2`.

## Fixes relative to rc.1 (found in rc.1 verification, rpi#22 / rpi#23)

- **Permanent one-row gap above the editor** (rpi#22): streaming output previously touched the "⠋ Working" indicator embedded in the editor's top border — the ever-present leading `Spacer(1)` that upstream `abb1775ff` (PR #850) added to `widgetContainerAbove` had never been ported with setWidget, and V14-17's embedding exposed it; fixed by seeding a permanent Spacer when widgets_above are constructed (`widgets_below` gets none, matching upstream's spacerWhenEmpty=false).
- **Removed two DBG debug prints on the fullscreen mouse-dispatch path** (rpi#23, a V14-14 porting leftover): after switching an existing session to fullscreen, multiple `[DBG layout dispatch]` / `[DBG selection press]` lines appeared bottom-right, the scrollbar area misrendered, the progress bar got wiped and the input area overwritten — under raw mode + alt screen, direct stderr writes bypass the TUI cursor model and land at the cursor position, and because diff rendering doesn't repaint the overwritten rows the damage persisted; fixed by deleting both debug lines + a structural `deny(clippy::print_stdout/print_stderr/dbg_macro)` guard in the rpi-tui library crate (tests exempt) + two-layer regression tests (trigger sequence at the rpi layer + VT-screen-level per-line assertions at the rpi-tui layer: hot-switch + content beyond viewport + clean scrollbar/dock, screen byte-identical before and after mouse storms).
