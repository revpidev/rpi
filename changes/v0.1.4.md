# v0.1.4 (2026-09-18)

The main line of this release: **upstream parity** — the behavioral gold standard moves from `4181f66` (v0.84.1+) to **`9841914` (v0.85.0+)** (ADR-0023, 698 commits / 866 files +109554/−28676). Eighteen parity tasks (V14-01…18, five domains: agent / ai / coding-agent / tui / ecosystem reconnaissance) restored behavioral parity green item by item with an "upstream anchor → rpi landing → assertion evidence" triple each, and the M5 closeout completed the theme-validation split port (eb3e9feed, retiring the V14-15 carry-over gap) and a full re-record of the fixtures. Zero new ADRs; deviations D-092…D-100 all closed (3 registered, 5 retired, 2 retired-untriggered — see the summary at the end).

The same release folds in three parallel lines (decided 2026-09-08 to include in full): the **plugin rebases** (TE13–TE27, an atomic dual-plugin pin switch: subagents v0.48.0→v0.66.0 / mcp-adapter v2.24.0→v2.32.1, ADR-0025), the **interactive custom-UI ABI** (V14-20–V14-25, native + wasm dual carriers, ADR-0024/0027), and the **new plugin rpiv-ask-user-question** (TE28–TE32, ported from v2.9.0); each has its own section below.

The stable release then went through **sixteen rounds of RC pre-release verification** (`v0.1.4-rc.1`…`v0.1.4-rc.16`, closing the loop on field feedback round by round from 2026-09-08): field-verification fixes are folded into their home sections (the rc.1/rc.3/rc.4 entries under M4, the rc.8/rc.10 dialog-height stabilization under the new-plugin section, and the rc.7 `install --rc` addendum under V14-19); three comprehensive review closures (rc.5's eight-lane deep audit with 1 Blocker + 6 Majors / rc.11's pre-release review / rc.12's five-domain final re-review, the latter two with their own sections); the remaining rounds have their own sections — rc.9's residual pi-identifier de-branding (ADR-0028), rc.13's catalog-only model refresh, rc.14's highlight-engine cross-syntax panic eradication, and rc.15/rc.16's statusline live_output passthrough and frozen decode_ms. The RC channel mechanism itself is V14-19 (M3 section).

- **rc.3 verification fix: settings list value-column alignment** (rpi#24): the "Default thinking level per model" row's value sat 2 columns right of every other row — upstream's `SettingsList` label-column width is `Math.min(36, widest label)` (settings-list.ts:120), but the port had mistyped `min(30)`, and the longest real label is exactly 32 columns, past the 30 cap after which no padding is added; fixed to `min(36)`, verbatim with upstream, with a regression test across the 30–36 column range. **Investigation closure (not a defect, recorded in rpi#24)**: "horizontal rule becomes two rows" after switching fullscreen↔normal was confirmed by exhaustive A/B testing against the pin `9841914` (same key sequences against both binaries in a VT emulator) to be the terminal rendering ambiguous-width characters (`─` U+2500, East-Asian Ambiguous) as 2 columns — normal mode with autowrap on wraps the full border row, fullscreen (`?7l`) doesn't, and **upstream reproduces identically** (a residual risk already recorded in ADR-0020; remedy: set the terminal's Ambiguous width to Narrow); fullscreen being full-bleed with no margins is line-identical with upstream, and per the parity principle no padding was added.
- **rc.4 verification fix: live refresh freezing after hot-switching the display mode ("one keystroke, one frame", confirmed by PTY end-to-end reproduction)**: after switching TUI mode in `/settings` (either direction), all event-driven re-rendering stopped working — streaming replies, the working indicator, and the status bar no longer reached the screen, and only keystrokes forced a frame. Root cause: the `RenderHandle` returned by `TuiHandle::render_handle` froze the **creating renderer's** scheduler into a `Weak`; after `switch_tui_mode` swapped in a new renderer and the old one was dropped, `upgrade()` failed → every event-driven `request_render` silently no-oped and the driver thread stopped refreshing. Fixed by aligning with upstream's `createInteractiveTuiReference` Proxy semantics (tui-renderer.ts:66-96) — the `render_handle` closure now resolves the current renderer through a slot inside TuiHandle **at call time** and marks its scheduler; the `Weak` no-life-extension contract holds (a handle outliving the TUI still safely no-ops). Interactive mode captures the handle once at init and distributes it to all holders (the editor's autocomplete debounce thread / spinner / footer / subscription callbacks) — a single-point fix covers everything; regressions cover both-direction swaps + driver deadline assertions (red with the fix reverted) + PTY end-to-end (a real `/settings` hot-switch followed by streaming replies landing continuously without keystrokes, verified both directions).
- **rc.4 verification fix: keyboard input dying after clicking the editor/selector area in fullscreen** (a companion suspicion from the investigation, settled at unit-test level): after any click on a fullscreen dock editor row, keyboard focus moved to the editor container's **wrapper layer** — `Container::handle_input` is a no-op, so all subsequent keys were swallowed (transcript-area clicks were unaffected). Root cause: upstream's `Container.prototype.handleMouse` (tui.ts:355-358) forwards via `dispatchMouseEvent(child)` and leaves `focusTarget` to the **child component**, while the ported `Container::handle_mouse` returned only the bare result, so the outermost dispatcher pinned focus to the container entry. Fix: `SharedEntry::handle_mouse` now resolves via `dispatch_mouse_event(self.0)` (`Forwarded` passthrough, same shape as mouse-region.ts:26) — the gesture and focus targets return to the inner shared component; regression covers a 4-column × full-row click matrix over a 24-row terminal's dock area + per-cell keypress assertions (rows 20-24 went red across all columns before the fix) + PTY end-to-end (fullscreen start → transcript/editor-row/per-row clicks → all input probes echoing).

## statusline live_output raw-material passthrough (rc.15)

- **Raw-material passthrough for script-side language-aware token counting** (#45; `rpi-statusline`, PR #49): `rpi.live_output` previously exposed only aggregated character counts, forcing scripts to convert with a single chars/token factor (Chinese ~1.0–1.3 vs English/code ~3.5–8 chars/token, biased both ways, with the calibration factor drifting with the most recent message's language). Investigation confirmed the host had long been delivering the raw material into extension events (the `message_update` payload carries the accumulated partial verbatim — full text blocks + `usage`; both OpenAI-compatible chunk usage and Anthropic `message_delta` running totals land at `/message/usage/output`), and the plugin had merely counted characters and dropped it. The fix retains and passes it through: `live_output` gains 6 additive fields — `output_tokens` (provider-accumulated during the stream, present only when >0, never rewritten on silence), `text`/`thinking`/`toolcall` (the current message's accumulated raw text, identity-to-`*_chars` pinned by invariant tests), `decode_started_at_ms` (the first delta's wall-clock anchor, TTFT excluded), and `message_id` (plugin-local monotonic, changing per message). Chosen accumulated raw text over per-tick deltas (scripts are stateless processes re-run per invocation, V13-10 §1.2); the native-measures-but-never-converts red line holds (language-aware estimation lives entirely on the script side); `peek_fingerprint` now includes streaming usage and the message sequence number. Zero changes to the host/ABI/subscription set/wire protocol; the original 8 fields stay byte-identical; behavior without `liveTokens` configured is exactly as in TE12. Gates: `cargo test -p rpi-ext-statusline` 52 unit tests + 3 integration binaries green, clippy/fmt clean.

## statusline live_output frozen decode_ms (rc.16)

- **Decode-duration passthrough for stateless tok/s** (#50; `rpi-statusline`, PR #51): after rc.15's raw material, the payload still lacked the decode duration — `message_end` froze `elapsed_ms` without clearing the anchor, so idle ticks kept drifting on `now − decode_started_at_ms`, and precise tok/s scripts had to persist three classes of per-session state (TTFT `max()` back-derivation, frozen-denominator caching + just-ended detection, and `message_id` boundary detection); the resume-changes-id orphan and reused-id stale-rate failure modes both really happen. The fix passes through one number absorbing all three: `decode_ms` = first delta→now (streaming, live) / first delta→end (frozen after `message_end`; idle ticks recompute the same value from an unchanged payload), **always present, 0 before the first delta** (aligned with the `delta_ms`/`elapsed_ms` duration discipline — scripts can index unconditionally); TTFT becomes the same-clock, same-instant difference `elapsed_ms − decode_ms` — durations measured with `Instant` twin anchors (set at the same instant as the wall-clock anchor, which is kept serving `decode_started_at_ms`), `snapshot` sampling the same `now` as `elapsed_ms`, the frozen value captured at the same event instant, monotonic across wall-clock jumps (also revising the issue snippet's `SystemTime::elapsed()` `Result` compile error and its "omitted" semantic contradiction — see the issue comment). Boundaries: a no-delta abort → 0; a lost `message_end` self-heals; `peek_fingerprint` needs no inclusion. Zero changes to the host/ABI/subscription set; the original 15 fields stay byte-identical; behavior without `liveTokens` configured is exactly as in TE12. Gates: `cargo test -p rpi-ext-statusline` 54 unit tests + 3 integration binaries green, clippy/fmt clean.
