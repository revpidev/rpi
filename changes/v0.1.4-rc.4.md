# v0.1.4-rc.4(2026-09-08)

**预发布(pre-release channel)**:`0.1.4` 正式版候选第四轮,修复 rc.3 验证发现的两项热切换/全屏交互缺陷(独立排查双确认:PTY 端到端复现 + 单测级定论)。基线内容与 `changes/v0.1.4.md` 一致;正式版发布时各 rc 文件条目并入 `v0.1.4.md`。安装/升级:已装 rpi 用户 `rpi update --rc`(或 `rpi update --all --rc` 同步扩展到 `0.1.4-rc.4`);官方脚本强装 `RPI_GITHUB_API_URL=https://api.github.com/repos/revpidev/rpi/releases/tags/v0.1.4-rc.4`。

## 相对 rc.3 的修复(rc.3 验证发现)

- **热切换显示模式后实时刷新卡死——「按一次键刷一帧」**(PTY 端到端复现确认):`/settings` 切换 TUI 模式(任一方向)后,事件驱动的重渲染全部失效,流式回复/工作指示器/状态栏不再上屏,只有按键才补一帧(输入分发路径的即时渲染),表现为「输入卡死」。根因:`TuiHandle::render_handle` 返回的 `RenderHandle` 把**创建时渲染器**的调度器冻进 `Weak`——`switch_tui_mode` 换装新渲染器后旧渲染器被丢弃,`upgrade()` 失败 → 每次事件驱动的 `request_render`(agent 消息更新/订阅回调/spinner 定时器/footer)静默 no-op,新渲染器 `next_deadline` 恒为 `None`,驱动线程不再主动刷帧。修复:对齐上游 `createInteractiveTuiReference` Proxy 语义(tui-renderer.ts:66-96)——`render_handle` 闭包改为**调用时**经 TuiHandle 内槽解析当前渲染器并标记其调度器;`Weak` 保持不续命契约(句柄长于 TUI 时仍安全 no-op)。该句柄由 interactive mode 在 init 一次性捕获并分发到全部持有方(editor 自动补全 debounce 线程、spinner、footer、订阅回调),单点修复全覆盖。回归:`render_handle_reaches_the_renderer_swapped_in_later`(rpi-tui,双向换装 + 驱动 deadline 断言,还原修复前变红)、`switch_tui_mode_render_requests_reach_swapped_renderer`(rpi,事件路径);PTY 端到端:真实 `/settings` 热切换 → 无按键流式回复连续上屏,双向验证通过(修复前复现「回复缺失直到按键」)。
- **全屏下点击编辑器/选择器区域后键盘输入死亡**(排查伴生疑点单测定论):全屏模式对 dock 编辑器区域任一行左键 click(press+release 合成 click)后,键盘焦点被移到编辑器容器**包装层**——`Container::handle_input` 为 no-op,此后所有按键被吞(转录区点击不受影响)。根因:上游 `Container.prototype.handleMouse`(tui.ts:355-358)经 `dispatchMouseEvent(child)` 转发并把 `focusTarget` 留给**子组件**(plain Container 无 `handleInput` 不接管),移植的 `Container::handle_mouse` 只回传裸结果,最外层派发器把焦点钉到容器入口;而 `SharedEntry` 正是为保住子组件共享身份(焦点目标)而设。修复:`SharedEntry::handle_mouse` 改为经 `dispatch_mouse_event(self.0)` 解析(`Forwarded` 透传,mouse-region.ts:26 同型)——手势目标与焦点目标回到内层共享组件,编辑器/选择器点击后键盘继续可用。回归:`fullscreen_left_click_across_dock_keeps_editor_focus_and_input`(rpi,24 行终端 dock 区 4 列 × 全行点击矩阵 + 逐格按键断言,修复前 row 20-24 全列变红);PTY 端到端:全屏启动 → 转录区/编辑器行/逐行点击 → 输入探针全部回显。
