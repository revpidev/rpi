# v0.1.4-rc.10 (2026-09-12)

**Pre-release (pre-release channel)**: round ten of the `0.1.4` stable candidates. This round = **the ask-user-question dialog height-stability second-round fix** (rc.9 field report: ① total height jumps when focus moves to the "Type something." row; ② the Submit page's footer hint row floats far from the terminal bottom). The baseline content matches `changes/v0.1.4.md`; at stable-release time each rc file's entries fold into `v0.1.4.md`. Install/upgrade: existing rpi users run `rpi update --rc` (or `rpi update --all --rc` to sync extensions to `0.1.4-rc.10`); force-install via the official script with `RPI_GITHUB_API_URL=https://api.github.com/repos/revpidev/rpi/releases/tags/v0.1.4-rc.10`.

## Increments relative to rc.9

- **Dialog height stability, round two**: ① focusing the "Type something." row enters input mode and hides the markdown preview pane, but worst-case height probing had used the current frame's input-mode, collapsing the padding baseline with it — total height flip-flopped as focus moved between the input row and option rows (measured 21→13 rows on a preview-bearing question). Probing now always computes in non-input mode (input-mode body is provably ≤ preview-mode body), the padding absorbs the difference, and total height stays constant. ② The residual padding was appended after the footer hint row (upstream hides it beneath its own bottom border, visually invisible; rpi has no border and the overlay is bottom-anchored, so the hint got pushed N blank rows away from the terminal bottom — the Submit page measured 13 rows of float) — the padding is now inserted before the footer block: total height unchanged, the hint is always the dialog's last row hugging the terminal bottom edge; on the Submit page the picker-focus/notes-cursor anchors below the padding shift along with the insertion. The 12 golden frames were re-recorded (padding relocated, total height unchanged); invariant tests pin it down (input-row-focused height constant across both layouts, hint at the bottom, Submit cursor translation).
- The layout detail deviation is registered under the TE-D40 "height equalization" row.

## Verification requests (rc.10 focus)

- **Footer hint hugging the bottom** (re-checking rc.9 item ②): in a multi-question questionnaire, switch to the Submit page — the "Enter to select · … · Esc to cancel" hint row should hug the terminal bottom edge with no blank band below; likewise when a question tab / the input row / the notes editor is open.
