# v0.1.8-rc.2 (2026-11-04)

**Pre-release (pre-release channel)**: the second candidate for the `0.1.8` stable release, carrying the fixes found while verifying `0.1.8-rc.1`. The rc.1 feature set (upstream parity to Pi v1.4.0, the issue line #72/#73/#76, the durable runtime/storage increments, the extension/session/settings family, and the TE51–TE53 plugin rebase) is unchanged; at stable-release time this file's entries fold into `changes/v0.1.8.md`. Install: existing rpi users run `rpi update --rc` (or `rpi update --all --rc` to also move the seven lockstep extensions to `0.1.8-rc.2`); install.sh does not serve RCs. No registry, schema, model-catalog or version-endpoint change is part of this RC.

## Fixed in this RC

- **A message submitted while the model is streaming now shows up immediately** (interactive mode): typing a message and pressing Enter during a response used to produce nothing anywhere — no steer, no `Steering:` row, no transcript entry — until the run finished (or Escape aborted it), so queued input looked swallowed. The run loop awaited `session.prompt` for the whole run, leaving the new submit unread in the input channel; upstream runs the prompt from the editor submit callback (`interactive-mode.ts:3319-3340` @ `4a080252f`) and keeps the loop free. The prompt now runs spawned (`spawn_prompt`, with the shutdown race and the error surface kept), so the queue update and the `Steering:`/`Follow-up:` rows plus the `Alt+Up to edit all queued messages` hint render mid-stream, and `Alt+Enter` follow-ups behave the same. Regression: `submit_while_streaming_queues_the_steer_before_the_run_ends` (paced faux provider; fails when the prompt is awaited again).
- **Terminal size comes from stdout, not `/dev/tty`** (rpi-tui): `ProcessTerminal` queried `crossterm::terminal::size()`, which opens `/dev/tty` first, while upstream reads `process.stdout.columns/rows` (`terminal.ts:553-559`). When stdout is a pty that is not the process's controlling terminal — nested pty harnesses, wrappers that allocate a pty without `setsid`+`TIOCSCTTY`, some IDE/CI terminals — the fullscreen frame was laid out for the wrong screen (a 42-row frame on a 34-row terminal), the transcript ate the dock rows and the editor's content row, where typed input appears, was pushed off-screen during streaming. The default query now runs `TIOCGWINSZ` on fd 1 (Windows keeps crossterm's stdout console query); the off-tty `COLUMNS`/`LINES`/`80x24` chain is unchanged and the no-tty `tput` guard still holds. Regressions: `default_size_query_reads_stdout_fd_not_dev_tty` and `winsize_of_reads_the_requested_descriptor`.
- **Status line live rows keep their value and their color** (`rpi-statusline` items mode): a live row with no fresh reading — the gap between two assistant messages, the rate window before it is stable, a tier the current message has not produced yet — fell back to a muted `-` placeholder, so the footer flipped to a dash and back between responses and the dash lost the success color of the numbers it stands in for. The plugin now holds the last measured value per live row (only fields with a real measurement are stored; the cache clears when `liveTokens` is disabled or a session starts), renders the placeholder in the field's own tone, and never holds `streaming` (a real gap must not claim a stream is running). Regressions: `live_rows_keep_the_last_measured_value_until_refreshed`, `live_rows_keep_dash_placeholders_while_armed` (the success SGR is asserted) and the items integration's between-messages frame assertion.

## Verification requests (the point of this RC)

- Streaming submit: start a long response, type a message, press Enter — the `Steering:` row and the dequeue hint must appear immediately; `Alt+Up` must pull the text back into the editor; `Alt+Enter` must add a `Follow-up:` row. Let the run finish: the queued message lands exactly once, in order.
- Terminal sizing: run rpi under a pty harness (or any wrapper whose stdout pty is not the controlling terminal), resize the pty and confirm the frame follows the pty size; type while output streams and confirm the characters stay visible.
- Status line: idle `- · - tok/s` in the success color; numbers refresh while streaming; between two responses the previous numbers hold instead of flipping to `-`.

Known boundary: the RC endpoint (`https://revpi.dev/api/latest-rc-version.json`) goes live only after the manually started Release build has uploaded the assets; the stable endpoint (`latest-version`), the schema/model-catalog files and the extension registry stay at their current stable values for this RC. The remaining rc.1 verification items (real-account usage-provider smoke, Windows/pwsh paths, the durable crate's experimental boundaries) are unchanged.
