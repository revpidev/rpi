# v0.1.6-rc.3 (2026-10-06)

**Pre-release (pre-release channel)**: candidate for the `0.1.6` stable
release. Content = `v0.1.6-rc.2` plus the pre-stable fix below. Upgrade:
`rpi update --rc` (or `rpi update --all --rc` to also move the eight lockstep
extensions to `0.1.6-rc.3`); `install.sh` does not serve RCs
(`releases/latest` stays stable). The two new first-party plugins install
from the RC channel with `rpi install rpi-plan-mode --rc` and
`rpi install rpi-usage --rc`.

## Fixed in this RC

- **Built-in MCP (ABBA deadlock)**: a server still connecting when the first prompt dispatched `before_agent_start` could deadlock the interactive run loop — Enter did nothing (the user message was never persisted, so no session file was created) and Ctrl+C could not quit (the run loop never reached the shutdown watch). `pending_servers` (and the other server-list readers) held `servers` while locking each server's `entry`/`connection`/`ready`, while the connection callbacks held `server.connection` across `register_tools`/`on_connection_change` (the `if let` temporary-guard lifetime) — and those take `servers` and make synchronous host calls. The readers now snapshot `servers` before per-server locks and the callbacks clone the connection out of its lock first. The same guard-lifetime class is fixed in `reconnect`/`sign_out` (a guaranteed self-deadlock through `drop_client` re-locking `self.client`) and `hide_tools` (a synchronous `registerTool` host call under the `tools` lock). Per-fix detail: `changes/v0.1.6.md` §Review hardening → "Pre-stable fix (v0.1.6-rc.2 verification)".
