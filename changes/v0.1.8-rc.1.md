# v0.1.8-rc.1 (2026-11-03)

**Pre-release (pre-release channel)**: candidate for the `0.1.8` stable release, published ahead of it for verification. Content matches `changes/v0.1.8.md` (upstream parity to Pi v1.4.0, the issue line #72/#73/#76, the durable runtime/storage increments, the extension/session/settings family, and the TE51/TE52/TE53 plugin rebase); at stable-release time this file's entries fold into `v0.1.8.md`. Install: existing rpi users run `rpi update --rc` (or `rpi update --all --rc` to also update the seven lockstep extensions to `0.1.8-rc.1`); install.sh does not serve RCs (`releases/latest` stays stable at `0.1.7`). This RC does not change any registry, schema, model-catalog or version endpoint: those move only after the manually started build has uploaded the assets.

## New in this RC (first release of the v0.1.8 window)

- **Upstream parity to Pi v1.4.0** (ADR-0038; behavioral gold standard `4a080252f`, the v1.2.0–v1.4.0 windows folded in): provider catalog refresh (42 catalogs / 1718 entries, Kimi K3.1 Pro, MiniMax M3.1 Flash, Grok `xhigh`, corrected Codex context windows), the OpenCode `/inference` and OpenRouter per-key catalog transports, shared compatibility/identity/auth-origin handling, the classifier and tool-argument fix families, the typed configuration schemas served at `revpi.dev/schemas/`, coordinated settings writes, resumed-session tool loadouts, compaction summaries without fixed output caps, the codemode/MCP increments (declaration constraints, worker capacity, arbitrary `structuredContent`, resource capability reporting, OAuth `iss` fail-closed), the TUI/CLI/platform fix family (CJK Markdown, terminals, clipboard process groups, print-mode output limits, `rg --no-config`), and the CJK-friendly HTML export assets. Per-domain summaries and anchors are in `changes/v0.1.8.md`.
- **Issue line #72/#73/#76** (V18-07–V18-09): the per-model thinking override now applies when a session resolves its initial model (`--thinking` and a resumed session still win; `medium` still applies to provider defaults); `/export`, `/import` and `/compact` carry their arguments again (`/import` was a v0.1.7 regression and `/export` could not reach its `.jsonl` branch); the `/model` search highlights the best match on row 0 and a background catalog refresh re-applies the query, with the persisted default model sorted right after the current one.
- **Durable runtime and storage** (`rpi-durable`, experimental): SQLite schema v2 plus namespaced storage, the portable driver/migration layout under `chord/sqlite`, the 25-case storage conformance matrix, `sleepUntil`/timers/`wake`/`onWake`, crash-loop restart limits, Task v2 with `sleeping`, nested `executeTool` calls with structured output, deterministic code-mode replay and guarded storage, document retention, task-graph blocked reasons, and content-free telemetry spans. The default CLI path still does not depend on the crate.
- **Extensions, session and settings**: additive host calls `ctx.sessionStats`, `ui.emitText`, `ui.emitStructured`, `ui.hasOverlay` and `ctx.usage.cached`/`fetchDetailed` (all `rpiAbi: 1`), the extension startup/busy/dialog-stack semantics, tool reachability declarations and namespace aliases, wrap-not-truncate extension status rows, `/share` honoring `sessionShareDestination`, and the removal of the retired mcp-adapter's startup/update guidance without deleting user files.
- **Plugin line**: `rpi-subagents` rebased to pi-subagents v0.83.0 (fail-fast overrides, long-running guard, project-trust boundaries, the built-in `workflow:"parallel"`, foreground/composite run history and per-index resume, chain step settlement, bounded post-final compaction and steer drains); `rpi-ask-user-question`/`rpi-todo` rebased to rpiv-mono v2.15.0 (compact receipt, `toolCallId` answer channel, batch create, replay guards); `rpi-statusline` gains the 21-field declarative items mode and `/statusline` editor; `rpi-usage` ships eight typed providers, the `/usage` command grammar, the typed footer and the local-session-token fallback. The seven `.rpix` archives ride this Release with the pack-time `minHostVersion` (`0.1.8-rc.1` for this RC; `0.1.8` at the stable fold).

## Breaking changes in this RC

- **Durable storage and API** (V18-05/V18-06): opening a version 1 durable SQLite database migrates it to schema v2 (the `sleeping` status), after which rpi 0.1.7 and earlier cannot open it — keep a copy before opening a valuable database with this build. `pi.tool` is version 2 with a tagged `ToolTaskInput`/`ToolTaskResult` (`kind: "model" | "nested"`), `ToolExecutionResult.content` is now `output` with `structuredOutput` beside it, `StorageRejected` is replaced by `StorageRequestError` plus session failure, `TaskRuntime.sleep()` is replaced by `sleepUntil`, `defineDoc()`/`defineDocFamily()` require `checkpointWhen`, `ToolControl.terminate` is a boolean, `HarnessOptions.models`/`settings` accept functions, and external `ToolExecutionApi`/`CodemodeHost` implementations must add `create_task`/`idle` (hand-written Harness fakes must also add `sleepUntil`/`setTimer`/`now`). JSONL needs no migration.
- **Kimi Code transport and configuration** (V18-01): the provider uses OpenAI Chat Completions and requires an explicit `/v1` in a custom `baseUrl` (`https://api.kimi.com/coding/v1` is the built-in endpoint); a legacy `https://api.kimi.com/coding` override is rejected before any request with the provider, model, configuration key and a migration example. rpi never appends the suffix or falls back to the old transport.
- **Extension startup and dialog behavior** (V18-02, ADR-0044): `before_agent_start` carries `messageType:"user"|"custom"` and also fires for idle `sendMessage(..., { triggerTurn: true })`; the session is busy from setup; concurrent dialogs stack, and overlays from different owners can stay mounted together. Handlers that assumed the previous untyped payload or replace-on-open dialogs must be updated.
- **Subagent configuration and history** (TE51): `subagents.*` and the agent override maps reject unknown fields and an illegal `thinking` value at load or write time instead of degrading silently, an agent `tools` entry using `+name`/`-name` is rejected, a replace-mode child no longer inherits `APPEND_SYSTEM.md`, upstream's retired `run-history.jsonl` is neither written nor read, and only the current child-directory layout can be resumed (an older layout is reported as unrecoverable, not migrated). Existing history files are not deleted.

## Verification requests (the point of the RC)

- Self-update on all six targets (`rpi update --rc`: download + sha256 verification + atomic replacement; Windows gets manual-replacement instructions), and `rpi update --extensions --rc` moving the seven lockstep extensions to `0.1.8-rc.1` while a `0.1.7` install keeps working.
- The four BREAKING surfaces: the Kimi `/v1` diagnostic and a successful Kimi request, the schema v2 database upgrade on a disposable copy (old rpi must refuse the migrated file), the extension `before_agent_start` union plus two simultaneous dialogs/overlays, and a subagent config with an unknown override field / illegal `thinking` / `+name` tools entry failing with its path and field.
- The durable crate: `cargo test -p rpi-durable` (conformance, sleeping, replay, telemetry) and the default CLI path still not depending on `rpi-durable`.
- The plugin line: `/statusline` items + editor, `/usage` with `--cached`/`--json`/`list`/`help` and a provider without a quota script showing the local-session report, `--offline` running zero usage scripts, and the subagent guard/`parallel`/resume paths on a real install.
- The v0.1.7 MCP OAuth issuer deferral is closed: a sign-in whose authorization response carries `iss` but has no discovered authorization-server metadata fails closed before any token request.

Known boundary: the RC endpoint (`https://revpi.dev/api/latest-rc-version.json`) goes live only after the Release assets are in place; the stable endpoint (`latest-version`), the schema/model-catalog files and the extension registry stay at their current stable values for this RC. Real private-subscription endpoints and the Windows/pwsh paths were exercised only with offline fixtures/loopback and the documented CI environment, not with real accounts or a local pwsh.
