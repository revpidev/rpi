# v0.1.9 (2026-11-26)

This release moves the behavioral gold standard to Pi v1.5.2 (ADR-0048) and re-bases the first-party `rpi-subagents` and `rpi-smart-fetch` extensions, and it makes streaming performance and Linux memory the main line (ADR-0049). On the release benchmark the long-history + long-code-answer + fullscreen scenario runs at 38% of the v0.1.8 process CPU with pure-compute frame p95 at 44% and input-to-visible latency at 5%; an empty Linux GNU session uses 60% less resident and 82% less virtual memory, a long session about half; the statusline gains the `estimate` calculation mode. Breaking changes below cover validation semantics, provider defaults, the `Model.compat` Rust representation, Markdown transformer surfaces, missing-cwd sessions, grep context, the experimental durable Rust API and the extension rebase. Every v0.1.9 host-call is additive and `rpiAbi` stays `1`.

## Main line

- **Upstream parity to Pi v1.5.2** (ADR-0048): the behavioral gold standard moves from `4a080252f` (v1.4.0) to `b4afdddf` (v1.5.2). The regenerated models.dev v2 catalog contains 43 providers and 1815 entries (1667 chat, 72 image, 76 classifier), with the target default model table, Azure long-context pricing, GLM allowlists, OpenCode protocol endpoints and a new `qwen-token-plan-individual-cn` provider (`QWEN_TOKEN_PLAN_CN_API_KEY`). The generated manifest is timestamped `2026-11-17T03:17:54.693Z`; all 43 provider model lists match rpi-pages after unwrapping the site's public `models` envelope. The structure hash is `c1439edeb0ae1a09ff4bb9e486b53253994d702d8ded8588cc6b717a29912e0f`.
- **Schema and startup memory** (ADR-0049): `jsonschema` is pinned to 0.61.2 with its public `macros` feature, so native models/settings validators use the compiled meta-validator without initializing the dynamic global meta-validator. Built-in catalog generations share immutable model data with copy-on-write overrides. On 64-bit, `Model` shrinks from 1064 to 480 bytes and `AnyModel` from 1064 to 904 bytes.
- **Linux malloc arenas** (ADR-0049): `rpi` and `rpi-rpc` set glibc's `M_ARENA_MAX` to 1 before argument parsing or runtime/worker creation on Linux GNU. `MALLOC_ARENA_MAX=<positive 32-bit integer>` remains the sole override; invalid values warn and fall back to 1. The default uses `mallopt` rather than an environment write, so tool children do not inherit it. Other operating systems and libc implementations are unchanged.
- **Providers and authentication**: Anthropic message threads and per-message effort binding, idle cache warming, provider-reported cost attribution, OpenAI compatibility controls, per-session strict-tool fallback, OpenRouter BYOK/latest aliases and safer context clamps, Kimi K3.1/GPT top-level tool metadata, Bedrock/Gemini schema fixes, Microsoft-Decision-1 through GitHub Copilot's `/v1/systemone`, structured refresh warnings, HTTP(S)-only login URLs opened without a shell (including Windows `rundll32`), private auth files and lock identity, and credential-write draining at shutdown. Transport errors retain their source chain and llama.cpp names its server.
- **MCP and codemode**: bounded JSON/SSE/error bodies with connection drop on overflow, linear SSE and stdio framing with close cancellation and process-group/direct-child cleanup, caller-owned `McpPipe`, two-phase OAuth with refresh-only reuse, prompt cancellation with background token persistence and lock classification, shared tool naming/schema/output-limit/config helpers, local JSON Pointer resolution with malformed-escape handling, and console/thrown `NaN`/`Infinity` output instead of `null`.

### Coding agent, sessions and TUI

- **Authentication and packages**: `rpi auth login|logout <provider>` supports API-key, no-browser, device and copy-code flows, with Radius sharing the MCP credential writer. Startup update notices carry previous/next version-or-commit and a changelog source, collapse per package, and remember last-seen versions through `extensionChangelogVersions`.
- **Session reliability**: missing interactive cwds offer Continue/Fork/Cancel; Continue is non-persistent, while startup Fork creates a new ID under the current cwd and resume/import Fork uses the current session directory. Print/RPC retain `MissingSessionCwdError` and never auto-continue. Disk-write failures roll back in-memory entries, branch metadata keeps live thinking levels, and summaries use current context edits/auth without hidden or failed originals.
- **Tools and lifecycle**: `exec` adds bounded `maxBuffer` output with `truncated`, UTF-8-safe accumulation and process-tree termination; `read` adds optional chunk streams, bounded regular-file windows and special-file EOF handling; `edit` generates normalized source-span diffs before writing while preserving mixed line endings; grep builds its context from ripgrep output only. Bash separates shell exit from output timeout, prompt images share a serial resize queue, shutdown settles results before extension disposal, and exports include deep histories plus system prompt/tool updates.
- **Interactive and terminal**: custom overlays aggregate visible/hidden blocked bitmaps and receive key text/hints; Markdown transformers accept `custom`/`summary`/`changelog` contexts with optional `messageId`/`timestamp`, shared by assistant, summary and changelog surfaces. Mermaid supports pie, author styles and clickable labels without claiming every third-party Mermaid boundary. Component frames add optional `capturesViewportInput` and renderer options add keybinding hints, while `Component::render` and `rpiAbi=1` remain unchanged. Search covers NFC Unicode, name/full-name weighting and local `$ref` expansion with cycle safety; UAX #29 tokenization is not presented as every `Intl.Segmenter` dictionary behavior.
- **Experimental durable stack**: Session Writer group commit with ordered multi-batch storage and `CommitResult`, shared `Arc` hot reads, SQLite prepared-statement/read caches and bounded outcome queues; tagged watch/observer calls, address-stable retire/recreate and 10,000-op collapse; deferred progress with bounded Append deltas and read/write/deadline/close flushes; live v3 migrations, bounded transcript windows, read-only Session/Harness/JSONL modes, incremental scheduler indexes, crash/retry recovery and terminal restart limits. `read` declares text/image structured output for codemode (including an image note) with journaled replay. `Continue`, `maxTurns`, raw entry ranges, `afterRun` child draining and ordered provider-payload hooks are implemented, while default CLI isolation, Session JSONL outer framing and cumulative extension events are unchanged.

### Markdown, Mermaid and rendering reuse

- **Mermaid fast path**: the built-in transformer scans for a fenced `mermaid` info word before parsing and returns the source unchanged when none exists (zero comrak parses). Its transform result is cached for the current source, width, message type, streaming flag, rendering mode, theme fingerprint and terminal-capability generation with a bounded entry/byte LRU; third-party transformers keep their per-render execution. The candidate scan is conservative: container-prefixed tabs and a case-insensitive word fallback are accepted, so a real diagram is never missed; false positives only run the normal parse and leave the source unchanged.
- **Assistant slots**: each visible text/thinking block keeps one Markdown instance at its position and kind and updates it with `set_text()`. The streaming flag is read lazily, so the same instance survives the stream end. Updates copy only visible text/thinking, stop/error and tool presence out of the live-message lock; tool-only deltas never deep-copy tool arguments.
- **Block and highlight reuse**: Markdown keeps a bounded current/previous generation of top-level rendered blocks. Unchanged blocks are not converted, wrapped or highlighted again; reference definitions anywhere in the document (including blockquotes and list items, labels that span lines, and nested containers with any indentation) disable block reuse, detected outside the parsed code-block ranges and with escaped closing brackets; duplicate raw blocks respect their next-token spacing; code blocks reuse highlighted lines across resizes and spacing changes. Source, transformed text and rendered lines share `Arc` ownership.
- **Revision contract**: `Component::cache_revision()` is an additive default-`None` method with monotonic revisions for Markdown, Text and Spacer and aggregation for assistant messages. `CodeHighlighter` keys on a monotonic theme generation, with the theme pointer only as a secondary check; `Image` revisions also track transcoder registration. Containers whose children are publicly mutable keep returning `None`.
- **PNG byte budget**: the conversion cache keys on a construction-time 256-bit content digest with prefix/suffix collision checks, shares converted data with `Arc`, and enforces the existing 32-entry limit plus an 8 MiB total-byte LRU. Eviction only drops derived PNGs; session images and Kitty behavior are unchanged.

### Streaming tool arguments

- **Shared incremental parser**: a Rust port of upstream #9265's `StreamingJsonParser` / `ToolCallArgumentsStream` reads each argument delta once. `snapshot()` returns an immutable tolerant value, while the authoritative final arguments still come from one strict `parse_tool_call_arguments` at block close. For JSON function arguments, the 33 ms preview cadence gates materializing `block.arguments`; grammar/custom input keeps its per-delta update (bounded by the input length).
- **Provider coverage**: Anthropic, Bedrock ConverseStream, OpenAI Completions, OpenAI Responses (including Codex/Azure), Mistral, rpi-messages, faux and the agent proxy keep one parser per tool call in stream state, so raw argument text never reaches content blocks or partial messages. Grammar/custom tool input appends deltas and closes explicitly; pi-messages accepts only the next or an existing `contentIndex` and rejects skipped or huge indices.
- **Preview variant (D-112)**: the streaming preview follows upstream #9265 — an open string keeps trailing whitespace, raw control characters and invalid escapes visible; malformed literal or number suffixes, numbers beyond the `f64` range and missing or extra commas/colons (including a value where a key is expected, or an empty array containing blanks) follow the upstream tolerant rules; an exponent marker with a sign but no digits yet shows its mantissa whatever the case of `e`/`E`; and a very large open container may lag until its copy credit catches up. Complete valid documents are unchanged; the strict final parse still rejects invalid JSON, non-objects, out-of-range numbers and schema failures before any tool runs.

### Viewport virtualization and render scheduling

- **Transcript height index**: fullscreen transcripts are measured through a height index instead of a full render. The additive `Component::as_transcript_document()` (default `None`) lets a scroll child expose its blocks; `Container` implements it and nests through the application's region wrappers, so the document's header, loaded-resources and chat regions flatten into one block sequence. A block is measured once per `(instance id, revision, width)`; the additive `Component::cache_instance_id()` gives trusted blocks a process-unique identity, so a replaced block can never be served the cached lines of the block it displaced, not even when the allocator reuses the old address. Blocks without the identity protocol keep a per-frame local render that is counted as a bounded fallback and never disables virtualization for the rest of the transcript. The retained line set is bounded (256 blocks / 16,384 rows beyond the working set); appends touch the tail only, a width change re-measures once, and `invalidate()` drops it.
- **Viewport window**: the scroll child carries only the viewport plus a 16-row overscan. The full-text consumers read everything else on demand: scrollbar geometry from the height index, OSC 133 prompt jumps from a prompt index kept with the heights, search from a lazy full-text corpus cached per content stamp and released a frame after its last consumer, selection/copy and Kitty residual crops from row ranges. Regular mode keeps its whole-content render and `previous_lines` diff unchanged.
- **Cross-frame layout cache**: the layout engine keeps a renderer-owned `LayoutRenderCache` behind its frame-local cache. Entries are keyed by component address, width, revision and a frame generation, hold their owner (a hit also requires `Arc::ptr_eq`), and are bounded by an LRU; invalidation, layout-root swaps and restarts clear it and removals drop their entries. Components without a trusted revision still render every frame and are never stored.
- **Latest-wins scheduling with adaptive backpressure**: every render request bumps a generation, and a request that arrives while a frame is pending is folded into that frame (counted), so slow frames never queue stale intermediate frames; renders owed to message_end, resize, theme and the final invalidate are always delivered — input and resize frames are latency-class at the 16 ms baseline, the others wait at most one tier interval — and forced renders are immediate. The minimum render interval follows the measured frame cost — 30 fps above 16 ms, 20 fps above 33 ms, recovering one tier after 30 cheap frames. The thresholds are internal constants; there is no new setting.
- **Benchmark harness**: `run_suite.py --suite backpressure` runs the CPU scenarios in the throttled render mode (adaptive tiers enabled, input-driven frames measured on the real schedule) and reports tier frame counts, folded requests, latency promotions and frame intervals separately from the fixed-cadence CPU gate; each frame event carries the schedule state.

### Statusline calculation, live total and tokenizer

- **Calculation policy**: `statusLine.liveTokens` accepts an optional `calculation` of `auto` (default; the previous Provider → bundled tokenizer → CJK heuristic order) or `estimate` (always the lightweight Han/other heuristic while streaming, every total/tier/rate value marked `~` even when the provider already reports an exact running total, and no tokenizer loaded or run while streaming). The legacy `true`, `{refreshMs}` and missing-key shapes all stay `auto` and gain no key. The typed settings schema is a strict enum (an illegal value fails the `statusLine` scope at startup and keeps the previous in-memory settings on reload); the statusline's own raw parser only falls its policy back to `auto` with one diagnostic per unknown value. `/statusline` offers the two-value cycle and saves only the legal enum through the existing A+B lock, fingerprint-conflict and atomic-write path; the policy applies on the next refresh without a restart, and command and items mode share it.
- **Mid-stream policy switch**: switching while a message streams rebuilds the current message's counter once from a shared full-text snapshot (`CountReset`): `auto → estimate` rebuilds only the Han/other buckets (no BPE), `estimate → auto` adopts the provider's streaming exact total directly when there is one and no tier row is selected, otherwise rebuilds the local count. Message generations, timing, provider usage and the `pending_provider_exact` / `settled_local_exact` / `settled_estimated` overlay are kept; the `~` marker follows the new policy, the rate numerator hold of ADR-0047 stays, and `message_end` still runs the official full-tokenizer correction under both policies.
- **Live session total**: items `live-total-tokens` is now `sessionStats.total + pending provider-exact output + settled local exact + settled estimated + the current message's provisional output`. `message_end` settles the current message exactly once: a provider terminal `output > 0` becomes pending with a persistence watermark, otherwise the official full tokenizer result becomes local exact, otherwise a normally completed message keeps its final heuristic as settled estimated (`~`); aborted/errored messages drop their final estimate. Pending entries are cleared by the `assistant_messages` watermark of any applied snapshot (never by trigger category); local settled sums survive snapshots and the next `message_start`; a new session clears every generation. Command mode keeps its complete `rpi.live_output` payload and never creates pending entries.
- **Counts-only watermark probe**: `ctx.sessionStats` gains the optional additive argument `{countsOnly:true}`, answered in O(1) as `{sessionId, sessionFile?, startedAt, entryCount, userMessages, assistantMessages}` by incrementally maintained `SessionManager` counts — no entry clone, iteration or usage aggregation. The statusline reads it once per finished assistant message with provider usage, inside the `message_end` callback and before the host persists that message (the host order is pinned by a regression test), deciding from its reconciled field cache rather than the raw settings file. A failed probe hides the row until a boundary read issued after that message clears it best-effort; entries that survive three applied snapshots are diagnosed; a slow probe (an old host answering the full snapshot) switches to the cached `assistant_messages + pending` lower bound, never to the full stats. `rpiAbi` stays 1; an older host answers the full snapshot to the same call and the SDK reports either shape.
- **Incremental counting**: the items path feeds the bundled tokenizers delta by delta. Each tier keeps the open raw added-token prefix (proper-prefix oracle, match-snapped cut), the open NFC composition sequence (normalization boundaries covering combining marks and Hangul jamo) and the layered split chain with a per-pattern tail guard, so stable pieces are counted exactly once by byte range and only the open tail plus the new bytes are processed per tick; the items live tick no longer deep-copies the message. Open pieces or NFC sequences above 64 KiB fall back to the refresh-cadence full recount (`CountFallback`), and `finalize` equals the official full pass for all six families at every delta boundary (arbitrary chunk sizes, contractions, added tokens, Hangul, NFC and long words).
- **Compact tokenizer tables**: every token byte is stored once — a contiguous byte pool with a rank→range table and an open-addressed index whose lookups compare the full bytes for tiktoken, a sorted merge-pair table for HF BPE, and shared byte-pool indexes for the `ignore_merges` vocabulary and the added-token prefix oracle. A model switch still releases the previous family, and cold load plus first count stays at roughly 10–40 ms per family (the merge table is built by one sort).
- **Display change (not breaking)**: under `auto`, the local exact/estimated contribution of a normally completed message now stays in the live session total across snapshots and the next message instead of being dropped at `message_end`, so the `~` marker can persist until the session ends when no exact source exists. Configuration, the streaming source precedence and `TokenSource` are unchanged; aborted/errored messages still contribute no estimate.

## Breaking changes

### Providers, validation and configuration

- **Rust model representation**: `Model.compat` is now `Option<Box<ModelCompat>>` (64-bit `ModelCompat` remains 592 bytes). Rust callers constructing a `Model` must box the compat value. This is a source-level API break, not a models.json or wire-schema change.
- **Validation semantics**: plain JSON Schema follows the final pi-schema coercion and local-unresolved-`$ref` behavior. `BigInt`/`Undefined` accept and preserve the JSON input; `Void` always rejects. Validation error paths/messages have migrated accordingly. Refine/codec/custom-format execution and fabricated JS BigInt/undefined values are not introduced.
- **Anthropic continuation**: official Anthropic origins use message threads by default. Continue only while the request prefix matches; changed history, compaction, tools or thread failures fall back to a full request. Set `compat.supportsMessageThreads: false` or `StreamOptions.disable_continuation` to disable; proxy defaults remain off and cache-warming replays never read or replace thread state.
- **Cache warming**: the default `cacheWarming` mode is now `idle`, not `streaming`. Explicit `streaming` and `off` are unchanged, and an absent or invalid setting also resolves to `idle`.
- **OpenAI compatibility**: empty `tools` arrays are omitted by default. Legacy proxies can opt back into `compat.requiresToolsWithToolHistory`; new `promptCacheKeyMode` (`auto`/`enabled`/`disabled`) and `requiresNonNullAssistantContent` controls are available. Generated models schemas include all three fields.

### Tools, Markdown and sessions

- **grep context and `GrepOperations::read_file`**: `grep` builds its context lines from ripgrep's own output. The deprecated `GrepOperations::read_file` default stays on the trait for source compatibility but is never called, so a custom grep implementation that influenced remote results through `read_file` must override `AgentTool::execute` instead. Globs are matched relative to the path with symlink awareness, a leading `./` is ignored, lone CR and UTF-16 files are read, and an exact `limit` hit is not reported as truncation; `find`/`ls` normalize `limit < 1` to 1.
- **Markdown surfaces**: `MarkdownTransformContext` now covers `custom`/`summary`/`changelog` with optional message identity/timestamp. Existing user/assistant/thinking defaults are unchanged, but summary/changelog renderers now use the same transformer/Mermaid pipeline and can change their output.
- **Missing-cwd sessions**: interactive startup, `--session`/`--resume`, `/resume`, `/import` and `ctx.switchSession()` now require an explicit Continue/Fork/Cancel decision. Startup Fork changes session ID/cwd; Continue does not persist that decision, and failed/cancelled imports remove their copies.

### Durable Rust API migration (experimental, not source-compatible)

- **Public types**: `Storage::commit` accepts ordered batches and returns `CommitResult { stored, refused }`; `commit_one` preserves the ordinary helper, and hot `conversation`/`task`/`submission` reads return `Arc<T>`. `WatchCall`/`WatchEnd` use the final tagged forms, `DocumentChangeKind::{Change,Retire}` replaces retirement inference, `subscribeCommits` becomes `observeCommits` (advance/end/detach) with `DocumentCommitChange` as the change shape, and old watch getters/events move to `observeDoc`/`observeConversation`/`observeTaskGraph`; `FileChange` uses `Paths`/`Overflow`/`Failed` and watchers stop rather than close. `ConversationView` becomes a bounded window (default min 50 / max 100 entries, independent observers, `before`/`from`/`resume`) and the paginated `ConversationTranscript` is new; `ConversationHandle::submit` takes an `InputSubmissionDraft`, and `WhenIdle::Reject` refuses a submission while the conversation is busy. `SearchDocument`/`ToolSearchDocument` add `namespace_text` for namespace-weighted ranking. `SourceInfo` and `ResourcePathMetadata` add optional `changelog_path`; package resolution fills it from the package changelog and preserves it through `ResolvedPackageResource`/`PackageResource`. `CommitPersistence::Deferred { within_ms }` and `ProgressPolicy.persist_within_ms` are new. `LIVE_DOC` (the `pi.live` record) is v3 with `reason→trigger` and required `run.turns`, `pi.tool` is v3 with optional `unoffered`, and `pi.generation` is v2 with saved thinking levels and sequential pending unoffered calls; older task records are rejected by the new reader and the next write upgrades v1/v2 fixtures (JSONL and SQLite). `HarnessOptions`/`JsonlStorageOptions` add `read_only`, `Report` replaces the string+info callbacks with one channel containing `ReportInfo`, `ReportTask`, `ReportFrom`, `StorageFailed` and `TaskInterrupted`, `TaskInspectionState::Ready` becomes `Pending`, and `retry_task`/`TaskParked` disappear. `SubmissionDraft`/`SubmissionRecord` add `Continue` and `ContinueSubmissionStatus`, drafts add `when_idle`, agent state/change adds `max_turns` and conversation compaction settings, `TaskRuntime` adds `entries` and `commit_with_options`, `HookApi` adds `entry`/`entries`, and generation hooks add `after_run`/`before_provider_request` with `RunSummary`, `RunEndTask(s)` and `ProviderRequest`. `SessionEnd` intentionally remains `Closed`/`Failed` and is not part of this migration.
- **Behavioral migration details**: restart limits now end in terminal outcomes rather than parked retry state, unoffered calls create pending `pi.tool` tasks without resolving/executing, all seven Harness error classes pass through `afterTool` with rebinding and structured-output/control gating, deferred poll recovery retries the same provider response, and handoff orders reset → selected steer/write → final follow-up. `trace_in(start, callback, context)` is context-last; no Chord registry-value adapter, JS runtime, remote stack or default durable CLI endpoint is added.

### Extensions

- **Recovery trust**: background resume/auto-resume now requires the parent-owned `recovery.json`; runs created by older versions without it are refused with a relaunch/`reuseFrom` hint instead of trusting `status.json`.
- **Capability ceiling identity**: rpi has no session-file-path capability registry; the descendant allowlist is carried by the session's inherited environment and resolved per launch, so an old path registration cannot remain active.
- **Structured output**: a child with `outputSchema` must finish through `structured_output`; the raw JSON value is validated before coercion, so `"42"`/`"x"`/null no longer pass for numeric/string-typed schemas.
- **smart-fetch details**: new tool results persist compact `fetchSummary`/`batchSummary` details instead of full `fetchResult`/`batchResult` bodies; old sessions remain readable in memory and are not rewritten.
- **Worktree resume (S01)**: a background child whose recorded cwd is a managed worktree is refused when the handoff records the worktree/branch as removed, when a pending durable handoff capture is still finalizing, or when the root/cwd is missing or outside the root. A preserved (retained) worktree whose cwd still exists is resumable, matching the upstream `resolveRetainedWorktreeCwd` semantics.

## Fixed

- Deferred durable commits fold held operations into the next read/write stored commit while unrelated and read-only commits keep them held; they publish only current internal deltas, flush before unload/version reload and before close ends commit observers, reject invalid `within_ms`, and release every retention pin. Session outcomes are line-fenced and failure-poisoned, document reads and attach operations are fenced behind earlier outcomes, failed Writer parts open gates only after Session failure, repeated close returns the same failure, SQLite group commits accumulate writes per table, and watch pins follow the current incarnation while view observers detach outside mount locks. A maintenance/deadline flush advances the cached stored-delta count, and an overflowed hold stores a base instead of a replace delta (later held operations are covered by it); a watch, document-state or conversation-view attach that races close rejects instead of hanging, close listeners registered during close run once, `unloadDocuments` waits for admitted publications, a view observer's `end` waits for its in-flight `advance`, and scheduler fault reports wait for the terminal publication to become durable. Storage/adoption publication failures reject commits (a component listener throw settles the commit and fails the Session), and Writer panics settle every outcome and gate.
- Nested host dialogs keep deferred inline components unmounted until the final close, and extension terminal titles use the same control-character replacement as direct terminal titles.
- Refreshing catalogs distinguishes configured-only from credential-backed sources: configured sources never refresh OAuth, stale credential failures become provider warnings while other providers continue, and non-auth catalog errors remain fatal. `rpi update --models` therefore succeeds past a stale `invalid_grant` without hiding a network failure.
- Bedrock preferred strict tools retry once non-strict while required tools stay strict, with session memory isolated from Anthropic. Gemini rewrites only schema `const` nodes to single-value enums and preserves literal/default/example/`__proto__` subtrees. Faux cache writes no longer also count as input tokens.
- MCP OAuth sign-in is split into start/complete: refresh never registers a new client or replaces pending PKCE state, lock busy and other failures are distinguished, and callback shutdown aborts idle keep-alive connections. Relative root `$id`, bad percent escapes, missing and cyclic references resolve without unsafe recursion.
- **Long single-word lines wrap in one pass** (`rpi-tui`): `breakLongWord` used to collect one segment per grapheme and both wrap helpers advanced one byte at a time with an ANSI-scanner call per byte, so the collapsed `write` preview of a one-line 25–41 KiB file re-wrapped ~80,000 scanner calls and a 40,000-entry vector on every streaming delta. The wrap now walks the non-ANSI runs once, processes graphemes as they are found and locates the next escape byte with a byte search. Rendered lines are unchanged (a differential test keeps the previous implementation as the reference over random ANSI/CJK/emoji/tab inputs and 20,000-character words). On the release benchmark the `long-arguments-fullscreen` scenario moves from 112% to 101% of the v0.1.8 pure-compute frame p95 (9 repeats) with process CPU at 81% of v0.1.8, byte-identical output.
- `session-id` replaces `session_id` on OpenAI Responses. Zhipu code 1308 and ChatGPT workspace limits are not retried, LiteLLM context overflow is recognized, and dropped provider streams are retryable without matching digits inside request IDs.

## Performance and memory evidence (v0.1.8 → v0.1.9)

- **Method**: same machine (AMD Ryzen 7 8845HS, 16 logical CPUs, Linux 6.12.113, glibc 2.41, rustc 1.98.1), release builds of the v0.1.8 stable source plus the reviewed V19-00 measurement overlay and of this release, the same 17 CPU and 7 memory replay bundles (byte-identical to the V19-00 manifest), fixed cadence with adaptive backpressure disabled, 3 repeats per CPU scenario (9 for the sub-millisecond scenarios and `long-arguments-fullscreen`), 1 repeat per memory scenario (3 or 10 for the empty session). The rebuilt v0.1.8 baseline reproduces the archived V19-00 outputs exactly (17/17 final screens, terminal byte streams and frame sequences) with CPU within 98–105% and pure-compute p95 within 90–108% across the scenarios, so the archived and fresh baselines agree within the run-to-run noise of this harness.

## Known boundaries

- **Not verified with real accounts.** Providers, OAuth, usage quotas and MCP were exercised only with offline fixtures and loopback stubs; a real-subscription smoke remains a manual opt-in outside the gates.
- **Platform coverage.** The arena default, override and invalid-value matrix ran on Linux GNU only; non-GNU/non-Linux targets were compile-probed with rust-std 1.95.0 (musl and FreeBSD) rather than run, and a full musl check still needs a musl C toolchain for `ring`. Windows was not exercised by hand in this window. The PowerShell installer suite ran on a local PowerShell 7.6.9 with invariant globalization; Linux `pwsh` and Windows PowerShell 5.1 run in the manually started release build.
- **Regular mode.** The two 1 MiB-history regular scenarios keep the whole-content render and `previous_lines` diff by design and improve less than fullscreen (CPU 59–75% of v0.1.8).
- **Sub-millisecond frame noise.** The cheap scenarios' pure-compute p95 (0.5–1.6 ms frames) moves within ±8% between runs of the same binary; `mermaid-off-fullscreen` reads 106.7% of v0.1.8 at 9 repeats (three extra 9-repeat rounds: 106.4–110.2%, pooled 108.6%) with 32% less CPU, and `long-arguments-fullscreen` 101.3%. The 50% targets apply to the main scenario only; these readings stay within the 10% line on their central estimates.
- **The 2 MiB code-page budget passes narrowly** (canonical pair 2,020 of 2,048 KiB; mean +1,652 KiB): the jsonschema compile-time meta-validator accounts for most of the growth, and a next version should budget it explicitly.
- **Numbers are not floating-point round-tripped.** The workspace's `serde_json` does not enable `float_roundtrip`; numbers with 17 or more significant digits parse 1 ulp away from the shortest JavaScript round-trip in the streaming preview and the final parse alike, as in v0.1.8.
- **Upstream moved on.** Pi v1.6.0 (2026-11-20) and v1.6.1 (2026-11-25) and pi-subagents v0.89.0–v0.90.0 were released after ADR-0048 adopted the v1.5.2 / v0.88.1 pins. This release stays on those pins (re-confirmed at closeout on 2026-11-26); moving them is a separate ADR for the next version.
- **Known test flakiness, not release behavior.** Two existing tests are sensitive to parallel load in the full workspace suite and pass in isolation: `agent_session_test::in_memory_fork_waits_for_active_tool_turn` occasionally hangs, and `fullscreen_transcript_measures_history_through_the_height_index` can miss its frame-count floor.
- **`rpi-durable` remains experimental** (the API changes without notice between releases) and is not on the default CLI path. Upstream's Fleet inspector, remote/JS stacks and other registered deferrals stay deferred.
