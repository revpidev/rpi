# v0.1.5-rc.4 (2026-09-27)

**Pre-release (pre-release channel)**: candidate for the `0.1.5` stable release. Content = `v0.1.5-rc.3` plus the independent review round-2 batch and the TUI driver-thread abort fix below; at stable-release time this file's entries fold into `v0.1.5.md`. Upgrade: `rpi update --rc` (or `rpi update --all --rc` to also move the six lockstep extensions to `0.1.5-rc.4`).

This RC lands the round-2 outcome of the pre-stable review (per-item detail in `changes/v0.1.5.md` § "Pre-stable review fixes (round 2)") plus one crash fix found in real use after rc.3.

## Fixed in this RC

- **Escape during streaming no longer crashes the TUI driver thread** (rpi-native crash): pressing `Esc` while a response was streaming panicked `rpi-tui-driver` with `there is no reactor running, must be called from the context of a Tokio 1.x runtime` — the escape handler spawned the session abort with a bare `tokio::spawn` on a thread that has no Tokio runtime. The abort (both the empty-queue and the queue-restore branches of `restoreQueuedMessagesToEditor`) now routes through the `spawn_async` fallback used by every other key-dispatch callback (ambient runtime when present, dedicated current-thread runtime otherwise). The same latent panic in the `/llama` Hugging Face search debounce (typing in the search box) is fixed with it. Both are pinned by regression tests that drive the handlers from a runtime-less thread.
- **Overlay composition round** (review round 2, P1): a `models.json` provider entry now composes exactly like upstream `applyModelsJson` — `config.models` upsert into the base catalog with defaults inheritance (previously the list was replaced), `modelOverrides` last, per-call recomposition so dynamic catalogs stay live, and a configured `apiKey` no longer erases the base OAuth method (stored OAuth credentials keep resolving). Streaming follows upstream `streamWith`: the base serves every model whose api it declares; every other model streams through that model's own api provider, and an api rpi does not serve terminates with the upstream `No API provider registered` error.
- **Post-abort compaction gate** (review round 2): an abort that cancels a retry's backoff sleep can no longer fall through into the post-run compaction check and run a billable summarization after the user aborted.
- **MCP OAuth and proxy-call repairs** (review round 2): token exchange and refresh carry the origin-scoped service headers (all five OAuth requests share one header builder; a malformed configured header fails the request with the upstream message instead of being silently dropped); `client_credentials` reads its stored registration URL-scoped, clears a token-less dead one with the failure propagated, and forwards a live registration's DCR-issued `client_secret`; proxy argument validation runs before the approval gate (invalid calls no longer prompt, deny, or cache a session grant).
- **Extension/RPC/TUI repairs** (review round 2): the wasm SDK `toolExecute` route releases the state lock before running a tool handler (`subscribe`/`unsubscribe` from a handler no longer deadlocks); the RPC fail-closed `user_bash` response carries the handler's original message; the interactive `!`/`!!` interception gains its regression harness; `SessionCompactFailedEvent` joins the exported hook types; `complete_summarization` uses the documented `biased` select; the auto-compaction catch classifies cancel races as aborted; cache-warming timers exit on `clear_run`; `sync_compaction_model` no longer silently no-ops under contention; deferred post-login re-selection checks the session identity; the WSL clipboard temp file is created 0600 atomically; the editor CJK separator class is composed from the shared table; assorted tests are hermetic against hostile host environments.
