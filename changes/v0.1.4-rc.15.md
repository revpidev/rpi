# v0.1.4-rc.15 (2026-09-16)

**Pre-release (pre-release channel)**: round fifteen of the `0.1.4` stable candidates. This round = **statusline `live_output` raw-material passthrough** (#45). Install/upgrade: existing rpi users run `rpi update --rc` (or `rpi update --all --rc` to sync extensions to `0.1.4-rc.15`); force-install via the official script with `RPI_GITHUB_API_URL=https://api.github.com/repos/revpidev/rpi/releases/tags/v0.1.4-rc.15`.

## Increments relative to rc.14

- **Raw-material passthrough for script-side language-aware token counting on the statusline** (#45; `rpi-statusline`, PR #49): `rpi.live_output` previously exposed only aggregated character counts, forcing scripts to convert with a single chars/token factor — Chinese (~1.0–1.3 chars/token) and English/code (~3.5–8) bias it in both directions, and the calibration factor drifts with the language of the most recent message. Investigation confirmed the host had long been delivering the raw material into extension events: the `message_update` payload carries the accumulated partial verbatim (full text blocks + `usage`; both OpenAI-compatible stream-chunk usage and Anthropic `message_delta` running totals land at `/message/usage/output`) — the plugin had merely counted characters and dropped it. The fix retains and passes it through: `live_output` gains 6 additive fields: `output_tokens` (provider-accumulated output tokens during the stream, present only once >0, never rewritten on later silence; after `message_end` still closed out by `output_tokens_exact`), `text`/`thinking`/`toolcall` (the current message's **accumulated raw text** per delta class, reset on `message_start`, frozen on `message_end`, with an identity-to-`*_chars` invariant pinned by tests), `decode_started_at_ms` (the wall-clock epoch ms of the message's first delta — the TTFT-exclusion anchor, set once and never re-based per tick), and `message_id` (a plugin-local monotonic id that changes per message, letting stateless scripts detect message switches). Design choice: accumulated raw text rather than per-tick deltas — scripts are stateless processes re-run per invocation (V13-10 §1.2 layering), and delta-only would force them to persist state across calls to reassemble text, while rates are already covered by `delta_chars`/`delta_ms`; the native-measures-but-never-converts red line holds (language-aware estimation lives entirely on the script side — free to do CJK/Latin script splits or swap in a real tokenizer); `peek_fingerprint` now includes streaming usage and the message sequence number (reasoning tokens can advance without characters, and message switches in the frozen state self-heal). Zero changes to the host/ABI/subscription set/JSON-RPC wire protocol; the original 8 fields stay byte-identical; behavior without `liveTokens` configured is exactly as in TE12. Known benign differences (vs. the `message_end` authoritative content): no signature, no block structure (multi-block concatenation), redacted thinking absent — none affect token estimation.
- **Gates**: `cargo test -p rpi-ext-statusline` 52 unit tests + 3 integration binaries all green (new: raw-text retention and per-message `message_id` changes, in-stream usage 0-guard latching, the decode anchor set once at the first delta, the fingerprint moving with streaming usage/message sequence, carrier new-field shape and omission matrices, and cross-carrier-seam assertions for in-stream usage/raw text/anchors/frozen values); clippy/fmt clean.

## Verification requests (rc.15 focus)

- With `statusLine.liveTokens` + a custom token-rate script configured: one Chinese and one English streaming round each — `rpi.live_output`'s `text` raw content and `output_tokens` pass through correctly; on providers with in-stream usage (OpenAI-compatible/Anthropic) the rate should be exact immediately (no estimation needed), others estimate via script splits over the raw text; `output_tokens_exact` closes out consistently after `message_end`; the rate anchored to `decode_started_at_ms` no longer jitters with the 1Hz refresh.
- Users without `liveTokens` configured: statusline behavior exactly as in rc.14 (zero-change regression).
