# v0.1.4-rc.14(2026-09-15)

**预发布(pre-release channel)**:`0.1.4` 正式版候选第十四轮。本轮 = **高亮引擎跨语法 panic 根治**(#47)+ 全仓 mod.rs 清零(规范 §3.1)。安装/升级:已装 rpi 用户 `rpi update --rc`(或 `rpi update --all --rc` 同步扩展到 `0.1.4-rc.14`);官方脚本强装 `RPI_GITHUB_API_URL=https://api.github.com/repos/revpidev/rpi/releases/tags/v0.1.4-rc.14`。

## 相对 rc.13 的增量

- **高亮引擎跨语法 panic 根治**(#47;v0.1.3 T17 起存在,非 rc 回归):syntect(fancy-regex 后端)对语法正则惰性编译,遇 Oniguruma 子程序调用 `\g<-1>` 直接 `expect` panic。旧 build.rs 预检只验证「每个正则可编译」并让 6 个不兼容语法运行时按**名字**排除——但其 context 仍完整留在内嵌 dump 里,而 bat 语法集中 `JavaScript (Babel)` 与 `JavaScript` 同属 `source.js`,syntect 链接器 `.rev().find()`(排后者胜)把所有 `include: scope:source.js` 都链进了 Babel。结果 39 个语法(HTML / Markdown→HTML / PHP / Vue / Svelte / QML / JSP / Elixir→`Regular Expressions (Elixir)` 等)解析到 `<script>`、`~r` 等内容时 push 进被排除语法的 context,首次命中即 panic——`catch_unwind` 兜住了进程,但 panic 消息打到 stderr 污染 TUI,且整块内容退回纯文本。
- **修复(build 期剔除 + 引用改写 + 重链接)**:`crates/rpi/build.rs` 把 21,692 个 `Direct` 引用全量改写回可解析引用(语法内 → `Named` 19,858;跨语法 → `File` 按名 1,799;指向被删语法的 → 按同 scope 重绑 34,`source.js` 回落正常 `JavaScript` main;无同 scope 替代的留未解析 `File` 1 例——Elixir `~r` 行运行时纯文本降级,`parse_line` 返回 `UnresolvedContextReference` 而非 panic),剔除 6 个语法后重链接(`Context.prototype` 由 `build()` 重建),198→192 语法。门禁收紧:剔除后**零**编译失败;`FANCY_INCOMPATIBLE` 名单必须与资产集精确匹配(上游集漂移即 fail);语法名唯一性断言(File 按名改写依赖);dump 回读断言。
- **vendored fork `vendor/syntect`**:改写需上游 crate 私有的两个 API,故引入 vendored fork——crates.io 5.3.0 原版 + 两处加性可见性补丁(`get_context` 转 pub、`ContextReference` 变体去 `#[non_exhaustive]`),裁剪 tests/examples/benches/assets 后约 470KB,经 `[patch.crates-io]` 接入,行为与注册表版一致;来源/补丁 diff/升级流程见 `vendor/syntect/PATCHES.md`。`highlight.rs` 的 `FANCY_INCOMPATIBLE` 保留为运行时防御镜像,并新增 3 个回归测试。
- **用户可观测变化仅两点**:原先 panic 回退整块丢高亮的内容(HTML 内嵌 JS 等)现在正常高亮;Elixir `~r` 行降级纯文本(原先整块 panic 回退)。`cargo tree -i onig` 无匹配——G4 纯 Rust 约束维持。
- **全仓 mod.rs 清零**(规范 §3.1):6 个 `mod.rs` 全部转 Rust 2018 同名文件布局(main 存量 4 处 + vendor 2 处,纯机械移动,`mod` 声明与解析等价),转换后 `git ls-files | grep mod.rs` 为零;dump 重新生成逐字节一致。
- **门禁**:`cargo test -p rpi` **2287/0**(含新回归:跨语法嵌入 html/markdown/jsp/elixir 不 panic 且逐行往返、html `<script>` 恢复 JS 着色——`syntaxType`/`syntaxFunction` 断言、六个不兼容语法不可按名解析);`cargo test -p rpi-tui` 1339/0(markdown 组件消费同一高亮入口);clippy / fmt 干净。

## 验证请求(rc.14 重点)

- 打开含内嵌 `<script>` 的 HTML/Markdown→HTML/PHP/Vue/Svelte/QML/JSP 文件:JS 段应正常着色,stderr 无 panic 消息、内容不整块退回纯文本。
- Elixir 含 `~r/.../ ` 的行:该行纯文本降级,进程不崩、无 panic 输出。
- 代码块高亮常规回归:六目标安装后抽查 markdown 渲染与代码高亮无异常。
