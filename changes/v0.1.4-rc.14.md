# v0.1.4-rc.14 (2026-09-15)

**Pre-release (pre-release channel)**: round fourteen of the `0.1.4` stable candidates. This round = **eradicating the highlight engine's cross-syntax panics** (#47) + eliminating mod.rs files repo-wide (standard §3.1). Install/upgrade: existing rpi users run `rpi update --rc` (or `rpi update --all --rc` to sync extensions to `0.1.4-rc.14`); force-install via the official script with `RPI_GITHUB_API_URL=https://api.github.com/repos/revpidev/rpi/releases/tags/v0.1.4-rc.14`.

## Increments relative to rc.13

- **Cross-syntax panic eradication in the highlight engine** (#47; present since v0.1.3 T17, not an rc regression): syntect (fancy-regex backend) compiles grammar regexes lazily and hits an Oniguruma subroutine call `\g<-1>` with an outright `expect` panic. The old build.rs pre-check only verified "every regex compiles" and excluded six incompatible grammars at runtime **by name** — but their contexts remained fully embedded in the dump, and in the bat grammar set `JavaScript (Babel)` and `JavaScript` both claim `source.js`, so the syntect linker's `.rev().find()` (last match wins) linked every `include: scope:source.js` into Babel. The result: 39 grammars (HTML / Markdown→HTML / PHP / Vue / Svelte / QML / JSP / Elixir→`Regular Expressions (Elixir)`, …) panicked on first hit when parsing `<script>` blocks, `~r` literals, and the like — `catch_unwind` contained the process, but the panic message hit stderr and polluted the TUI, and the whole block fell back to plain text.
- **Fix (build-time excision + reference rewriting + relinking)**: `crates/rpi/build.rs` rewrote all 21,692 `Direct` references back into resolvable ones (within a grammar → `Named`, 19,858; cross-grammar → `File` by name, 1,799; pointing at a deleted grammar → rebound to the same scope, 34, with `source.js` falling back to the normal `JavaScript` main; with no same-scope replacement, left unresolved, 1 case — the Elixir `~r` line degrades to plain text at runtime, `parse_line` returning `UnresolvedContextReference` instead of panicking), then excised the six grammars and relinked (`Context.prototype` rebuilt by `build()`), 198→192 grammars. Gates tightened: **zero** compile failures after excision; the `FANCY_INCOMPATIBLE` list must exactly match the asset set (upstream drift fails the build); a grammar-name uniqueness assertion (the by-name `File` rewrites depend on it); a dump read-back assertion.
- **The vendored fork `vendor/syntect`**: the rewrite needs two upstream-crate-private APIs, hence a vendored fork — the crates.io 5.3.0 original + two additive visibility patches (`get_context` made pub, `ContextReference` variants de-`#[non_exhaustive]`), trimmed of tests/examples/benches/assets to ~470KB, wired in via `[patch.crates-io]`, behaviorally identical to the registry version; provenance/patch diffs/upgrade procedure in `vendor/syntect/PATCHES.md`. `highlight.rs`'s `FANCY_INCOMPATIBLE` remains as a runtime defensive mirror, with 3 new regression tests.
- **Only two user-observable changes**: content that previously lost highlighting to the whole-block panic fallback (HTML-embedded JS, …) now highlights normally; Elixir `~r` lines degrade to plain text (previously the whole block panicked and fell back). `cargo tree -i onig` has no matches — the pure-Rust G4 constraint holds.
- **mod.rs eliminated repo-wide** (standard §3.1): all 6 `mod.rs` files converted to the Rust 2018 same-name file layout (4 pre-existing in main + 2 in vendor, purely mechanical moves, `mod` declarations resolution-equivalent); after the conversion `git ls-files | grep mod.rs` returns nothing; the dump regenerated byte-identically.
- **Gates**: `cargo test -p rpi` **2287/0** (including new regressions: cross-syntax embedding html/markdown/jsp/elixir not panicking with per-line round-trips, html `<script>` regaining JS coloring — `syntaxType`/`syntaxFunction` assertions, and the six incompatible grammars being unresolvable by name); `cargo test -p rpi-tui` 1339/0 (the markdown component consumes the same highlight entry point); clippy / fmt clean.

## Verification requests (rc.14 focus)

- Open HTML/Markdown→HTML/PHP/Vue/Svelte/QML/JSP files containing embedded `<script>`: the JS sections should color normally, with no panic messages on stderr and no whole-block fallbacks to plain text.
- Elixir lines containing `~r/.../`: the line degrades to plain text, the process doesn't crash, no panic output.
- Regular regression of code-block highlighting: spot-check markdown rendering and code highlighting after installing on any of the six targets.
