# v0.1.6-rc.4 (2026-10-07)

**Pre-release (pre-release channel)**: candidate for the `0.1.6` stable
release. Content = `v0.1.6-rc.3` plus the pre-stable fix below. Upgrade:
`rpi update --rc` (or `rpi update --all --rc` to also move the eight lockstep
extensions to `0.1.6-rc.4`); `install.sh` does not serve RCs
(`releases/latest` stays stable). The two new first-party plugins install
from the RC channel with `rpi install rpi-plan-mode --rc` and
`rpi install rpi-usage --rc`.

## Fixed in this RC

- **Codemode rendering (upstream parity)**: the built-in `codemode` extension registers no `renderCall`/`renderResult` hooks and the T17 built-in registry had no `codemode` entry, so the tool resolved no renderer definition at all and fell through to the generic fallback — the call printed the entire script as pretty JSON and the result printed the full output with the `Script completed / Wall time / Output:` header, unfolded. Upstream (`extensions/codemode/renderer.ts` @ a13d35a74) folds the script to 10 visual lines with an expand hint, lists the nested tool calls (last 8 when collapsed; `models.*` costs and their total) and the output (5 visual lines) with the header dropped and the `Full output:` path named. That renderer is now ported as the built-in `codemode` renderer (`tool_renderers/codemode.rs`); the T17-by-name lookup keeps the extension itself hook-free and lets a replacing extension override it with its own hooks. Per-fix detail: `changes/v0.1.6.md` §Review hardening → "Pre-stable fix (v0.1.6-rc.3 verification)".
