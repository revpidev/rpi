为什么是 Rpi

Rpi 是 Pi（earendil-works/pi）coding agent 的 Rust 移植：继承其交互形态与扩展模型，四层 crate 清晰拆分，独立演进。

🧩 四层 crate 架构

rpi-ai provider/适配层 · rpi-agent agent 循环与 harness · rpi-tui 终端渲染 · rpi 组装与 CLI。职责清晰，可独立复用。

🔌 扩展宿主

双通道扩展：L1 Wasm（ABI v1）+ L0 原生动态库（abi_stable），两阶段信任加载、33 事件 / 24 API / 28 UI 方法，支持 /reload 热更。

🖥️ 终端原生体验

完整 TUI：会话树、slash 命令、选择器、语法高亮（syntect）、HTML export 与 gist share。交互模式与 headless / RPC 三模式并存。

☁️ 38 个内置 provider

OpenAI、Anthropic、DeepSeek、MiniMax、Kimi、Moonshot、Google、Bedrock…开箱即用；模型目录由本站点静态下发，支持 ETag 增量更新。

🔒 隐私优先

全部产品端点自托管（本站即部署源）且可逐项关闭：RPI_MODEL_CATALOG_URL、RPI_VERSION_CHECK_URL、RPI_TELEMETRY_URL 设 off 即零请求；telemetry payload 仅版本号。

🌱 项目来源

由 Pi（earendil-works/pi）移植而来，保留 MIT 许可；上游参考实现在 external/pi/，设计决策记录于 docs/ 与 ADR。

快速开始

单二进制、零运行时依赖（musl 静态构建），从源码构建或直接使用发布产物。

1构建

git clone <your-repo-url> rpi && cd rpi
cargo build --release
./target/release/rpi

2配置 provider

# 官方 38 个 provider 已内置，只需写自定义/覆盖：
# ~/.rpi/agent/models.json（可选）
{"providers": {"deepseek": {
  "apiKey": "DEEPSEEK_API_KEY",
  "models": [{"id": "deepseek-v4-flash"}]}}}

3端点自托管（可选）

# 默认已指向本站；自建请见 deploy/resetpi/
export RPI_MODEL_CATALOG_URL=https://resetpi.com
export RPI_VERSION_CHECK_URL=https://resetpi.com/api/latest-version
export RPI_TELEMETRY_URL=https://resetpi.com/api/report-install

4开始使用

rpi                     # 交互模式
rpi --print "重构这个函数"  # headless 一次问答
rpi --rpc               # RPC 服务（32 命令）

产品端点

本站托管 rpi 的全部产品回调；静态托管 + Pages Functions，无后端。每个端点均可在客户端用 RPI_* 环境变量或 settings.json 覆盖或关闭。

端点用途状态
/api/models/providers/{id} 远程模型目录 overlay——38 个内置 provider 的模型清单，ETag/304 增量 revalidate ● 运行中
/api/latest-version 版本检查（{"version","packageName","note"}），交互模式启动时异步探测 ● 运行中
/api/report-install install telemetry 收口（GET ?version=），payload 仅版本号 ● 运行中
/session/#{gistId} 会话分享 viewer（gist id 走 URL fragment，前端渲染） ● 运行中
/changelog 更新横幅里的 changelog 页面 ● 运行中
